# 전체-대시보드 — 개념 페이지 원문 이관

위키 `프로그램/wiki/concepts/` 정리(2026-10-06) 때 개념 페이지에서 빼낸 날짜별 실측·사건·결정 기록 원문. 원칙은 위키 페이지에 남아 있다.

## from [[실제-광고비-계수]]

### 구글 — 부가세 공제 + 부가세 포함액에 캐시백 (전체 대시보드, 대표 2026-09-26)

- 구글 청구엔 부가세가 붙지만 **공제받는다**(대표 확인) → 비용은 공급가. 카드 캐시백 2.8%는 **부가세 포함 결제액**에 붙는다 → 공급가 기준 계수 `k = 1 − 0.028 × 1.1 = 1 − 0.0308 = 0.9692`.
- 처음엔 0.972(공급가에 2.8%)로 넣었다 — 캐시백이 **어느 금액에 붙는지**를 안 물어서. 1~8월 합계 차이 −2,642원. 한 번만 도는 DB 이전 표식(`google_fee_vat_2026_09_26`)으로 옛 값만 고쳤다.

## from [[모름-vs-0-표시-규약]]

### 전체 대시보드에서 새로 잡힌 사례 (2026-09-25~27)

- **「0원인 날」과 「못 받은 날」은 수집 기록으로 가른다.** 광고비 금액만 보면 둘이 같다. 수집이 그날 ok/no_data를 남겼으면 「받았음(0이 맞음)」, 기록이 없으면 「광고비 자료 없음: 메타(9/16~9/25 없음)」처럼 **날짜 구간**으로 알린다.
- **가능성이 높아도 자동으로 정상 처리하지 않는다.** API로 주문을 받는 가게의 빈 날은 「주문 없음」일 가능성이 크지만, 「API로 받음」 배지만 달고 「정상(원래 없음)」은 대표가 누른다. 누른 것은 설정에 남고 확정 판정에 들어간다.
- **비어 있는 입력칸은 0이 아니다.** 지출 탭 부가세 칸 빈칸 = 보류(비용에 안 넣음), `x` = 부가세 없음. 빈칸을 0으로 읽었으면 급여가 부가세 10% 만큼 틀렸다.
