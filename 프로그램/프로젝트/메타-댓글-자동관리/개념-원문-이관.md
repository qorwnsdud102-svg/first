# 메타-댓글-자동관리 — 개념 페이지 원문 이관

## from [[산-댓글-가려내기]]

2026-09-22 실측: 구매 문의 대기 **56건 중 25건(작성자 22명·전부 인스타)**이 부스터가 주문한 글과 글자까지 같았다.
그대로 보냈으면 **우리가 산 댓글에 우리가 판매 메시지**를 보냈다. 손해는 메시지 비용이 아니라,
① 진짜 손님 응대에 섞여 판단이 흐려지고 ② 같은 계정에 업체가 말을 걸어 컨셉이 깨지는 것이다.

한쪽만 만들면 반쪽이다. 2026-09-22 첫 판에는 글자 대조만 있었고, 그래서 **IG 25건은 잡았는데 FB 51개는 못 잡았다**
(형제 세션이 찾아 줬다). 두 갈래를 다 붙이자 FB 구매 문의 13건이 추가로 걸렸다.

검산이 맞아떨어진 예(2026-09-22): 영상 `1064875862991482` 에 21:52 주문 6개 → 그 뒤 첫 6개,
01:52 주문 5개 → 그다음 5개가 **정확히** 떨어졌다.

### 실측 (2026-09-16, [[메타-댓글-자동관리]] 재개 중)

| 광고 종류 | 광고 수 | 메타 인사이트 반응·댓글 | 조회 API로 읽힌 반응·댓글 |
|---|---|---|---|
| 노출 위치별 맞춤 | 297 / 308 | 4,905 · 156 | **0 · 0** |
| 단일 영상 | 11 | 213 · 7 | FB 38 · 4 + IG 일부 |

- 어깨 광고 한 건: 인사이트 반응 479·댓글 11, 대표가 연 FB 게시물은 공감 282·댓글 8. API가 주는 광고 게시물(`creative.effective_object_story_id`)은 **문구부터 달랐다**("끝입니다!" vs 화면 "끝납니다!"), 게시물 통계 클릭 0.
- 대조군 단일 영상 광고: 인사이트 반응 4 = FB 게시물 1 + IG 좋아요 3 일치, 게시물 통계 클릭 83.
- **0이 나온 경로 전부**: `effective_object_story_id` 게시물 · 페이지 `ads_posts`의 같은 시각 형제 게시물 12개 · 소재 영상 객체 `/{video_id}/comments` · `/{post}/dynamic_posts` · 페이지 feed/posts/published_posts · IG `effective_instagram_media_id`.
- 권한·앱 상태는 원인이 아니었다: 필요한 권한 4개 포함 시스템 사용자 토큰, 앱 라이브 게시 **전후 결과 동일**.

### 해결 절 원문 (FB·IG 줄)

- **FB:** 댓글은 페이지 소유 **비공개 릴스 영상**(대표가 복사한 링크 `facebook.com/reel/{영상}/?comment_id=…`)에 달린다. 이 영상 ID는 소재·페이지 목록 어디에도 없고, 광고 `/{ad_id}/previews`(`MOBILE_FEED_STANDARD`, `FACEBOOK_REELS_MOBILE`)가 주는 iframe HTML 안 **`"videoMediaData":{"videoID":1712397450060227`(따옴표 없는 숫자)** 한 자리에 있다. HTML의 15~17자리 숫자 51개 중 나머지 50개는 앱 번호·국가 전화 코드·카테고리 번호. 그 영상은 `from.id=페이지`, `post_id` 있음, `/{영상}/comments`로 댓글·`can_hide`·`permalink_url`이 읽힌다. 켜진 광고 11개 중 10개에서 영상 18개(1개는 미리보기 500 오류로 재시도).
- **IG:** 형태별 미디어는 광고계정 `/adcreatives`의 `effective_instagram_media_id`에 있다. 소재 목록에 **문구**(`body`·`object_story_spec.video_data.message`·`asset_feed_spec.bodies`)가 오고 IG 캡션과 92/92 일치 → 켜진 광고 소재와 **문구가 같고 게시 시각 ±15분**인 미디어가 형태별 게시물(광고 11개 → 28개). 미디어 4,176개 정보를 다 받지 않고 같은 문구 미디어의 시각만 받는다.

### 반응 조회도 막힌다 — 광고 전용 피드 게시물 (2026-09-22 추가)

이 페이지는 **게시물을 못 찾는** 문제를 다루는데, 찾은 뒤에도 한 겹이 더 있다.
**광고 전용(`is_published=false`) FB 피드 게시물은 좋아요·댓글 수를 못 읽는다 — 오류가 아니라 0 이 돌아온다.**

```
GET /{page_id}_{post_id}?fields=likes.summary(true),comments.summary(true)
  → {"likes":{"summary":{"total_count":0}}, "comments":{"summary":{"total_count":0}}}
  실제(브라우저)  좋아요 225 · 댓글 34
```

`reactions`·`comments.filter(stream)`·`shares` 로 바꿔도 전부 0 이다. **릴스(`/reel/`)는 같은 방법으로 제대로 읽힌다**(222·33).
릴스도 `is_published=false` 인데 읽히므로, **비공개라서 못 읽는 것이 아니다.**

원인으로 보이는 것: `/me/accounts` 가 주는 페이지 id 와 그 게시물이 실제로 사는 페이지 id 가 **다르다**
(브라우저 주소는 `facebook.com/61574054860277/posts/…`, 토큰이 주는 페이지는 `586083164589708`).
후자로 만든 합성 id 는 **에러 없이 빈 껍데기**를 돌려준다. `61574054860277` 로는 그 객체를 열 수 없다(권한 없음).

`post_impressions` 계열도 v25 에서 사라졌다(`(#100) The value must be a valid insights metric`).
남아 있는 것은 `post_video_views`·`post_clicks` 인데, **광고 노출을 제대로 안 잡는다** —
릴스 오브젝트 자기 조회가 4,829 인데 그 소재의 `facebook_reels` 노출은 53,639 이었다(10분의 1).

# 메타가 스스로 숨기는 광고 댓글

### 한 줄 정의

메타는 **페이지 설정을 켜지 않아도** 광고 댓글의 상당수를 스스로 숨긴다. API로 읽으면 `is_hidden=true`로 오지만 **작성자 본인과 그 친구에게는 보인다** — 그래서 대표 눈에는 멀쩡히 보이고 프로그램만 "이미 숨겨짐"으로 건너뛴다.

### 실측 (2026-09-20 · 일상곡선 FB 광고 릴스 전수)

- FB 댓글 **43건 중 19건(44%)이 숨김 상태**로 들어왔다.
- 숨겨진 쪽: "효과없음 돈이아까버요", "거짓? 아니요?", "구라치지마세요", "완죤사기꾼천국이내", "병신 일본에 무슨황제야" … **거의 전부 부정 댓글**. 여기에 시험으로 단 짧은 댓글 **"ai", "광고네"**도 포함.
- 보이는 쪽: "얼마이에요?", "How can I buy", "계좌로도.되나요", "진짜인가요", "구입원함" … **거의 전부 문의·중립**.
- **페이지 설정은 둘 다 꺼져 있었다** — 「페이지에서 특정 단어를 포함하는 댓글 숨기기」 해제·목록 비어 있음, 「비속어가 포함된 게시물과 댓글 숨기기」 꺼짐. 대표가 건 필터가 아니다.
- 비즈니스 스위트 → 받은 메시지함 → Facebook 댓글에서 게시물을 열면 **「이 페이지에서 숨김」** 칸에 모여 있고 [숨기기 취소]로 풀 수 있다.

### 프로그램 설계에 주는 함의

1. **부정 댓글 자동 숨김의 추가 가치는 생각보다 작다.** 메타가 남겨 둔 23건을 우리 AI에 돌렸더니 부정은 **1건**뿐이었다 — "바르고~완치되면, 천만원 줄께~ㅎㅎ"(반어적 조롱, 0.85). 메타는 **욕설·명백한 사기 단정은 잡고, 욕 없는 비꼬기는 놓친다.** 우리 몫은 그 틈과 IG, 그리고 정책이 바뀔 때의 보험이다.
2. **진짜 값어치는 구매 문의 쪽에 있다.** 같은 23건 중 **14건이 구매 문의·효과 질문·관심**이었다. 메타는 이걸 대신 해 주지 않는다.
3. **자동 숨김에 걸린 구매 문의는 놓친다.** 짧은 문의("광고 보고 왔는데 얼마에요?")가 걸리면 우리가 건너뛰어 메시지를 못 보낸다. 2026-09-20 표본에서는 숨김 19건에 구매 문의가 없어 **대표 결정: 지금처럼 건너뛴다**(판단·기록·구매 문의 모두 안 함, 숨김이 풀리면 그때).
4. **건너뛴 것도 화면에 보여야 한다.** 숨겨진 댓글은 기록으로 남지 않아 화면이 조용하다 → 댓글이 달렸는데 아무 변화가 없으면 사람은 프로그램이 죽은 줄 안다. 현황에 "지난 확인 … **이미 숨겨져 있어 건너뜀 2건**"처럼 **건너뛴 사유와 건수**를 한 줄로 낸다. ([[모름-vs-0-표시-규약]]과 같은 계열 — 0건과 "안 본 것"을 구분해 보여 준다.)
5. **숨김이 풀려도 댓글 수는 그대로다.** "댓글 수가 바뀐 게시물만 읽기" 최적화를 쓰면 숨김 해제를 못 알아챈다 — 정기 전체 재읽기(1시간)에 의존하게 된다. 즉시 반영이 필요하면 강제 재읽기 수단이 있어야 한다.

### 확인·조작 방법 (사람 손)

- 무엇이 숨겨졌나: 비즈니스 스위트 → 받은 메시지함 → **Facebook 댓글** → 게시물 → 「이 페이지에서 숨김」.
- 페이지 필터 확인: 페이스북에서 **페이지 프로필로 전환** → 설정 → 검색 "단어" → 「페이지에서 특정 단어를 포함하는 댓글 숨기기」·「비속어가 포함된…」. (개인 프로필 설정과 화면이 똑같아 헷갈린다 — 반드시 페이지로 전환한 상태여야 한다.)
- 인스타는 별도다: 인스타 앱 → 설정 → **숨겨진 단어**("공격적일 수 있는 댓글 숨기기"가 기본 켜짐인 경우가 많다).

### 실측 (2026-09-20 · 일상곡선 댓글 43건 표본)

| 재 본 것 | 결과 |
|---|---|
| 빈 요청("1+1?", 답 10토큰) sonnet-5 | **14.0초** |
| 빈 요청 fable-5 / opus-5 | 11.2초 / 12.0초 |
| 실제 판단 호출(판단 기준 3.4KB + 댓글) | 14.4초 — **첫 글자까지 13.1초, 글 쓰는 데 0.7초** |
| 댓글 17건 1건씩 | 482.6초 · 입력 39,310토큰 · **$0.117** |
| 댓글 17건 **한 번에 묶어** | 51.7초 · 입력 2,690토큰 · **$0.015** |

→ **시간의 90%는 줄서기**다. 모델을 바꿔도 11~14초로 같다. 스트리밍으로 쪼개 보면 첫 글자까지가 지연 전부다.

빈 요청인데 **입력 토큰이 1,314개**로 청구된다. 우리가 보낸 건 5토큰이다 — **프록시가 자기 지시문을 매 호출에 얹는다.** 여기에 우리 판단 기준(~950토큰)이 더해져 **댓글 1건에 약 2,300토큰**. 댓글 본문은 10~30토큰이다.

### 모델 단가는 상식과 반대일 수 있다

같은 1.0배 그룹인데 실제 청구는 이렇게 갈렸다(같은 작업 기준).

| 모델 | 1건씩 건당 | 17건 묶음 1회 |
|---|---|---|
| claude-sonnet-5 | **$0.0056 (7.7원)** | $0.0151 |
| claude-fable-5 | $0.0264 (36.5원) | $0.0852 |

**작은 모델이 4.7배 비쌌다.** 토큰 수는 거의 같다(39,310 vs 39,459) — 단가 차이다. 리셀러의 가격표는 모델 크기와 무관할 수 있으니 **대시보드 청구 내역(CSV)으로 확인**하고 고른다.

정확도도 함께 봤다(같은 17건): 숨김/남김 정답은 넷 다 16~17/17로 비슷했지만 **fable은 멀쩡한 댓글("저에게 물어보세요")을 숨김으로** 판정했다. 싸지도 않고 위험만 늘었다.
