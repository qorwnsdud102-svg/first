# 프로젝트/ — 작업장 (도서관 아님)

툴별 **개발·운영 실무 기록**의 자리. 도서관(wiki)과 분리된 작업장이다.
2026-10-06 신설 — 사장님 지시: "LLM WIKI를 정돈된 도서관으로 만들고 싶었는데, 그때 작업에만 필요한 메모까지 들어가 지저분해졌다." 마케팅 `프로젝트/`(2026-08-27)와 같은 규칙을 프로그램에 확대.

## 무엇이 여기 오는가

- 툴 개발 일지 — Plan 1~N, 날짜별 추가·수정, "남은 일", 대표 결정 이력
- 운영 실측 — 특정 날짜의 숫자·계정 ID·실주문 표·커밋 해시
- 특정 툴에만 쓰이는 설계 — 시트 gid·칸 배치, 버튼 이름, 배포 순서
- 일회성 분석 — 특정 기간·특정 상품의 원인 분석
- 운영 일지 — PC 이관 당일 기록, 세션 협업 날짜별 사건

## 무엇이 여기 오면 안 되는가 (→ 각자 제자리로)

| 툴과 무관하게 재사용되는 원칙·함정 | → `wiki/concepts/` |
| 툴·API·업체 카드 (무엇·어디·핵심 결정) | → `wiki/entities/` |
| 여러 페이지를 가로지르는 노하우 | → `wiki/syntheses/` |
| 외부 자료 원문 | → `raw/` |
| 배포되는 최종 산출물 (검수 보고서·템플릿) | → `아웃풋/` |

## 운영 규칙

1. **위키에는 증류물만** — 툴을 만들며 배운 것은 원칙·사례 1~2줄로 증류해 wiki에 올린다. 일지·실측은 여기 남긴다. wiki 페이지는 이 폴더를 경로로 참조 (`→ 상세: 프로그램/프로젝트/<툴>/개발기록.md`).
2. **폴더 = 툴 단위.** 툴 공통 운영(PC 이관·세션 협업)은 `운영-공통/`.
3. **툴 저장소의 docs와 중복 금지** — 코드 저장소(`C:\claude\<툴>\docs\`)에 이미 있는 스펙은 복사하지 말고 경로만 적는다.
4. 종료·폐기 툴은 폴더를 그대로 두고 이름에 `-폐기` 접미.
