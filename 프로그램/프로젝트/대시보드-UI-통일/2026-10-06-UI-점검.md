# 대시보드 3종 UI 점검 — 통일 전 진단

대상
- **A 메타 대시보드** — `C:\claude\메타 관리프로그램` (8006, 6화면: 현황·소재·확인 필요·매출·내역·설정)
- **B 전체 대시보드 대표용** — `C:\claude\전체 대시보드-M` main (8010, 5화면: 대시보드·성과 조회·추천·매출·스토어·설정)
- **C 전체 대시보드 간략용(직원)** — 같은 저장소 `staff_app.py` (8020, 4화면, B와 같은 style.css·app.js)

방법: 코드·DB **복사본**(API 키·토큰 제외, 자동 수집 끔)을 18006·18010·18020에 띄우고 헤드리스 엣지로 15화면 × 데스크톱 1440 / 모바일 375 캡처 + 화면 안 실제 계산값(글자 크기·색·반경·간격·아이콘·버튼 문구) 추출. 클릭은 화면 전환만, 쓰기 요청 0건·외부 요청 0건.

> **데이터 주의**: 복사본이라 A는 마지막 수집이 오래돼 숫자가 대부분 「–」, B의 빨간 「API 키 오류」 배너는 키 파일을 일부러 뺀 탓이다. 아래 판정은 **구조·디자인** 기준이고, 운영 데이터에서만 보이는 문제는 따로 봐야 한다.

## 1. 한 줄 결론

**B와 C는 이미 같은 디자인 시스템(같은 CSS 변수 파일)이고, A만 다른 집이다.** 색(#0064e0)·글꼴·레일 선택 모양·카드 반경 8은 셋이 같아서 "비슷해 보이지만", 글자 크기·버튼 높이·간격 단계·아이콘·레일 폭·상단바 구조·빈 값 기호·날짜 형식이 전부 달라서 **오가며 쓰면 다른 프로그램처럼 느껴진다.** 통일의 핵심은 ① 공통 기준 파일 하나 ② 상단바·레일 뼈대 하나 ③ 숫자·날짜 표기 하나.

## 3. 화면별 점검표 결과 (UI-UX-원칙 §3)

### A 메타 대시보드

**잘 된 것**: 형제 도구 규칙의 원조 — 레일 아이콘·상단바 주 동작 1개(「지금 수집」)·배너 3줄 순서가 규칙대로. KPI 카드가 추세 카드 원칙(큰 숫자 + 어제·최근 7일 + 추세선, 빈 날엔 「추세를 그릴 날이 아직 모자랍니다」). 재고 카드가 사람 단위(「약 53일 · 11월 28일 품절 예상」).

| # | 문제 | 근거 | 고치는 방향 |
|---|---|---|---|
| A1 | **같은 경고가 세 번** — 상단 칩 「멈춤」, 빨간 배너 「마지막 수집이 17131분 전…」, 현황 카드 안 큰 글씨로 같은 문장 | §2-1 강조 하나 · §2-10 | 배너 한 곳만. 카드 자리에는 정상일 때 쓸 정보 |
| A2 | **「17131분 전」** — 사람 단위가 아님 | §2-6 · 재고 원칙(화면 한 줄 = 사람 단위) | 「11일 전 (9/24 14:49)」 |

### B 전체 대시보드 대표용

**잘 된 것**: KPI 4장이 추세 카드 원칙 그대로(큰 숫자 + 「8월 대비 ▲」 + 월별 추세선). 「돈의 흐름」이 문장으로 설명("100원 팔 때마다 15.2원 남은 셈이에요") — UX 라이팅 모범. 「미확정」을 숫자 옆 주황으로 표시 — 모름-vs-0 규약 준수. 추천 배지 색(빨강 OFF 검토 / 주황 소재 점검 / 초록 유지)이 뜻과 맞음. 「API로 받음 — 주문이 없었을 가능성이 큽니다」처럼 이유를 같이 말함.

|---|---|---|---|
| B1 | **첫 화면의 주인공이 경고 목록** — 「확인할 것 17개」 패널이 화면 절반을 차지하고 KPI 4장이 아래로 밀림 | §2-1 주인공 하나 · §2-10 핵심 정보 첫 화면 | KPI를 맨 위로, 확인할 것은 「확인할 것 17개 · 가장 급한 것: …」 한 줄 + 펼치기 (상세는 레일 3번 자리) |

## 4. 통일 순서 제안

1. **공통 기준 파일** — `tokens.css`(색 역할·글자 5단계·간격 7단계·반경 3단계·그림자 2단계·버튼 2크기) + 표기 규칙(빈 값 `–`, 날짜, %, 금액). 정본을 한 곳에 두고 두 저장소에 같은 파일로 둔다. 기준값은 [[디자인-기준-먼저]] 기본값 + A의 색.
2. **뼈대 공통화** — 레일(64px · Phosphor · 자리=뜻) · 상단바(정체성 칩 → 상태 → 시각 / 보조 → 파란 주 동작 1) · 배너 3줄 · 본문 1600px · 기간 막대 컴포넌트.
3. **첫 화면 재배치** — B·C: KPI 먼저, 확인할 것 요약 한 줄. A: 중복 경고 정리.
4. **표기 일괄 교체** — 빈 값·날짜·% (B·C는 app.js 공통 포맷 함수, A는 화면 파일 한 곳).
5. **화면별 잔손질** — A3~A7, B5~B11, C2.
6. 각 단계마다 이 점검을 다시 돌려 전후 비교(같은 캡처 스크립트: scratchpad `uiaudit/capture.py` — 다음 세션에선 다시 만들어야 함).

## 5. 대표가 정할 것

- 기준 겉모양을 **A(메타) 쪽**으로 맞출지, **B(전체) 쪽**으로 맞출지 — 제안: 겉모양·뼈대는 A(형제 도구 규칙의 원조), 기준 파일 구조는 B(CSS 변수)
- 기간 선택 위치 — 제안: 상단바가 아니라 본문 맨 위 필터 줄
- B·C 첫 화면에서 「확인할 것」을 KPI 아래로 내려도 되는지
