# 라이브 검증 일지

[[라이브-검증-프로토콜]] 위키 페이지에서 날짜 박힌 사고 서술을 규칙 + 사례 1줄로 줄이면서, 원래 문단을 원문 그대로 옮겼다(2026-10-06 도서관 정리). 도구 한계 절은 새 개념 페이지 [[브라우저-자동화-도구-한계]]로 분리됐고, 그 원문도 아래에 보존한다.

## 원문 — 검증 행위가 실환경을 오염시킨 사고 (2026-09-15)

- **검증 행위 자체가 실환경을 오염시키지 않는지 먼저 본다** (2026-09-15 실사고, [[네이버-SA-성과측정-툴]]). "읽기 전용 검수"라고 pytest를 돌렸는데, 수집 API 테스트가 `report_dir` 기본값(실제 `data/reports/`)으로 가짜 보고서를 저장해 `2026-09-07_AD.tsv.gz`(118KB)가 4행짜리 가짜(158B)로 바뀌었다. DB는 메모리라 무사했지만 원본 보관본이 오염됐다. → 테스트를 돌리기 전에 픽스처가 실경로를 건드리는지(`conftest`의 경로 기본값·autouse) 확인하고, 픽스처의 모든 경로 기본값은 `tmp_path`로. **pytest도 쓰기다.**

## 원문 — 대표 케이스 1건 통과 ≠ 전 케이스 통과 (2026-09-22)

- **대표 케이스 1건 통과 ≠ 전 케이스 통과 — 같은 코드가 여는 화면을 전수 순회하라.** 한 상품(11번)에서만 확인하고 통과시킨 배포가, 같은 스킨을 쓰는 형제 상품(13~16)에서는 **조건 게이트 때문에 전혀 적용되지 않은 채** 옛 문구를 노출하고 있었다(2026-09-22, [[한시행사-공지-운영]]). 스모크가 그걸 못 잡은 이유는 단 하나 — **한 주소만 봤기 때문**. → 조건부로 켜지는 기능은 **그 조건이 갈리는 모든 케이스**(상품·회원상태·폭·로그인)를 목록으로 만들고 순회한다. 같은 도메인 **375px iframe에 각 케이스를 띄워 한 번에 훑는 프로브 함수**를 만들면 6개 상품이 1~2분이며, 그 프로브를 검증 문서에 **항목으로 박아** 다음 배포부터 자동으로 걸리게 한다.

## 원문 — 분리 전 §claude-in-chrome 라이브 검증 · §대시보드 전체 점검은 헤드리스로

### claude-in-chrome 라이브 검증 (도구 한계와 우회)

- **라이브 확인은 Claude가 직접** navigate → DOM/computed style(조상체인·display·크기) → console/network → 스크린샷. 붙여넣기 전에도 `javascript_tool`로 수정안을 라이브 DOM에 주입해 먼저 실증. **한계**: 공개 페이지만 — 로그인/관리자·실결제·비번 입력은 안 함(그 부분과 붙여넣기는 대표가).
- **짧은 애니(2초 GIF 등)는 스크린샷으로 못 잡는다**(캡처 지연 ~2초). → `getBoundingClientRect` 기하측정·`new Image().onload` natWidth·전역변수 감시(`window.__x`)로 증명. `javascript_tool`의 async 반환은 `{}`로 비어오니 **결과를 전역에 저장하고 다음 호출에서 읽기**. 육안 필요하면 애니 지속시간을 임시로 6초로.
- **`resize_window` ≠ 기기 뷰포트**(창 크기라 세로가 실기기보다 짧음). 정확한 폰뷰(아이폰14ProMax 430×932 dpr3)는 **F12 기기 에뮬레이션**으로 — 대표가 직접 켜줘야 함.
- **CSS 변수는 정의 요소가 아니라 "적용받는 자손"에서 읽어라.** `:root`에 `--x:30`, `body.scrolled`에 `--x:50`이면 `getComputedStyle(html)`은 항상 30 → 실제 값은 자손 요소에서 읽어야 보임.
- **기하 측정 전 트랜지션을 꺼라.** class 토글 직후 `getBoundingClientRect()`는 애니 중간값 → `*{transition:none!important}` 주입 후 reflow(`offsetHeight`) → 측정.
- **클래스/플래그 게이팅은 "켜지는 쪽" 값이 실존하는지부터 실증**(반대쪽만 보고 추정 금지). 예: `ez-view-type-pc`가 스크립트에 아예 없어 PC에서 영원히 미발동한 사고 → [[카페24-스킨구조-함정]].
- **포커스 없는 자동화 창에서는 "브라우저가 일을 멈춘다".** 창이 뒤에 가려지면 **CSS 트랜지션이 진행되지 않아** `getComputedStyle`이 계속 옛 값을 반환하고(=수정이 안 먹은 줄 알고 30분 헛디버깅), **클립보드 API는 pending으로 매달리거나 거부**되며, **스크린샷이 5초 타임아웃**난다. → 기하는 `transition:none` 주입 후 측정, 클립보드·스크린샷은 **내장 브라우저(browser pane) 모바일 에뮬**로 재시도. 실제로 내장 브라우저 375×812에서 복사 버튼 **실클릭이 OS 클립보드에 기록되는 것까지 확인**됐다(앱이 "페이지가 클립보드에 썼다"고 경고 → 역설적으로 그게 성공 증거). 부작용: **대표 클립보드가 덮이니** 배포용 복사본이 물려 있으면 미리 알리고 나중에 재복사.
- **클릭 좌표 프레임은 스크린샷 프레임 기준 — 브라우저 확대가 100%가 아니면 어긋난다.** `devicePixelRatio≠1`이면 스크린샷 배율과 클릭 배율이 달라 엉뚱한 곳이 눌린다(눌렸는데 "아무 일도 안 일어남"으로 보임). → **클릭 좌표 = 요소 CSS 중심 × (스크린샷 프레임 폭 ÷ innerWidth)**, 그리고 `document.addEventListener('click',…,true)` 로거로 **실제 명중 대상**을 확인. 모바일 폭 재현이 필요하면 같은 도메인 **375px iframe에 페이지를 띄우고 그 안에 주입**(transform:scale로 확대해 캡처)해도 된다.
- **시안은 스크린샷이 아니라 "눌러볼 수 있는 파일"로 건네라.** 대표 화면에서 내 스크린샷이 안 보이는 환경이 있었다(3회 왕복 낭비). → 시안은 **자체 완결 HTML 1장**(A안/B안 토글 + 실제 동작·실제 이미지)으로 만들어 파일로 전달하면 대표가 직접 눌러보고 즉답한다. 폰 확인도 그 파일을 카톡으로 보내면 끝.

### 대시보드 전체 점검은 헤드리스로 (전체 대시보드, 2026-09-27)

- **앱 창이 뒤에 있으면 내장 브라우저 캡처는 믿을 수 없다.** 스크롤 뒤 캡처가 5초 타임아웃·빈 회색 화면·잘린 화면(뷰포트 에뮬 시)으로 번갈아 나왔다. 사용자 크롬도 화면 배율(`devicePixelRatio` 1.75) 때문에 캡처가 왼쪽 위만 잘려 왔다.
- **해결: Playwright + 설치된 크롬(`channel="chrome"`, headless)** 로 탭마다 전체 페이지 캡처 → 1,200px씩 잘라 읽기. 창 위치·배율과 무관하게 매번 같은 결과.
- **말풍선은 `hover(force=True)`로 판정하지 말 것.** 마우스가 이미 근처에 있으면 새 이벤트가 안 나서 「안 뜸」 7건이 나왔다 — 모두 거짓. **`mouse.move(x, y, steps=8)`로 실제로 움직여** 다시 보니 전부 떴다. 「안 뜸」이 나오면 `elementFromPoint`로 마우스 밑에 무엇이 있는지까지 적는다.
- **읽기 전용 점검의 경계**: 체크 칸은 눌러 보고 되돌리되, 상태를 바꾸는 버튼(「정상(원래 없음)」)은 누르지 않는다.
- 스크립트에서 쓰는 창 크기·경로는 스크래치 폴더에 두고, 결과는 「문제 칸 사진 + 한 줄 설명」으로 보낸다.
