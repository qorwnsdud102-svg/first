### PG 밖 창구 — 문자주문(계좌이체) (2026-09-20 히토 신설)

전화 응대 부담 때문에 ARS 버튼을 **문자주문**으로 바꾼 사례. 결제창을 쓰지 않는 창구라 **기술보다 제도·운영 리스크가 먼저**다.

- **플랫폼 vs 자사몰**: 네이버·쿠팡이 문자/계좌 유도를 막는 건 수수료 우회(정책) 문제고, **자사몰 계좌이체는 정상 결제수단**. 대표도 이 구분은 정확히 알고 있었다.
- ⚠️ **선불 현금결제 5만원 이상은 에스크로(결제대금예치)/소비자피해보상보험 의무**(전자상거래법). 문자로 계좌를 직접 받으면 **카페24 주문서를 안 거쳐 이 장치가 빠진다** — 세트 구매가 5만원을 훌쩍 넘는 몰(히토 2세트 64,620원)은 정면 해당. **안전한 형태 = 카페24 '무통장입금(가상계좌)' 결제수단으로 받고, 문자는 주문서 작성이 어려운 고객용 보조 창구**.
- **현금영수증**: 전자상거래 소매업은 의무발행 업종 — 10만원 이상 현금거래는 요청 없어도 발급(미발급 가산세). 안내 이미지에 발급 문구가 있어도 **수기라 누락 위험**.
- **카드 거부로 보이면 여신전문금융업법 소지** — 계좌이체는 선택지 중 하나로만(카드·간편결제와 병렬).
- **주문이 카페24 밖에 생긴다** → 대시보드 매출·배송관리·분쟁 증빙에서 빠지고, 고객 주소·연락처가 대표 폰에 쌓인다(개인정보 관리 의무). 통계에 넣으려면 입금 확인 후 관리자에서 수기 주문 등록.

**구현 패턴(히토 A안, 되돌리기 1줄)**

- **설정 하나로 몰별 on/off**: `CONFIG.smsPay = { img, bank, acc, holder, tel, msg }` — `img` 없으면 코드 전체가 `return`(다른 몰은 ARS 그대로). 템플릿을 공유하는 다중몰에서는 값이 아니라 **객체째 몰별 값으로 승격**해야 잔재 게이트(타몰 문자열 유출 검사)를 통과한다.
- **통 이미지 안내는 복사가 안 된다** → 팝업 하단에 스크롤 밖 고정 액션바: `[계좌번호 복사]`(하이픈 제거·숫자만)·`[문자 보내기]`(`sms:번호?&body=<양식>` — `?&`가 iOS·안드로이드 양쪽 호환) + 계좌·번호를 **글자로도** 노출(길게 눌러 복사). 본문 양식은 기기에 따라 무시될 수 있어 "번호는 항상, 본문은 되면 좋고"로 설계.
- **클립보드는 실패를 전제로**: `navigator.clipboard`(보안 컨텍스트+포커스 필요) → 실패 시 `textarea+execCommand` → 그것도 실패면 "길게 눌러 복사" 토스트. 카톡 인앱 브라우저처럼 막히는 환경이 실제로 있다.
- **배치**: 상세 플로팅 버튼은 하단 바 바로 위(`bottom: calc(var(--bar-h) + 33px)`, 구매 말풍선 위 20px)에 두고, 드로어에서는 **즉시구매와 같은 줄**에 58px 버튼으로 — 새 줄을 만들면 드로어가 길어져 대표가 반려(높이 불변이 요구사항이었다).
- **금액·계좌가 이미지와 CONFIG 양쪽에 있는 이중 소스** → 바꿀 때 둘 다. (이미지 안 숫자는 코드 검색에 안 잡히니 체크리스트에 명시)

# 카페24 스마트디자인 자사몰 커스터마이징

### 한 줄 정의

카페24 스마트디자인 스킨(`detail.html` 등)을 직접 수정하고 서드파티 위젯(리뷰앱 ReviewAid)을 얹어 자사몰 상세페이지를 커스터마이징할 때 반복해서 부딪히는 스킨·라우팅·위젯·모바일 제약 모음. (사례: 리페아 자사몰 — 첫화면 도입부 리디자인 + 리뷰영역.)

### 핵심 주장 / 속성

- **"라이브가 안 바뀐다"의 90%는 "내가 보는 게 진짜 라이브가 아니다"** — 의심 순서: ① **대표 디자인 ≠ 편집 중 디자인**(보관함에 디자인 여러 개, 라이브=대표 1개), ② URL의 **`/skin-skinN/` prefix = 특정 스킨 강제**(미리보기용, 캐시·저장과 무관하게 옛 스킨 렌더), ③ **디자인 '미리보기' 클릭 = 브라우저가 그 스킨에 쿠키 핀**(그 세션 내내 그 스킨), ④ 카페24 사이트캐시. → 테스트는 **클린 URL**(skin prefix 없는) + **미리보기 안 누른 새 환경(폰 데이터)**으로. `미리보기` 누르면 주소에 스킨번호 떠서 디자인↔스킨번호 매핑 확인 가능.

- **링크 href에 `/skin-skinN/` prefix 박지 마** — 미리보기 상태 **주소창을 통째 복붙**한 게 원인. 메인 VIEW MORE 한 줄 하드코딩이 전 페이지 클릭을 옛 스킨으로 라우팅시킴(대표 바꿔도·캐시 비워도 안 풀림). 링크는 `/product/...`부터. 이미 새는 건 `소스 찾기/바꾸기`로 `/skin-skinN/` 제거.

- **마케팅 문구·상품 요약은 스킨이 아니라 상품 데이터(인라인 style)** — 스킨 CSS로 이기기 어려움. 카페24 **상품관리 입력칸**(요약/상세설명)에서 수정. 그 HTML은 별도 파일로 자산화(`sources/...요약문구.html`)해 버전관리.

- **모바일 첫화면 세로예산** — 인스타/카톡 **인앱 브라우저 상·하단바가 ~100px** 먹음 → 스크롤 없이 핵심 노출하려면 **worst-case(작은 폰) 기준 고정픽셀**로 설계 + 실측 보정. `svh + 상한캡`은 이미지 비율 깨짐 우려로 회피, **썸네일은 `aspect-ratio`로 비율 고정**(1:1→4:3 등 높이만). 상단 띠·헤더는 압축해 공간 회수.

- **서드파티 위젯은 어드민 설정이 1차, 코드는 보조** — 위젯 root div(`<div id="앱-...-root" class="...">`)는 **위치만** 지정. **어드민에서 ON이면 root 안 박아도 앱이 자동 주입**(브라우저 콘솔 `injector` 로그 `[...-root] complete`로 확인). → **끄려면 어드민에서**(+ 메인/상세 **페이지별 탭** 구분: "상품 상세 페이지 설정"의 위젯 사용 OFF). 코드로 div 지워도 안 사라짐.

- **위젯 색상 = CSS 변수** (`--앱-위젯-...-color`). 어드민 색상설정이 그 변수(요소 인라인)를 세팅 → **색 변경은 어드민에서**가 확실. 코드 `!important` 변수 오버라이드는 보조(인라인이 어느 요소에 붙느냐에 따라 안 먹을 수 있음).

- **위젯 DOM 읽기/동기화** — 클래스가 **CSS-module 해시**(`_8l3hc_40` 등)라 빌드마다 바뀜 → 셀렉터는 `[class*="_이름_"]`로. 위젯은 **비동기 렌더** → `MutationObserver + 폴링`으로 감지. 셀렉터는 **가장 구체적 블록 + 라벨 텍스트까지** 확인(예: "전체 리뷰 수" 블록만) — 안 그러면 다른 카운트(포토 개수 등)를 오독.

- **id 중복 위젯 반복** — 같은 root id 2개는 보통 첫 것만 렌더(`getElementById`). 단 앱에 따라 둘 다 처리하기도 함 → **넣고 검증**(둘 다 뜨면 OK, 아니면 JS 복제/대체). 같은 위젯을 상·하단 반복 노출에 사용.

- **데이터 = 정책 분리** — 가짜/고정 카운터(리뷰수·재고 "남은 N세트")는 **설정블록 상수**로 빼서 수정 쉽게. 실제값 필요하면 위젯 DOM에서 읽어 동기화(0이면 0+장식뱃지 숨김).

- **공개 가이드(Notion 등) 긁기** — 루트만 공개면 **Playwright로 메뉴 링크 추출** 가능, 딥링크 직접열기는 로그인벽 → 루트에서 **클라이언트 네비**(DOM click)로 들어가거나 사용자 캡처 요청. 설치코드가 이미지면 풀페이지 스크린샷으로 읽기.
