# 네이버 급등·신규 브랜드 탐지 노하우

> "요즘 네이버에서 뜨는 브랜드·제품 찾고 싶다" 는 요청 하나로 카테고리 3개(화장품/미용·생활/건강·
> 가구/인테리어)를 전수 훑으며 얻은 교훈. 코드: `competitor-finder/scripts/surge_trend.py`.
> 같은 프로젝트의 키워드 수집편은 [[네이버-키워드-접촉지점-수집-노하우]].

## 한 줄 정의

**"넓게 훑기" 와 "시간축 보기" 를 서로 다른 소스에 맡긴다** — 차단·쿼터가 없는 소스로 후보를 전수
확보하고, 비싼 쿼터 API 는 압축된 후보의 월별 추이에만 쓴다.

## 소스 3종 분업 (핵심 구조)

| 역할 | 소스 | 비용 | 준다 |
|---|---|---|---|
| 후보 전수 + 절대 검색수 | [[ItemScout-API]] | 무료·무제한 | 카테고리 leaf별 키워드 500개, 최근 30일 검색수·상품수·경쟁강도 |
| 시간축(급등 판정) | [[네이버-데이터랩-쇼핑인사이트-API]] | 쿼터 (1콜=키워드 5개) | 키워드별 월별 상대비율 |
| (대체 가능) 절대 검색수 | [[네이버-검색광고-API]] `keywordstool` | 넉넉 | 월간 PC/모바일 검색수 |

- **ItemScout total = keywordstool 검색수와 정확히 일치**한다(독도토너 10,290 = PC 1,500 + 모바일 8,790).
  → 검색광고 API 호출을 통째로 생략할 수 있다. 소스가 겹치면 실측으로 확인하고 하나를 버린다.
- ItemScout 는 **스냅샷만** 준다. `duration` 은 `30d` 외 전부 빈 응답이고 `monthAgoExt`/`yearAgoExt` 는
  값이 아니라 boolean 플래그 → **급등은 ItemScout 만으로 판정 불가**. 시간축은 반드시 데이터랩.
- 기존 `scan_surge.py` 가 쓰던 `datalab.naver.com/shoppingInsight/*`(비공식 웹 엔드포인트)는 IP 차단
  대상. **공식 오픈API 로 갈아타면 차단이 아니라 쿼터 문제로 바뀐다** — 쿼터는 돈·시간으로 풀린다.

## 판정 기준 (임계값은 상수 = 데이터로 분리)

- **신규 브랜드**: N(기본 6)개월 전 추정 검색량 0 & 최근 완전월 300+ → "무에서 유"
- **급등**: 3개월 전 대비 3배+ & 최근 완전월 500+
- **절대 검색수 역산**: `해당월 ratio / 기준월 ratio × ItemScout total`
- **기준월 = 최근 "완전한" 달**. 진행 중인 달은 데이터가 덜 차서 반드시 제외(8/19 실행 → 기준월 7월).
- **정렬은 배수가 아니라 절대 증가량**. 배수로 정렬하면 `1 → 1,410` (배수 1410x) 같은 노이즈가 최상단을
  점령한다. 작은 수 나누기는 신호가 아니라 잡음이다.

## ⚠️ 결측 생략 함정 (하루를 날린 버그)

데이터랩은 **검색이 없던 달을 응답에서 통째로 뺀다**(0으로 안 준다). 이걸 0으로 복원하지 않으면
"N개월 전 0" 조건이 **구조적으로 성립 불가** → 7,889개를 돌리고 신규 브랜드 **0건**이 나온다.
4월에 처음 등장한 명백한 신규(테키라쌍커풀액)가 전부 '급등' 으로 오분류돼 있었다.

→ 조회기간 전체 월 목록을 만들어 `{m: got.get(m, 0.0) for m in months}` 로 채운 뒤 판정.
일반화는 [[측정-지표-함정]] §침묵하는 결측.

## 쿼터를 설계 제약으로 (자세히: [[API-쿼터-경제학]])

- **비싼 응답은 무조건 디스크 캐시.** 첫 실행 때 캐시를 안 만들어 7,889개분 트렌드를 날리고 재조회했다.
  캐시가 있으면 **판정 기준을 바꿔 다시 돌리는 게 공짜**가 된다 — 이게 이 파이프라인의 생명줄.
- **429 는 다음 키로 로테이션**, 전 키 소진이면 캐시 저장 후 중단 → 재실행 시 이어받기.
- 개발자센터 시절엔 "하루 1,000콜/키" 때문에 검색수 하한을 1,000 으로 올려 후보를 압축해야 했다.
  [[NAVER-API-HUB]] 이관 후 **일일 제한이 사라져** 같은 작업을 한 번에 끝냈다. 제약이 바뀌면 설계도 바꾼다.

## 노이즈 분리 — 카테고리마다 정답이 다르다

- **상품수 0 필터**(`--min-products 1`)는 카테고리별로 **효과가 정반대**라 기본 off 옵션으로 뒀다.

  | 카테고리 | 상품수 0 히트 | 정체 |
  |---|---|---|
  | 생활/건강 | 423건 | 김수현복귀광고·남궁민드라마 등 **거의 다 비쇼핑 노이즈** → 필터 유효 |
  | 화장품/미용 | 871건 | **네리티아실크프라이머 같은 진짜 신규**가 섞임(자사몰만 판매/쇼핑 등록 전) → 필터 위험 |
  | 가구/인테리어 | 전체의 28% | 필터 효과 큼 |

  교훈: 필터는 도메인 상수가 아니다. **끄고 켤 수 있게 하고, 근거 수치를 함께 남긴다.**
- **플랫폼 키워드 제외**(쿠팡·지그재그·무신사…)는 전 카테고리 공통으로 유효. 재사용: `filter_keywords.PLATFORMS`.
- **기존 브랜드 목록은 제외가 아니라 "표시"** 로 쓴다 — 부분일치 매칭이라 신생 브랜드를 오탐할 수 있어,
  사람이 눈으로 검증할 수 있게 컬럼으로만 남긴다.
- 쳐낸 것은 **전부 사유와 함께 엑셀에 보존**(no silent drop — [[네이버-키워드-접촉지점-수집-노하우]] 와 같은 규칙).

## 개체 묶음이 낱개 키워드보다 낫다

낱개 키워드 순위표는 `2026여름네일`·`여름패디` 같은 시즌 키워드에 점령된다. **다른 히트 키워드의
접두어인 키워드를 뿌리로 삼아 묶으면**(테키라 ⊂ 테키라마스카라 ⊂ 테키라쌍커풀액) 브랜드 단위 신호가
드러난다. 키워드 2개 이상이 **동시에** 올라오는 것 자체가 신규 브랜드의 실제 지문이다.

- 화장품 실측: 네리티아 16개 키워드 합산 97,280 · 테키라 17개 76,420 · 비렌느 7개 63,320.
- 낱개로 보면 흩어져 보이던 것이 묶으면 1~3위로 올라온다.

## 카테고리마다 "뜨는 것" 의 성격이 다르다

| 카테고리 | 상위 신호의 정체 |
|---|---|
| 화장품/미용 | **브랜드 밀집**. 신생 브랜드(네리티아·테키라·비렌느·블랑로더·아타가) + **연예인/전문가 이름 키워드**(함익병 기미크림·김고은선크림·이시언샴푸·김신영땀템) |
| 생활/건강 | **문제·증상 밀집**. 초파리·진드기·모락셀라·비립종 등 시즌성 문제 검색이 지배. 브랜드는 그 아래 묻힘(테릭스실드·카프슬리머) |
| 가구/인테리어 | **테마 밀집**. 냉감 계열 17개 키워드가 최대 축. 브랜드는 소수(닥터그래핀베개·씨에스리빙) |

→ "신규 브랜드 발굴" 목적이면 **화장품형 카테고리가 수확률이 높다**. 생활/건강형은 같은 기준으로
돌리면 노이즈 비중이 커서 상품수 필터·수동 검증이 더 필요하다.

## 모르는 키워드는 반드시 검색해서 실체 확인

`테키라`·`네리티아`·`비렌느`·`테릭스실드` 처럼 처음 보는 이름은 기억으로 판단하지 말고 WebSearch 로
정체를 확인한다. 오늘 확인한 것 전부 실재 브랜드였다(테키라=쌍꺼풀액/마스카라, 네리티아=세럼 파데
열풍, 테릭스실드=콘센트 자동소화 캡슐 KFI 형식승인). 이 습관은 접촉지점 편의 `올투게더나우` 사례와 동일.

## 잔가시 (실제로 파이프라인을 멈춘 것들)

- **엑셀 제어문자**: 네이버 키워드에 `\x10` 이 섞여 오면(`닭가슴살100\x100개입추천` 1건) openpyxl 이
  `IllegalCharacterError` 로 **통째로** 실패. 저장 직전 `ILLEGAL_CHARACTERS_RE.sub("", v)`.
- **파일 잠김**: 사람이 결과 엑셀을 열어둔 채 재실행하면 `PermissionError` 로 판정 결과가 통째로 증발.
  → 잠기면 다른 이름으로 저장(우아한 실패).
- 둘 다 "마지막 저장 단계" 에서 터진다. **비싼 계산 뒤의 출력 단계일수록 방어적으로** 쓸 것.

- **메타 광고 크롤링(STEP 2~4)과 아직 안 붙었다.** 발굴된 신규 브랜드가 실제로 광고를 돌리는지
