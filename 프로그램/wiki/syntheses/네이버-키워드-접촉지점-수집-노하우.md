# 네이버 키워드 접촉지점 수집 노하우

> 제품/욕구를 설명하면 네이버 키워드를 검색량과 함께 모아 비타겟을 쳐내고 접촉지점 1~5차로
> 분류해 엑셀로 뽑는 도구를 만들며 얻은 교훈. 표본 = 허리디스크 환자용 허리보호대 (2026-06-22).
> 코드: `competitor-finder` 프로젝트(`scripts/harvest_keywords.py` · `write_touchpoint_excel.py`).

## 한 줄 정의

키워드 수집은 **기계(스크립트)**, 노이즈 판단·접촉지점 분류는 **Claude**가 한다. 노이즈 거름의 기준은
"허리와 **관련** 있나"가 아니라 "허리보호대 **살 사람**이 검색하나"(구매의도)다.

## 데이터 소스 노하우

- **검색광고 `keywordstool` API가 핵심 엔진** — 연관검색어 + 월간 검색량(PC/모바일)을 한 번에 준다.
  시드 1개("허리보호대")로 연관검색어 787개, 검색량 1000↑ 137개. 시드 5개씩 묶어 호출.
- **자동완성**(`ac.search.naver.com/nx/ac`)은 무인증 — 보조 수집. 검색량은 keywordstool로 보완.
- 검색량 `"< 10"`(10 미만) 값은 0 처리. 검색량 = PC+모바일 합.
- 데이터랩(쇼핑인사이트)은 별개 — 카테고리 TOP500용. 키워드 확장엔 keywordstool이 맞다.

## 노이즈는 시드에서 터진다

- **넓은 시드가 의료검색 전체를 끌어온다.** `물리치료·도수치료·정형외과` 같은 시드 → 피부과(518k)·
  공단기·일본어사전·비아그라까지 딸려옴. 시드 44개 1회전 = 5,622 키워드, 1000↑만 1,449개.
- 대응: ① 시드를 **제품 직결로 좁히거나** ② 도메인 스템(허리|척추|디스크|좌골|협착…)으로 프리필터.
  단, 프리필터로 **조용히 버리면 안 됨** (아래).

## 분류 기준 = 구매의도 (topical 아님)

- **장요근 사례**: 해부학적으로 허리통증 원인 맞음(단축→골반전방경사→요통, 검색으로 확인). 그러나
  `장요근스트레칭` 검색자는 셀프케어 하는 사람 → 허리보호대 안 산다 → **5차(먼 연관)**.
- 같은 논리로 **골반·코어·저림류** = 관련은 있으나 구매의도 멀어 5차.
- 접촉지점 차수 정의는 마케팅 위키 `마케팅/wiki/concepts/접촉지점.md`(허리견인기 1~5.5차)를 표준으로.
  1차 제품직결 · 2차 치료/병원/시술 · 3차 증상/질환+약 · 4차 세부질환/치료법 · 5차 먼 연관.

## 쳐낸 건 전부 보여준다 (no silent drop)

- 프리필터로 자동 제외한 키워드도 **검색량 임계값 이상이면 전부 "쳐낸 시트"에 사유와 함께** 남긴다.
  안 그러면 사람이 오판(=숨은 키워드 누락)을 검수할 수 없다.
- **숨은 브랜드 = 가장 위험한 false negative.** `올투게더나우`(허리·손목 보호대 경쟁사)는 스템에 안
  걸려 자동 제외될 뻔 → WebSearch로 정체 확인 후 1차로 복구. 모르는 브랜드는 기억 말고 검색.
- 임계값 미만 제외 개수는 숫자로 명시(예: 1000 미만 4,173개 제외), 필요시 덤프.

## 엑셀 산출

- 2시트: **타겟_접촉지점**(1→5차 색상·검색량순) + **쳐낸_키워드**(검색량순, 제거사유).
- 검색량은 셀 값=정수 + `number_format="#,##0"`(쉼표). 텍스트로 쉼표 박으면 정렬 깨짐.
- **비고칸 필수** — 애매한 것(브랜드/헬스용/구매의도 먼 것)을 표시해 사람이 검수.

## 내 생각 / 미해결 질문

- 규칙(정규식) 분류는 조잡 — `뇌MRI`를 MRI로 잘못 담는 식. 정밀히 하려면 Claude 직접 의미분류 또는
  `classify_product.py`식 LLM-API. 다만 대화 안에서는 Claude가 곧 LLM이라 API 없이도 더 정확.
- 2회전(발견 키워드 재투입)은 노이즈 증폭 위험 — 좁은 시드일 때만 가치.
