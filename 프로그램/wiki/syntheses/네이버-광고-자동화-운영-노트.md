# 네이버 광고 자동화 운영 노트

## 한 줄 정의

운영 PC 에서 사람 손 안 거치고 네이버 광고 자동화 도구를 돌리기 위한 엔지니어링 노하우 — 화면 가시화(§2)·서버 안(§4~§5)·PC 밖(§6).

## naver-biding 전용 정책 (이관)

사용자 액션 `force=True` cool-off 우회 정책(옛 §1)과 운영 PC ↔ 개발 PC 분리 + `git_pull_watcher`(옛 §3)는 naver-biding 한 도구의 설정이라 작업장으로 옮겼다. 일반화되는 한 줄만 남긴다 — **개발 PC DB 는 stale 이다.** 같은 코드여도 데이터가 다르니, 운영 PC 출력을 공유받거나 stale 임을 명시한 뒤 코드 동작 기준으로만 분석한다. DB 가 PC 마다 따로면 **마이그레이션은 멱등 스크립트**로(운영 PC 에서 1회 수동 실행, 재실행해도 안전). → 상세 기록: 프로그램/프로젝트/naver-biding/운영노트-이관.md

## §2 사이클 동작 가시화 UX 원칙

- 락인 6h fetch (bid 동결) 도 History 1줄 ("🎯 안착가 확인 N회차") — "이 키워드에서 일어난 모든 일" 타임라인.
- 일반 (락인 아닌) 변경 없음은 그대로 스킵 (스팸 방지).
- skip 사유 4분기 (`cooloff_search_crawl` / `stuck_max` / `paused_kw` / `cooloff_lock`) 진입 시 1줄 + 같은 사유 반복 dedupe.
- 헤더 배지 cutoff 와 시스템 페이지 cutoff 통일 (다른 cutoff 두 곳 비교 시 사용자 멘탈 모델 깨짐).
- 시:분 포맷 backend 가 미리 (`H시간 M분`) — "7.4시간" 같은 소수 금지.
- 회차 타임라인 표시 ("안착가 확인 1회차 ✓ 완료 / 2회차 ← 다음 / ... / 안착가 재탐색").
- min_bid 같은 변하지 않는 값은 UI 숨김 (DB/알고리즘 그대로).

## §4 subprocess.Popen + CREATE_NEW_CONSOLE — uvicorn → GUI 띄우기

- 대시보드 버튼 → FastAPI 가 `subprocess.Popen([sys.executable, "-m", "..."], creationflags=CREATE_NEW_CONSOLE)`.
- uvicorn 이 사용자 session 으로 떴으면 Chrome 창 같은 display 에 뜸. service / system account 면 display 없어 실패 가능.
- 사용 사례: 네이버 nid bvsd 봇감지 회피용 1-click capture (사용자가 직접 ID/PW + 캡차/2FA).

## §5 FastAPI BackgroundTasks 한계 → ThreadPool

- BackgroundTasks 는 단일 worker 순차. 광고그룹 N × 15~25초 사이클 → 4~5분 분산. 사용자 변화 안 보여 "ON" 재클릭 → 중복 큐잉.
- → `ThreadPoolExecutor(max_workers=4)` + `trigger_now_async` 광고그룹 단위 병렬. 광고그룹 내부 키워드는 2~5초 간격 순차 유지.
- 진행바 모달 + `/cycle-status` polling 으로 중복 클릭 방지.

## §6 Windows 예약작업·배포·공유 함정 ([[네이버-SA-성과측정-툴]]에서 실측)

두 번째 자동화 도구에서 같은 계열의 함정이 다시 나왔다. naver-biding(§4~§5)이 "서버 안"이라면 이건 "PC 밖".

- **schtasks가 bat을 직접 실행하면 콘솔 창이 뜬다** → 사용자가 수집 중인 줄 모르고 닫으면 `STATUS_CONTROL_C_EXIT`로 죽고 잠금 파일만 남는다. `wscript.exe`로 vbs를 거쳐 숨김(0) 실행. 단 vbs가 대기하지 않으면(`Run …, 0, False`) 스케줄러는 항상 성공(0x0)만 보고 `RestartCount`는 죽은 설정이 된다.
- **schtasks 기본값은 노트북에 불리** — `AllowStartIfOnBatteries`·`DontStopIfGoingOnBatteries`·`StartWhenAvailable`을 PowerShell `Set-ScheduledTask`로 따로 켠다. `/RU` 없이 만들면 **로그온 상태에서만** 돈다 → 07:30로 등록했지만 실제 실행은 매일 08:44~08:56(PC 켠 뒤), 주말 0회. `WakeToRun` 또는 `/RU <user> /NP`(S4U) 검토.
- schtasks 출력은 cp949 → `encoding="cp949", errors="replace"`. 한글 작업명은 피한다. PowerShell 5.1 한글 스크립트는 **UTF-8 BOM** 필수. 콘솔은 `PYTHONIOENCODING=utf-8` + `chcp 65001`.
- **방화벽 `-Profile Private`는 공용 Wi-Fi에서 무효** → `-Profile Any -RemoteAddress LocalSubnet`으로 주소 범위로 제한. 그래도 로그인 없는 0.0.0.0 공유는 같은 서브넷 누구나 설정 변경·수집 실행이 가능하다 — 쓰기 라우트는 127.0.0.1만 허용하거나 토큰을 둔다.
- **이동용 zip에 키 파일·DB·`.git`이 통째로** 들어가고 바탕화면에 생긴다(클라우드 동기화 시 유출 경로). 키는 빼고 새 PC에서 손으로 넣는다. WAL 모드 DB는 서버·수집 중 복사하면 `-wal` 미반영 사본이 된다 — `VACUUM INTO`로 백업.
- **requirements.txt는 `pip freeze` 기준으로 전부 고정** — import는 하는데 목록에 없는 패키지(bcrypt·openpyxl)가 새 PC에서 즉사를 부른다.
- uvicorn **단일 워커** 고정(전역 JOB 상태) · 정적 파일 `Cache-Control: no-cache`(수정한 JS가 안 보이는 사고 방지) · 스케줄러·bat·웹 버튼이 **같은 파일 잠금**을 공유.
- **pytest 출력 캡처가 하위 프로세스를 깨뜨린다(대표 PC, 2026-09-15).** 테스트 안에서 `subprocess.run(["node", "--check", …])`을 부르면 캡처가 켜진 상태에서 `WinError 6 핸들이 잘못되었습니다`로 실패한다. 코드 문제가 아니다 — `python -m pytest -q -s`(캡처 끔)로 돌리면 통과. 새 PC에서 테스트가 이유 없이 무더기로 실패하면 이것부터 의심.
