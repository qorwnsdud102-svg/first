# 네이버 광고 자동화 운영 노트

## 한 줄 정의

운영 PC 에서 사람 손 안 거치고 네이버 광고 자동화 도구를 돌리기 위한 엔지니어링 노하우 5종.

## §1 사용자 액션 force=True 모든 cool-off 우회 정책

- 사용자 명시 액션 ("지금 실행" / "자동입찰 ON" / "Stuck 리셋", 단일·bulk 모두) 은 `force=True` 로 trigger.
- 우회 대상: stuck 6h / search_crawl cap / 락인 6h cool-off.
- 정기 cycle (스케줄러) 만 cool-off 적용.
- force 도 cap 카운트 누적 — 보호 유지 (의도적 폭주 방지).
- 의도: 사용자 명시 액션은 시스템 보호보다 응답성 우선.

## §2 사이클 동작 가시화 UX 원칙

- 락인 6h fetch (bid 동결) 도 History 1줄 ("🎯 안착가 확인 N회차") — "이 키워드에서 일어난 모든 일" 타임라인.
- 일반 (락인 아닌) 변경 없음은 그대로 스킵 (스팸 방지).
- skip 사유 4분기 (`cooloff_search_crawl` / `stuck_max` / `paused_kw` / `cooloff_lock`) 진입 시 1줄 + 같은 사유 반복 dedupe.
- 헤더 배지 cutoff 와 시스템 페이지 cutoff 통일 (다른 cutoff 두 곳 비교 시 사용자 멘탈 모델 깨짐).
- 시:분 포맷 backend 가 미리 (`H시간 M분`) — "7.4시간" 같은 소수 금지.
- 회차 타임라인 표시 ("안착가 확인 1회차 ✓ 완료 / 2회차 ← 다음 / ... / 안착가 재탐색").
- min_bid 같은 변하지 않는 값은 UI 숨김 (DB/알고리즘 그대로).

## §3 운영 PC ↔ 개발 PC 분리 + git_pull_watcher

- 개발 PC ≠ 운영 PC. `git_pull_watcher` 가 push 2분 내 운영 PC pull + uvicorn 재시작 + health 확인. 사용자 개입 0.
- DB 분리 (sqlite). 마이그레이션은 `scripts/migrate_*.py` 멱등 스크립트, 운영 PC 에서 사용자가 1회 수동 실행.
- **개발 PC DB 는 stale** — 디버깅 시 같은 코드여도 데이터는 다름. 운영 PC 출력 공유받거나 stale 임을 명시한 후 코드 동작 기준으로만 분석.
- 멱등성 필수 — 재실행 안전.

## §4 subprocess.Popen + CREATE_NEW_CONSOLE — uvicorn → GUI 띄우기

- 대시보드 버튼 → FastAPI 가 `subprocess.Popen([sys.executable, "-m", "..."], creationflags=CREATE_NEW_CONSOLE)`.
- uvicorn 이 사용자 session 으로 떴으면 Chrome 창 같은 display 에 뜸. service / system account 면 display 없어 실패 가능.
- 사용 사례: 네이버 nid bvsd 봇감지 회피용 1-click capture (사용자가 직접 ID/PW + 캡차/2FA).

## §5 FastAPI BackgroundTasks 한계 → ThreadPool

- BackgroundTasks 는 단일 worker 순차. 광고그룹 N × 15~25초 사이클 → 4~5분 분산. 사용자 변화 안 보여 "ON" 재클릭 → 중복 큐잉.
- → `ThreadPoolExecutor(max_workers=4)` + `trigger_now_async` 광고그룹 단위 병렬. 광고그룹 내부 키워드는 2~5초 간격 순차 유지.
- 진행바 모달 + `/cycle-status` polling 으로 중복 클릭 방지.
