# snskit-booster (광고 반응 부스터)

## 한 줄 정의

메타 광고 소재마다 FB·IG 게시물 링크를 API로 뽑아, 프리셋(1차·2차·3차 회차)대로 [[snskit-API]]에 좋아요·댓글을 자동/수동 주문하는 포탈 웹앱. 브라우저 자동화 없이 **API 두 개**(메타 Marketing API 조회 + snskit api/v2)로만 돈다.

## 왜 만들었나

대표가 광고관리자에서 소재 수정 화면을 열어 링크 두 개를 복사하고, snskit 주문 화면에서 게시물마다 좋아요·커스텀 댓글을 넣어 접수하고, 같은 게시물에 D0→D+1→D+4로 세 번 반복하던 수작업. 주문내역을 뜯어보니 IG 좋아요 20~57 + 커스텀 댓글 3~23, FB 커스텀 댓글 4~5가 패턴이었다. [[마케팅/DA 광고]]의 "광고 댓글 작업"(3등급 수강생 노하우) 실행 도구.

## 구조 (2026-09-16 Plan 1)

- 포탈 `bid.100storeee.kr/boost/` → `127.0.0.1:8004`, FastAPI + SQLite + 순수 HTML/JS 단일 페이지. 격벽 원칙대로 독립 리포·독립 키·독립 DB.
- 링크는 크리에이티브 필드로 조립한다: FB `https://www.facebook.com/{page_id}/posts/{post_id}/` (`effective_object_story_id`), IG는 `instagram_permalink_url`의 숏코드로 `/p/{code}/` 재조립. 게시물 `permalink_url` 조회는 페이지 권한 오류(#10)라 쓰지 않는다.
- 판단 단위는 게시물(FB post id). 소재가 여럿이 한 게시물을 써도 1번.
- 회차는 프리셋 JSON(시점 offset·몇 시 이후·항목·댓글 출처 풀/AI/직접·승인 필요). 댓글 풀은 소재 이름 토큰(`Y26_W38_온천크림_SB_손가락_…`)의 제품·부위로 매칭, 같은 게시물엔 같은 문구 재사용 없음(FB·IG 통틀어).
- 안전장치 8종(자동모드·송출중 소재·전송 시간대·미완료 주문·min/max·일일 상한·잔액 하한·시뮬레이션) + 돈 안전 패턴은 [[유료-주문-이중결제-방지-패턴]].

## 실측 (2026-09-16)

- 계정 소재 **312개**(송출중 11, 나머지 중지). 메타 `limit=500` + 중첩 필드(campaign{}·adset{}·creative{})는 **500/code 1 "reduce the amount of data"** → 페이지 100, code 1이면 반으로 줄여 같은 페이지 재요청.
- 시뮬레이션 사이클: 9게시물 27건 29,340원, 10번째부터 일일 상한(30,000원) 보류. 22시 이후 스캔은 전송 시간대 보류. 옛 중지 게시물까지 회차를 계획하면 로그가 넘쳐 **송출중 게시물만 계획**으로 바꿈.
- 서버 PC 배포·실주문 전환은 대표 결정 대기 (`docs/내일-할-일.md`).

## 안정성 보강 (2026-09-17)

- 대표가 실사용 테스트를 시작하기 전, 별도 worktree 에서 감사 4갈래(백엔드 장애·동시성/배포·데이터/돈 경로·운영자 UX)를 동시에 돌려 **재현 프로브로 확인된** 결함만 명세(H1~H43)로 묶고 3갈래(엔진·API/프로세스·화면) 동시 구현 → 통합 리뷰 2갈래 → 장애 주입 장기 소크(가상 7,800일) → 최종 리뷰 → `main` 머지·재기동. 테스트 223 → 410.
- 돈 쪽 교훈은 [[유료-주문-이중결제-방지-패턴]] §2026-09-17 보강. 운영 쪽: 사이클 스레드는 죽지 않게 + 생존 상태를 화면 배너로, API 는 사이클이 락을 쥐면 3초 뒤 409(요청이 줄서다 나중에 몰래 실행되지 않게), 변경 요청엔 커스텀 헤더(`X-Booster`) 필수, 설정은 **바뀐 칸만** 저장(열어 둔 옛 화면이 비상정지를 되돌리지 않게).
- 운영자 관점 기능 제안(확인 필요 센터·주문 예보·새 소재 규칙·댓글 로테이션·회차 직접 조작·작업자 기록 등, 명세 §6) → 2026-09-19 전부 반영(아래 Plan 3).

## 화면 (2026-09-17)

- **메타 광고관리자 스타일** — 대표 요청 "광고관리자가 익숙하니 비슷하게". 좌측 레일(대시보드·소재·승인·설정·로그) · 상단바(계정·잔액·지출/상한·자동모드·시뮬레이션/실주문 배지) · 소재는 캠페인/광고 세트/광고 3탭 평면 표 + 우측 상세 패널 + 체크박스 일괄 작업. 대표 승인, 이후는 실사용 피드백으로 보완.
- 만드는 법: 대표가 광고관리자 스크린샷 3장 + 영문 프롬프트로 **Variant**(variant.com)에서 HTML 시안을 뽑고, 그 마크업을 템플릿으로 삼아 데이터 바인딩만 붙였다(Tailwind CDN·Phosphor 아이콘 그대로). 시안 한 장이 설계 논의를 대부분 대신했다.
- 리뷰가 잡은 화면 쪽 함정: 캠페인 **이름**으로 드릴다운하면 `- 사본` 캠페인이 섞인다(→ id로) · 게시물을 공유하는 소재의 지출을 합치면 중복(→ 게시물 dedupe) · 비동기로 여는 모달은 늦게 끝난 요청이 다른 소재 창을 덮는다(→ 토큰 가드) · 트리+단일 편집기 배치는 저장 안 한 입력을 조용히 버린다(→ dirty 확인).

F1~F17: 확인 필요 센터(13가지)·24시간 주문 예보·스캔 미리보기·잔액 n일분 · 새 소재 규칙 · 댓글 로테이션·풀 편집기 · 회차 직접 조작(지금 실행·건너뛰기·다시 시도·일정 변경) · 회차 기준 '시작 후/직전 회차 후' · 작업자 이름+활동 기록 · 주문 조회·CSV · 프리셋 이력·영향 미리보기·적용 범위 · 딥링크·정렬·되돌리기 · 실주문 전환 마법사 · 텔레그램 · AI 댓글(키 잔액 0이라 꺼 둠) · 포탈 게이트 보안(포탈 리포 별도 브랜치).

## 실사용 피드백 묶음 (2026-09-20 Plan 4)

첫 실주문을 하며 대표가 말한 것을 **고치지 않고 `docs/실사용-피드백.md` 에 모았다가 한 번에** 반영(대표 방침). 17건 → 토대(스키마 v5·진행 싱크) → 6갈래 동시 → 통합 리뷰 2갈래 → 소크 → 머지. 테스트 838 → 926.

- **말**: 풀 → **저장된 댓글**(출처는 `저장됨`), 로그 → **주문이력** + **기록** 분리, 레일은 댓글관리와 통일(현황 · 소재 · 확인 필요 · 내역 · 기록 · 설정), 주 동작은 파란 **[지금 확인]**. 한 프로그램 안에서 같은 이름이 두 곳을 가리키지 않게 대시보드 점검 센터는 **지금 볼 것**.
- **동작**: 중복 댓글을 막지 말고 **경고만**(아래 참조), 부위 **별칭·포함 매칭**(엘보→팔꿈치), 주문 **2클릭**(확인창이 미리보기를 겸하고 금액·빠진 항목·댓글 줄 번호를 보여 준다).
- **보이기**: 상단 진행 줄(`메타에서 소재 받는 중 (100개) · 7초`, 자동 사이클도), 주문이력 `7 / 10 완료`·[상태 새로고침], 현황의 최근 주문 10건, 수량 칸의 서비스 최소·최대.

## 변형 게시물 (2026-09-20 Plan 5)

**소재 1개 = 게시물 1개가 아니다.** 메타가 노출 위치·비율마다 게시물을 쪼갠다 — 실측 켜진 광고 11개 → FB 20 · IG 28. 부스터는 대표 1개씩만 들고 있어서, 첫 실주문이 IG 게시물 3개 중 1개만 태웠다(나머지 0).

- 목록은 **[[메타-댓글-자동관리]] 창구에 묻는다**(`GET /api/targets` · `POST /api/targets/refresh`, 127.0.0.1:8005). 직접 찾지 않는다 — 같은 광고를 두 프로그램이 따로 찾을 이유가 없고 메타 호출도 두 배가 된다. 받은 목록은 저장해 두므로 창구가 꺼져 있어도 주문은 나간다.
- 주문 단위는 그대로 '게시물' — 켠 변형마다 `posts` 행(`var:{platform}:{object_id}`)과 거울 `ads` 행을 만들면 회차·안전장치·H3·저장된 댓글 매칭이 한 줄도 안 바뀌고 돈다.
- **사람이 고른다.** 기본은 전부 꺼짐(지금 동작 유지), 켤 때 확인창에 '회차마다 이 게시물에도 같은 주문이 나갑니다 — 게시물당 약 ₩x'.
- 돈이 갈라지는 길 두 개를 막았다: 창구가 켜진 행의 링크를 바꾸면 **옮기지 말고 그 변형을 끈다**, 두 소재가 같은 단위를 공유하는데 링크가 다르면 **켜기를 거절한다**. 승인한 게시물이 아닌 곳으로 돈이 가느니 회차 하나를 놓치는 게 낫다.

## 두 프로그램 공존 감사 (2026-09-20, 운영 PC 이관 전)

[[메타-댓글-자동관리]]와 **같은 PC·같은 메타 앱·같은 페이지**를 쓰게 되어 충돌 감사·안정성 감사·소크 확장을 돌렸다. 테스트 926 → 1,039.

- **메타 한도를 나눠 쓴다**([[메타-API-호출-한도-주머니]]): 부스터는 사용량 머리글을 아예 안 읽고 한도 코드에도 재시도해 회복을 늦췄다. 이제 머리글을 읽어 80%에서 쉬고, 한도 코드엔 재시도 대신 `estimated_time_to_regain_access` 만큼 쉰다. 송출중만 받아 **하루 96→27 요청, 행 7,488→565**(−92%). 부분 목록으로 바꿀 때 `NOT_RETURNED` 쓸이가 멀쩡한 광고를 '사라짐' 으로 만들 뻔한 함정을 테스트로 막았다.
- **조용한 정지**: 변형 새로고침이 실패하면 사이클 스레드가 쓰기 트랜잭션을 붙든 채 남아 이후 모든 쓰기가 `database is locked` 가 됐다(자동 주문 전면 정지, 화면엔 '사이클 실패' 한 줄). `finally` 롤백으로 닫았다.
- **남의 게시물 주문**: 창구가 주는 대상의 `ad_id`·페이지를 우리 DB 기준으로 확인하고, 빈 목록 하나로 저장된 변형을 전부 쓸지 않는다.
- **소크가 새 기능을 몰랐다**: 변형·진행 표시·상태 새로고침이 하네스에 없어 "40시드 무결" 이 그 셋을 검증하지 않았다. 추가한 뒤 **실제 결함**(공유 단위 링크 어긋남)을 잡았다. 더 나아가 하네스의 가짜 응답에 `iter_content` 가 없어 창구 호출이 매번 죽고 **위반 0 으로 거짓 통과**하던 것도 드러났다 — [[소크-하네스-거짓통과]].

## 실가동·운영 PC 이관 (2026-09-21~22)

밤샘 드립 한 벌을 실제로 돌리고, 그 결과로 프리셋 구조를 정한 뒤 운영 PC 로 옮겼다. 테스트 1,039 → **1,060**.

### 회차 구조 — 자잘하게, 오래

한 게시물에 **5회차**(즉시 → +1h → +2h → +3h → +4h)로 나눠 넣는다. 회차 기한은 **직전 회차가 실제로 주문된 시각** 기준이라
앞이 늦어지면 뒤가 통째로 밀리고 간격은 유지된다. 같은 서비스가 연이은 회차에 겹치지 않게 배치해야
"앞 주문 미완료" 보류가 드립을 잡아먹지 않는다(FB 댓글은 1차 여성·3차 남성으로 갈랐다 — 2~3시간 걸려도 2차를 막지 않는다).

구좌별 배분은 [[광고-구좌별-노출-쏠림]]:

| 대상 | 프리셋 | 게시물당 |
|---|---|---|
| 대표(FB 피드 + IG) | 대표용 — IG 기본·**FB 경량** | 4,670원 |
| FB 릴스 변형 | 기본 5회차 | 6,240원 |
| IG 변형 | 기본 5회차 | 3,350원 |

### 저장된 댓글은 **진짜 댓글 말투**여야 한다

내가 쓴 문구는 전부 광고 대행사 톤이었다 — 띄어쓰기 정확, 문장 완결, 자연스러운 존댓말.
대표가 실제 광고에 달린 댓글 24줄을 주며 "내가 보내준 댓글이 너가 쓴 댓글보다 더 진짜같아" 라고 했고, 맞았다.

실제 말투의 특징: **띄어쓰기 붙임**(`관절쑤실때`) · **마침표를 쉼표처럼**(`계좌구매.되나요`) ·
**오타 그대로**(`주문히기`·`시퍼요`·`어떠케`) · **짧게 끊음**(`사볼까`·`굿굿`) · 이모지·`ㅠㅠ`·말줄임 · 존댓말/반말 혼용.

내가 쓴 81줄을 끄고 그 24줄을 부위별로 **아주 조금씩만 변형**해 채웠다(부위 34줄 × 4 + 공통 25줄).
금지어 필터(완치·치료·나았·100%·특효 등)는 따로 걸린다 — `물리치료` 가 무심코 걸렸다.

### 이관 (2026-09-22)

개발 PC → 운영 PC(`C:\Users\pc\Desktop\클로드\메타댓글 부스터`). 절차 노하우는 [[프로그램-운영PC-이관]],
되돌리기의 함정은 [[중복방지의-DB-경계]]. 부스터에만 해당하는 것:

- **원격 저장소가 없어 폴더 복사가 유일한 길**이다(형제는 `git pull`). "둘 다 pull 하면 된다" 로 잡으면 부스터만 빠진다.
- 꾸러미의 DB 는 **자동모드 꺼짐·시뮬레이션 켜짐**으로 넣었다. 키를 넣자마자 주문이 나가면 안 된다.
- **옛 PC 가 그날 쓴 돈이 일일 상한을 먹는다.** DB 를 가져가면 `오늘 지출` 도 따라온다(14,010원이 그대로 넘어가 첫날 여유가 그만큼 줄었다).
- 도구 하나에 개발 PC 경로가 박혀 있어 운영 PC 에서 죽었다. **폴더 이름이 달라진 덕에 드러났다 — 같았으면 조용히 개발 PC 의 DB 를 읽고 "정상" 이라고 찍었을 것이다.**
- 첫 자동 사이클이 **주문 0건**으로 끝나는 것을 확인했다. 켜진 게시물이 전부 회차를 마친 상태라 0건이 정답이었고,
  **돈 한 푼 안 쓰고 사이클 전 구간**(동기화→판정→상태조회→창구호출)을 검증했다. 이관 검증에 쓸 만한 수법이다.

### 실가동에서 나온 것

- **기존 소재의 새 게시물이 자동으로 켜져 13,860원이 나갔다.** 동기화는 `new_ads 0 / new_posts 3` 이었는데도
  '새 게시물' 로 보고 켰다. 그 소재들은 이미 회차를 다 돌았는데 처음부터 한 벌이 더 나갔다.
  → 소재가 이미 있으면 설정이 '자동 켜기' 여도 **검토 대기**로 둔다. 새 칸·새 판정의 기본값은 **사람이 켜기 전 상태**여야 한다.
- **앞 주문이 안 끝나면 뒤 회차가 통째로 보류**된다(항목 하나만 걸려도). 대표 요구로 **앞 주문 대기 한도**(기본 120분)를 뒀다 —
  접수가 확인된 주문만 유예하고, 돈이 나갔는지 모르는 `Placing`·`Unknown` 은 사람이 정리할 때까지 계속 막는다.
- **한 링크에 주문 단위가 둘**이면(대표 + 변형 거울) 같은 게시물에 돈이 두 번 나간다. 소크 스트레스가 실제로 잡았다.
  거울 쪽이 양보한다(`대표 게시물이 같은 링크를 주문 중` 보류).
- **소재 표의 지출이 대표 게시물만 세고 있었다** — 변형을 켜면 화면이 실제의 1/3 을 보여 줬다(4,620 표시 / 실제 13,860).
- 우리가 산 댓글이 형제 프로그램의 **구매 문의로 잡혀 판매 메시지가 나갈 뻔했다** — [[산-댓글-가려내기]].
  FB 랜덤 댓글은 문구를 우리가 주지 않아 `comment_uses` 에 한 줄도 없다. 글자 대조로는 영영 안 걸린다.

## 만들며 배운 것 (전이 가능)

- 계획 코드를 서브에이전트가 그대로 옮겨도 **리뷰가 매 Task마다 실제 돈 새는 경로를 잡았다** — 타임아웃 뒤 재주문, 공유 커넥션의 트랜잭션 오염, 클라이언트 댓글 줄 수로 상한 우회. 2단계 리뷰(스펙→품질) 비용은 컸지만 첫 실주문 전에 알았다는 게 값이다.
- Windows 함정 셋: `.bat`는 CRLF여야 다중행 `if (...)`가 파싱됨 / 새 venv엔 `tzdata`가 없어 `ZoneInfo("Asia/Seoul")`가 죽음(개발 PC 전역 파이썬이 가리고 있었다) / 확장자 숨김 때문에 키 파일이 `snskit_key.txt.txt`.
- Claude Code 자동 모드 분류기는 **키 파일 쓰기와 로컬 API의 설정 PUT**을 막는다(자격증명·실거래 오탐). 키는 사람이 넣고, 화면 조작은 브라우저로.
- **병렬 갈래는 각자 테스트 통과해도 이음매에서 깨진다** — 7갈래가 전부 초록이었는데 통합 리뷰가 갈래 사이 계약(예보↔엔진 필터, 승인 대기열↔실주문 전환, 적용 범위↔승인 요구) 결함 30여 건을 찾았다. 갈래 수만큼 통합 리뷰를 따로 잡아야 한다.
- **소크 하네스도 새 상태를 배워야 한다** — 새 헤더(`X-Operator`)를 안 보낸 하네스는 400만 받으며 "위반 0"을 냈고(주문 0건 — 지표로 알아챔), 새 상태(`queued`)를 모르는 불변식은 정상 대기를 "영구 정지"로 불렀다. 결과가 너무 깨끗하면 주문 건수부터 본다.
- **UTF-8 배치의 `'xist' is not recognized`** — `chcp 65001` 뒤 한글 줄이 섞인 .bat 는 cmd 가 줄 경계를 잘못 읽어 `if not exist` 조각을 명령으로 실행하는 잡음이 난다(기동은 정상). 무해하지만 보이면 놀라니 알아 둘 것.
