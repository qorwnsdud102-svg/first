# 네이버 검색결과 크롤링

## 한 줄 정의

Playwright 로 `m.search.naver.com` / `search.naver.com` 검색결과 직접 파싱. preview 거짓 정원·미노출 검증용 ground truth.

## 핵심 주장 / 속성

- **적용 범위** — 거짓 미노출 의심 키워드 (preview 미노출 + stats imp>0) 만. 정상 잡히면 preview 신뢰. 광고그룹 전체 매 사이클 크롤링 X.
- **호출량** — 키워드당 시간당 20회 sliding window (in-memory deque, `CRAWL_CAP_WINDOW_SEC=3600` / `CRAWL_CAP_LIMIT=20`). 광고주 전체 시간당 1,000회 이하. 호출 사이 2~5초 랜덤.
- **stuck 6h 자동 재점검** (2026-05-22) — `max_stuck_streak≥3` 영구 폐기 X. cool-off 안 cycle skip, 6h 경과 후 자동 fetch. "모든 키워드 stuck → 광고그룹 OFF" 자동 트리거도 폐기 (INFO 로그만).
- **force=True 우회** — 사용자 액션 (지금 실행 / 자동입찰 ON / Stuck 리셋, bulk 포함) 은 모든 cool-off 우회. force 도 카운트 누적 (cap 보호). 정책 상세: [[네이버-광고-자동화-운영-노트]] §1.
- **비로그인 타게팅 → 일반 로그인 쿠키 필요** — 광고그룹 "비로그인 사용자 노출 X" 설정 시 fresh browser 자동 제외 (자동화 감지 아님). `naver_login_state.json` (광고주센터 쿠키 `searchad_state.json` 과 **별도 파일**, 보안). `scripts/capture_naver_login.py` 1회 capture, 이후 `_resolve_storage_state` 자동 재사용.
- **nid bvsd 봇감지** — JS evaluate 로 ID/PW set+submit 자동화 실패. nid 페이지가 keystroke 단위 RSA encrypt + bvsd (browser-side virtual signature data) mouse/keyboard fingerprint 검증 → 빈 값이면 차단. 자동 로그인 포기, 1-click GUI capture 만 운영 ([[네이버-광고-자동화-운영-노트]] §4).
- **DOM querySelector, 정규식 X** — `<ul id=power_link_body>(.+?)</ul>` non-greedy 가 nested `</ul>` 끊김 → 광고 일부 누락. `page.evaluate(querySelectorAll(':scope > li.bx'))` 메인 광고 카드 (sublink_item 제외) + 각 li onclick `encodeURIComponent(...)` URL 추출.
- silent fallback — 크롤 실패 시 cycle 막지 않음, preview 결과로 회귀.
