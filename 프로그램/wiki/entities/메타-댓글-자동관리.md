# 메타 댓글 자동관리

## 한 줄 정의

메타 광고(FB·IG) 소재에 달린 댓글 중 **문의와 일반 반응은 남기고 부정 댓글만 자동 처리**하는 윈도우 상시 프로그램. 댓글 수 자체가 소재를 인기 있어 보이게 하므로 **남길 댓글을 지우는 실수가 가장 비싸다.**

## 대표 운영 규칙 (1등급 — 대표 결정 2026-09-16)

| 경우 | FB | IG |
|---|---|---|
| 확실한 부정 | 숨김 | 숨김, 안 되면 삭제 |
| 애매한 부정 | **숨김**(알림에 애매 표시) | 숨김, 안 되면 알림만 |
| 숨김 실패 | 알림만 — **FB 삭제는 어떤 경로로도 안 함** | 위 규칙 |

- FB는 숨김만: 삭제하면 작성자가 "내 댓글 지웠다"고 항의한다.
- IG는 비즈니스 스위트에 숨김 메뉴가 없어 삭제해 왔지만 **API로는 숨김이 된다**(`POST /{ig-comment-id}?hide=true`). 숨긴 댓글이 누구에게 보이는지는 문서에 없어 실측 후 IG 처리 방식을 정한다.
- **2026-09-17 대표 결정(실데이터 감사 뒤):** ① 인스타도 **무조건 숨김 먼저** — 숨김과 삭제 효과가 같으면 되돌릴 수 있는 숨김(설정의 "삭제 모드" 제거, 숨김이 일시 오류가 아닌 이유로 불가능할 때만 확실한 부정 삭제) ② **단어가 AI보다 먼저 판단하는 방식은 유지하되 단어를 좁힘**("사기꾼" 제외, 문의 단어는 "얼마에요"처럼 물음형 — 부분 일치라 "얼마나 사람을 속여야"도 문의로 남던 문제) ③ **이미 숨겨진 댓글은 건너뜀**(숨김이 풀리면 그때 판단).
- 판단 경계(대표 스크린샷 표본): "진짜인가요"·"구입원함"·"얼마에요 사고싶다"·"알려주세요" = 유지 / "거짓? 아니요?"·"말도 안되는 말"·욕설 = 부정. **궁금해서 묻는 질문은 유지, 단정·비난은 부정.**

## 무엇이 주력인가 (2026-09-20 실측 뒤 다시 정함)

처음엔 **부정 댓글 숨김**이 목적이었는데, 실데이터가 순서를 바꿨다.

- 메타가 이미 FB 댓글의 **44%를 스스로 숨긴다**([[메타-광고-댓글-자동숨김]]). 메타가 남겨 둔 23건에 우리 AI를 돌리니 추가로 잡은 부정은 **1건**(욕 없는 비꼬기).
- 같은 23건 중 **14건이 구매 문의·효과 질문·관심**이었다 — 메타는 이걸 대신 해 주지 않는다.
- → **부정 댓글 관리 = 안전망**(메타가 놓치는 비꼬기·IG·정책 변화 대비), **구매 문의 회수 = 주력**(사고 싶은데 주문을 어려워하는 분들을 매출로). 대표 정리, 2026-09-20.

## 구성 (재개판)

- 리포 `C:\claude\메타 댓글 자동삭제`(GitHub 비공개 `qorwnsdud102-svg/meta-comment-guard`), 브랜치 `resume-2026-09`.
- Python `.venv` · FastAPI 웹앱(운영 PC 포탈 `/comment/` → 8005, 광고 반응 부스터와 같은 레이아웃·[[형제-도구-화면-공통규칙]], **텔레그램 대신 화면**) · requests · anthropic SDK(AI Prime Tech 재판매 프록시, **claude-sonnet-5** — 2026-09-20 실측에서 같은 1.0배 그룹의 fable-5보다 4.7배 싸고 오판도 적었다) · SQLite(WAL·스키마 자동 갱신·단일 실행 잠금).
- **회차(2026-09-17 방식 · 주기는 2026-09-20부터 60분):** 켜진 광고 1건 → 저장된 게시물 댓글 수를 배치 2건으로 → 수가 바뀐 게시물만 읽기(FB 최신순, 1시간마다 댓글 있는 게시물 전체 확인) → 소재가 바뀐 광고만 찾기(FB 미리보기 `videoID`, IG 소재 문구+±15분) → **회차의 댓글을 모아 AI에 한 번에**(묶음 판단) → 구매 문의 자동 보내기(켰을 때만). 호출 한도는 주머니별로 쉼([[메타-API-호출-한도-주머니]]). 실측 평소 회차 **HTTP 3건·2초**, 첫 가동 124건·229초, 7일 치 46건 판단 114초.
- **회차가 지금 무슨 단계인지**를 서버가 알려 화면 진행 줄에 띄운다(`페이스북 게시물 찾는 중 — 광고 3/11`). 처리하지 않고 건너뛴 것도 회차마다 한 줄로 보인다(이미 숨겨짐·시작 시각 이전·우리 댓글).
- **다른 프로그램용 읽기 창구(2026-09-20):** `GET /api/targets`(소재의 형태별 게시물 전부 — 부스터가 대표 1개만 알고 있어 변형에 주문이 안 들어가던 문제), `POST /api/targets/refresh`(그 광고만 지금 찾기). 같은 PC의 127.0.0.1:8005로만 부른다.
- 모듈: 설정(시스템 사용자 토큰 키 파일) · 처리 기록(판단 실패 3회·오류 알림 1시간 1회) · AI 판단(실패는 조용히 "유지"가 아니라 예외) · 처리 규칙표(순수 함수, FB에 DELETE가 나오는 조합 0) · 메타 연결(페이지 토큰 자동 발급·IG 전용 삭제·토큰 마스킹).

## 셋업 교훈 (재발 방지)

1. **토큰 권한은 "앱 이용 사례"에 있어야 고를 수 있다.** 광고용 이용 사례만 있는 앱에는 댓글 권한이 목록에 없다 → "페이지의 모든 부분 관리" + "Instagram에서 메시지 및 콘텐츠 관리"(**Facebook 로그인 방식**) 이용 사례를 추가한 뒤 권한을 넣는다. 새 앱은 필요 없었다.
2. **권한 추가 = 새 토큰 발급.** 기존 토큰에 권한이 붙지 않는다. 기존 토큰은 계속 유효하므로 같은 토큰을 쓰는 다른 프로그램은 영향 없음. 그래프 API 탐색기 토큰은 몇 시간짜리라 쓰지 않는다.
3. **시스템 사용자 토큰은 생성 창에서 한 번만 보인다.** 창을 닫았으면 다시 생성. "토큰 취소"는 같은 앱 토큰을 한꺼번에 끊을 수 있어 누르지 않는다.
4. **앱 게시(라이브)는 개인정보처리방침 URL만 있으면 됐다** — 자사몰 카페24 기본 페이지 `https://hito.kr/member/privacy.html` 사용.
5. 키 파일은 대표가 메모장으로 직접 저장(자동 모드가 Claude의 자격증명 파일 쓰기를 막는다). 토큰을 채팅에 붙여넣으면 대화 기록에 남는다 — 가동 확인 후 재발급 권장.
6. **가짜 AI만 쓰는 테스트는 SDK 설치 문제를 못 잡는다.** 공용 파이썬의 anthropic 0.39.0은 httpx 0.28.1과 맞지 않아 클라이언트 생성이 `proxies` 오류로 실패했는데, 테스트 129개가 전부 통과했다(모두 가짜 클라이언트 주입). 브랜치 전체 최종 검토에서 발견. 공용 파이썬은 포탈과 공유하므로 건드리지 않고 프로그램 폴더 전용 가상환경 `.venv`에 0.125.0 설치 + "실제 클라이언트를 네트워크 없이 생성만 하는" 테스트 추가. [[라이브-검증-프로토콜]]의 "조건 충족된 샌드박스는 통과할 수밖에 없는 테스트"와 같은 계열 — 가짜 객체만 주입하는 테스트는 설치 환경이라는 실제 조건을 건너뛴다.

## 만들며 배운 것 (2026-09-17 실데이터 감사)

7. **가짜 자료 테스트는 실제 응답 형식을 옮겨 적어야 한다.** 미리보기의 `"videoID":"숫자"`를 가정한 정규식이 테스트는 통과하고 실제 HTML(`"videoID":1712…` 따옴표 없음)에서 0개 — 저장한 실제 HTML에 한 번 돌려 보고서야 발견. 실제 응답은 **파일로 저장해 두고 그걸 테스트 자료로** 쓴다.
8. **실데이터 첫 회차가 설계서의 "되겠지"를 가장 싸게 깬다.** 테스트 266개 통과 상태에서 첫 실회차 225초 만에 FB 찾기 전부 실패·호출 한도 초과가 드러났다. 가동 전 "시험 DB·자동 처리 끔"으로 실회차를 먼저 돌리는 단계를 계획에 넣는다.
9. **조용한 멈춤이 가장 비싸다.** 감사가 찾은 높음 등급 대부분이 "화면은 초록인데 실제로는 안 돎"(FB 대상 0·AI 장애로 확인 필요 폭증·DB 잠김으로 기록 0·처리 시작 시각 이동으로 댓글 누락) — 하루 한 번 보는 사람용 도구는 **상태 판정(health)을 서버가 계산**해 문제와 할 일을 사람 말로 보인다.
10. **메타가 작성자(`from`)를 안 줄 수 있다.** 작성자를 모르면 자동 처리를 막는 규칙은 기능 전체를 멈춘다 → 되돌릴 수 있는 숨김은 하고 되돌릴 수 없는 삭제만 막는다.

## 만들며 배운 것 (2026-09-20 실가동)

11. **느린 원인을 모델에서 찾지 말고 한 번 재 보라.** "AI가 25초나 걸린다"의 90%는 재판매 프록시 줄서기였다(빈 요청도 14초). 모델을 바꿔도 같고, 고칠 것은 **호출 횟수**였다 → [[AI-리셀러-프록시-비용과-지연]].
12. **화면이 조용한 것과 프로그램이 노는 것을 사람은 구분 못 한다.** 댓글 2건이 달렸는데 화면에 아무 변화가 없었다 — 메타가 이미 숨긴 댓글이라 설계대로 건너뛴 것이었지만, 건너뜀은 기록으로 남지 않아 보이지 않았다. **건너뛴 사유와 건수를 회차마다 한 줄로** 내보낸다.
13. **오래 걸리는 버튼은 진행을 보여야 한다.** [보내기] 한 번에 메타 응답이 몇 초씩 걸려 30초간 화면이 멈춘 것처럼 보였다 → 누른 즉시 "보내는 중 … n초", 여러 건이면 "n건 중 k건 끝남".
14. **주석 한 줄이 옆 프로그램의 진단을 틀리게 만든다.** discovery.py에 적어 둔 "페이지 소유 **비공개** 릴스"를 부스터 세션이 읽고 "작업자가 못 들어가서 주문이 대기 중"이라고 의심했다. 실제로는 타임라인 미게시일 뿐 **전체 공개**였다(로그인 없이 열어 확인). 남이 읽을 주석은 **관찰한 사실 그대로** 적는다.
15. **테스트가 문구를 붙잡고 있으면 문구를 못 고친다.** 기본 문구를 글자 그대로 비교하던 테스트가 문구 수정마다 깨졌다 → **규칙으로 시험한다**(번호 자리가 있는가 · 공개 답글에 계좌가 없는가 · 업체 이름이 없는가).
16. **대표의 한 줄이 판단 기준의 빈칸을 드러낸다.** "구매좀쉽게 하게해야죠"를 AI는 '불만'으로 보고 종류를 없음으로 뒀는데, 대표는 "사려다 막힌 사람"이라고 했다. 판단 기준에 **"구매 절차가 어렵다는 불평도 구매 의향"**을 넣자 0.90으로 잡혔다.
17. **메시지가 "나갔다"와 "읽힌다"는 다르다.** 인스타 DM은 **글 속 주소가 눌리지 않는다** — 안내 사진 주소를 글에 적어 보냈는데
    대표가 받아 보니 탭이 안 됐다. 비공개 답장은 댓글당 1통이고 한 통에 글이나 첨부 하나만 담기므로 "글 + 사진"은 불가능하다
    → **카드 한 통**(사진 + 80자 글 + 버튼)으로 묶으니 사진이 바로 보이고 버튼이 눌린다(2026-09-21 실측, 메타가 거절하지 않음).
    페이스북 메신저는 링크가 잘 눌려 글을 유지한다. **보낸 뒤 받는 쪽 화면을 실제로 보기 전까지는 끝난 게 아니다.**

18. **우리가 산 댓글에 우리가 판매 메시지를 보낼 뻔했다.** 형제 도구([[snskit-booster]])가 주문한 IG 댓글은
    "얼마에요"·"주문 어떠케해요" 같은 **구매 문의 말투**라, 우리 판단기에는 진짜 손님과 구별이 안 된다.
    2026-09-22 대기 56건을 부스터 저장소의 *실제로 주문에 쓰인 댓글 글*(sha1)과 맞춰 보니 **25건·작성자 22명이 일치**(43%,
    전부 인스타). 사람 눈으로는 절대 못 거른다 — 글도 사람 말투고 계정도 진짜 사람 계정처럼 생겼다.
    막는 법은 **작성자 목록**(주문마다 새 계정이 생기니 도구로 다시 만든다)과 **갓 달린 댓글 두고 보기**.
    교훈: **같은 광고를 두 프로그램이 건드리면, 한쪽의 산출물이 다른 쪽의 입력이 된다** — 창구를 열기 전에
    "상대가 만든 것을 내가 진짜로 착각할 자리"부터 찾는다.


## 구매 문의 운영 규칙 (2026-09-20 대표 결정)

- **인스타는 사진 카드, 페이스북은 글**(2026-09-21). 인스타 DM은 글 속 주소가 눌리지 않는다.
- **전화가 아니라 문자 주문**으로 안내한다. 메시지에 계좌를 적지 않고 자사몰 상세페이지 하단과 같은 **「문자결제방법」 안내 사진 주소**를 보낸다(계좌가 대화에 남지 않고, 계좌를 바꿔도 사진만 갈면 된다).
- **구매 링크는 제품 상세 하나로 고정**한다(광고 랜딩이 무엇이든).
- **업체 이름을 쓰지 않는다.** 인스타 계정(둥둥이맘)은 일반 40대 개인 컨셉이라 "○○입니다"가 붙으면 컨셉이 깨지고, 페이스북도 같은 이유로 뺐다. 문구는 **플랫폼별로 나눠** 둔다(FB 4개·IG 4개).
- **파컨(파워컨텐츠) 광고에는 보내지 않는다.** 일반인이 소개하는 컨셉이라 업체가 말을 걸면 깨진다 → 광고 이름에 "파컨"이 들어가면 제외(설정에서 단어 추가 가능). 2026-09-20 실데이터에서 남김 12건 중 5건이 이 규칙으로 빠졌다.
- **공개 답글에는 계좌를 넣지 않는다**(누구나 보는 자리 — 사칭 위험). 테스트로 막아 뒀다.
- 시작은 **승인 방식**(사람이 [보내기]를 누름). 하루 반응을 보고 자동 보내기로 넘어간다.

## 첫 발송 실측 (2026-09-20 저녁)

- 시험 2건(본인 계정 FB·IG) + **실제 고객 3건** = 5건 전부 `sent`, 실패·미확인 0.
- **메타가 일반 고객 대상 비공개 메시지를 막지 않았다** — 표준 권한으로 되며 앱 검수가 필요 없었다(이게 이 기능의 최대 불확실성이었다).
- FB는 19:59 메시지 + 공개 답글, IG는 20:00 DM + 공개 답글. 메타 쪽 상태로 교차 확인.
