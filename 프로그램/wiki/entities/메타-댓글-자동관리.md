# 메타 댓글 자동관리

## 한 줄 정의

메타 광고(FB·IG) 소재에 달린 댓글 중 **문의와 일반 반응은 남기고 부정 댓글만 자동 처리**하는 윈도우 상시 프로그램. 댓글 수 자체가 소재를 인기 있어 보이게 하므로 **남길 댓글을 지우는 실수가 가장 비싸다.**

## 대표 운영 규칙 (1등급 — 대표 결정 2026-09-16)

| 경우 | FB | IG |
|---|---|---|
| 확실한 부정 | 숨김 | 숨김, 안 되면 삭제 |
| 애매한 부정 | **숨김**(알림에 애매 표시) | 숨김, 안 되면 알림만 |
| 숨김 실패 | 알림만 — **FB 삭제는 어떤 경로로도 안 함** | 위 규칙 |

- FB는 숨김만: 삭제하면 작성자가 "내 댓글 지웠다"고 항의한다.
- IG는 비즈니스 스위트에 숨김 메뉴가 없어 삭제해 왔지만 **API로는 숨김이 된다**(`POST /{ig-comment-id}?hide=true`). 숨긴 댓글이 누구에게 보이는지는 문서에 없어 실측 후 IG 처리 방식을 정한다.
- **2026-09-17 대표 결정(실데이터 감사 뒤):** ① 인스타도 **무조건 숨김 먼저** — 숨김과 삭제 효과가 같으면 되돌릴 수 있는 숨김(설정의 "삭제 모드" 제거, 숨김이 일시 오류가 아닌 이유로 불가능할 때만 확실한 부정 삭제) ② **단어가 AI보다 먼저 판단하는 방식은 유지하되 단어를 좁힘**("사기꾼" 제외, 문의 단어는 "얼마에요"처럼 물음형 — 부분 일치라 "얼마나 사람을 속여야"도 문의로 남던 문제) ③ **이미 숨겨진 댓글은 건너뜀**(숨김이 풀리면 그때 판단).
- 판단 경계(대표 스크린샷 표본): "진짜인가요"·"구입원함"·"얼마에요 사고싶다"·"알려주세요" = 유지 / "거짓? 아니요?"·"말도 안되는 말"·욕설 = 부정. **궁금해서 묻는 질문은 유지, 단정·비난은 부정.**

## 구성 (재개판)

- 리포 `C:\claude\메타 댓글 자동삭제`(GitHub 비공개 `qorwnsdud102-svg/meta-comment-guard`), 브랜치 `resume-2026-09`.
- Python `.venv` · FastAPI 웹앱(운영 PC 포탈 `/comment/` → 8005, 광고 반응 부스터와 같은 레이아웃, **텔레그램 대신 화면**) · requests · anthropic SDK(AI Prime Tech 재판매 프록시, **Claude Opus 4.8** — 애매해도 숨기는 정책이라 오판 비용이 커져 대표가 Sonnet에서 올림) · SQLite(WAL·스키마 자동 갱신·단일 실행 잠금).
- **5분 회차(2026-09-17 새 방식):** 켜진 광고 1건 → 저장된 게시물 댓글 수를 배치 2건으로 → 수가 바뀐 게시물만 읽기(FB 최신순, 1시간마다 댓글 있는 게시물 전체 확인) → 소재가 바뀐 광고만 찾기(FB 미리보기 `videoID`, IG 소재 문구+±15분). 호출 한도는 주머니별로 쉼([[메타-API-호출-한도-주머니]]). 실측 평소 회차 **HTTP 3건·2초**, 첫 가동 124건·229초.
- 모듈: 설정(시스템 사용자 토큰 키 파일) · 처리 기록(판단 실패 3회·오류 알림 1시간 1회) · AI 판단(실패는 조용히 "유지"가 아니라 예외) · 처리 규칙표(순수 함수, FB에 DELETE가 나오는 조합 0) · 메타 연결(페이지 토큰 자동 발급·IG 전용 삭제·토큰 마스킹).

## 셋업 교훈 (재발 방지)

1. **토큰 권한은 "앱 이용 사례"에 있어야 고를 수 있다.** 광고용 이용 사례만 있는 앱에는 댓글 권한이 목록에 없다 → "페이지의 모든 부분 관리" + "Instagram에서 메시지 및 콘텐츠 관리"(**Facebook 로그인 방식**) 이용 사례를 추가한 뒤 권한을 넣는다. 새 앱은 필요 없었다.
2. **권한 추가 = 새 토큰 발급.** 기존 토큰에 권한이 붙지 않는다. 기존 토큰은 계속 유효하므로 같은 토큰을 쓰는 다른 프로그램은 영향 없음. 그래프 API 탐색기 토큰은 몇 시간짜리라 쓰지 않는다.
3. **시스템 사용자 토큰은 생성 창에서 한 번만 보인다.** 창을 닫았으면 다시 생성. "토큰 취소"는 같은 앱 토큰을 한꺼번에 끊을 수 있어 누르지 않는다.
4. **앱 게시(라이브)는 개인정보처리방침 URL만 있으면 됐다** — 자사몰 카페24 기본 페이지 `https://hito.kr/member/privacy.html` 사용.
5. 키 파일은 대표가 메모장으로 직접 저장(자동 모드가 Claude의 자격증명 파일 쓰기를 막는다). 토큰을 채팅에 붙여넣으면 대화 기록에 남는다 — 가동 확인 후 재발급 권장.
6. **가짜 AI만 쓰는 테스트는 SDK 설치 문제를 못 잡는다.** 공용 파이썬의 anthropic 0.39.0은 httpx 0.28.1과 맞지 않아 클라이언트 생성이 `proxies` 오류로 실패했는데, 테스트 129개가 전부 통과했다(모두 가짜 클라이언트 주입). 브랜치 전체 최종 검토에서 발견. 공용 파이썬은 포탈과 공유하므로 건드리지 않고 프로그램 폴더 전용 가상환경 `.venv`에 0.125.0 설치 + "실제 클라이언트를 네트워크 없이 생성만 하는" 테스트 추가. [[라이브-검증-프로토콜]]의 "조건 충족된 샌드박스는 통과할 수밖에 없는 테스트"와 같은 계열 — 가짜 객체만 주입하는 테스트는 설치 환경이라는 실제 조건을 건너뛴다.

## 만들며 배운 것 (2026-09-17 실데이터 감사)

7. **가짜 자료 테스트는 실제 응답 형식을 옮겨 적어야 한다.** 미리보기의 `"videoID":"숫자"`를 가정한 정규식이 테스트는 통과하고 실제 HTML(`"videoID":1712…` 따옴표 없음)에서 0개 — 저장한 실제 HTML에 한 번 돌려 보고서야 발견. 실제 응답은 **파일로 저장해 두고 그걸 테스트 자료로** 쓴다.
8. **실데이터 첫 회차가 설계서의 "되겠지"를 가장 싸게 깬다.** 테스트 266개 통과 상태에서 첫 실회차 225초 만에 FB 찾기 전부 실패·호출 한도 초과가 드러났다. 가동 전 "시험 DB·자동 처리 끔"으로 실회차를 먼저 돌리는 단계를 계획에 넣는다.
9. **조용한 멈춤이 가장 비싸다.** 감사가 찾은 높음 등급 대부분이 "화면은 초록인데 실제로는 안 돎"(FB 대상 0·AI 장애로 확인 필요 폭증·DB 잠김으로 기록 0·처리 시작 시각 이동으로 댓글 누락) — 하루 한 번 보는 사람용 도구는 **상태 판정(health)을 서버가 계산**해 문제와 할 일을 사람 말로 보인다.
10. **메타가 작성자(`from`)를 안 줄 수 있다.** 작성자를 모르면 자동 처리를 막는 규칙은 기능 전체를 멈춘다 → 되돌릴 수 있는 숨김은 하고 되돌릴 수 없는 삭제만 막는다.
