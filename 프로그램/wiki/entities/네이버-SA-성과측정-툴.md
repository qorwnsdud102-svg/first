# 네이버 SA 성과측정 툴 (성과측정 대시보드)

## 한 줄 정의

직원이 Claude Code + superpowers 사이클로 8일(2026-09-08~15) 만에 만든 로컬 프로그램 — 네이버 검색광고(파워링크·쇼핑검색·파워컨텐츠) 성과를 매일 수집하고, 스마트스토어 주문·정산과 원가 시트를 붙여 **브랜드별 순수익·손익분기 ROAS**를 내며, 키워드마다 유지/확대/소재/랜딩/OFF 검토를 규칙으로 추천한다. 사장님 최종 목표(네이버·구글·메타 × 스마트스토어·11번가·쿠팡·자사몰 × 카페 바이럴)의 **첫 1/3**.

## 2026-09-15 backstore1 광고 계정 연결 — 빠진 광고비가 순수익을 10% 부풀리고 있었다

- **발견.** 대시보드는 qorwnsdud102 계정만 수집하고 있었다. 같은 브랜드(일상곡선·멜라맘 등) 광고를 돌리는 backstore1 계정(캠페인 21개, 운영 중 4개)이 빠져, 매출은 잡히는데 그 광고비는 빠진 상태였다. 직원 NT 시트의 "back" 탭이 단서였다.
- **영향(9/8~9/14 실측).** 전체 실제 광고비 5,314,326 → 5,514,096원, 전체 순수익 1,923,267 → 1,723,497원(약 −10%), 일상곡선 ROAS 169.5 → 161.4%, 일상곡선 순수익 1,106,185 → 909,555원. 180일 기준 backstore1 보고 비용은 868만 원(전체의 약 4%)이지만 브랜드 하나에 몰려 있어 그 브랜드 판단이 크게 흔들린다.
- **주별로 보면 더 크다(180일 백필 후).** 7/27~9/13 일곱 주 동안 전체 주간 순수익이 매주 14만~34만 원씩 줄었고, 8/24~8/30 주는 흑자 116,783원이 적자 −93,905원으로 뒤집혔다. 일상곡선은 적자 주가 3주 → 4주.
- **설계.** 키 파일 `[account.<id>]` 블록으로 계정 추가, DB 네 테이블에 `customer_id`(NULL=기본 계정), 수집기의 삭제·덮어쓰기·완료 판정을 계정 범위로. 판단은 모든 계정 수집 뒤 한 번, 어느 계정이든 어제 수집이 실패하면 건너뜀. → [[수집-파이프라인-안전장치]] 11번.
- **교훈.** "데이터가 정확한가"는 숫자 대조만으로는 안 보인다. 광고주센터와 대시보드 합계가 원 단위까지 맞았는데도 **계정 하나가 통째로 빠져 있었다.** 입력 검증의 첫 질문은 "빠진 원천이 없는가"다 — 광고 계정·스토어·판매 채널 목록을 사람이 아는 전체 목록과 먼저 맞춘다.
- **독립 리뷰 반영(같은 날).** 한 계정만 백필해도 모든 계정의 어제 수집 상태를 보고 판단한다. 백필 전 마스터 동기화에 실패한 계정은 빼고 계속하며 결과에 `skipped_accounts`를 남긴다. 설정 탭 키 배지는 마지막 마스터 동기화 결과를 보여 주고, 수집 로그 API는 계정 ID 대신 이름만 돌려준다. 키 파일의 깨진 `[account.` 머리글은 줄 번호와 함께 오류를 낸다. → [[수집-파이프라인-안전장치]] 11번.

## 2026-09-15 디스플레이(카탈로그 판매) 광고비 CSV 반입 — 파일 원천에도 "반영 여부"를 붙인다

- **발견.** hundredjy 광고주센터(광고 계정 미드디, 디스플레이 계정 ID 1566978)의 카탈로그 판매 광고(스마트스토어 방문자 리타겟팅, 모든 제품 공용)가 대시보드에 없었다. 8/17~9/15 30일 총비용 817,897원(VAT 포함), 실제 광고비 약 73만 원.
- **API 없음.** 디스플레이 광고 API는 네이버 공식 파트너사 전용(고객센터 안내). 검색광고 API에는 디스플레이가 없다. 대표 결정: 처음엔 "기간·총비용 수기 입력"이었다가, 기간을 바꿔 가며 순수익을 보려면 일별 원자료가 있어야 한다는 이유로 **광고비 보고서 CSV(일별) 반입**으로 바꿨다.
- **설계.** 표 `display_costs`(날짜·계정 PK, 총비용·유형별 JSON). 설정 탭 카드: 반영된 기간·다음에 내려받을 기간·번호 순서·파일 올리기(raw body POST, multipart 의존성 없음)·폴더 다시 읽기·읽은 파일 표. 대시보드: 히어로에 네이버/디스플레이 분해와 반영 상태(반영·일부만 반영·미반영 + 설정 탭 링크), 브랜드 표 배분 툴팁·미배분 안내, 기간별 표에 "└ 네이버 검색"·"└ 디스플레이" 행(열마다 미반영/†), 유형별 표에 "디스플레이 · 카탈로그 판매" 줄. 계수 `NAVER_DISPLAY` = 1/1.1 − 0.017. 매일 수집에 `display_import` 단계. → [[수집-파이프라인-안전장치]] 12번, [[실제-광고비-계수]].
- **같은 날 부가세 결정.** 실제 광고비의 부가세를 시트의 ×0.91 대신 ÷1.1로(네 유형 모두). 검색광고 총비용은 VAT 포함이라는 대표 확인.
- **교훈.** 파일로 넣는 원천은 "넣었는가"를 화면이 말해 줘야 한다. 자료 없는 기간을 0원으로 보여 주면 순수익이 부풀고, 반대로 넣은 기간을 다시 넣게 하면 사용자가 지친다 — 원자료 보존 + 반영 여부 + 다음 기간 안내 세 가지가 한 세트다.
