# 네이버 SA 성과측정 툴 (성과측정 대시보드)

## 한 줄 정의

직원이 Claude Code + superpowers 사이클로 8일(2026-09-08~15) 만에 만든 로컬 프로그램 — 네이버 검색광고 성과를 매일 수집하고 스마트스토어 주문·정산과 원가 시트를 붙여 **브랜드별 순수익·손익분기 ROAS**를 내며, 키워드마다 유지/확대/소재/랜딩/OFF 검토를 규칙으로 추천한다. 이후 [[전체-대시보드]]로 자랐다.

## 무엇·어디

- 저장소 `C:\claude\성과측정 대시보드`. Python · FastAPI(단일 워커) · SQLite(WAL) · 바닐라 JS · 포트 8010 · 작업 스케줄러 매일 수집.
- 데이터 소스: [[네이버-검색광고-API]] Stat Report / [[네이버-커머스API]] 주문·정산(스토어 2개) / 구글 원가·풀필먼트 시트 / 사용자정의채널 엑셀([[NT-파라미터-매출-귀속]]) / 디스플레이 광고비 CSV(API 없음).

## 핵심 설계 결정

- 계산 계층: [[실제-광고비-계수]] → [[주문별-이익-모델]] → [[자동입찰-존중-판단-규칙]]. 표시 [[모름-vs-0-표시-규약]], 수집 [[수집-파이프라인-안전장치]].
- 여러 광고 계정은 키 파일 `[account.<id>]` 블록 + 테이블별 `customer_id`, 삭제·완료 판정은 계정 범위로, 판단은 모든 계정 수집 뒤 한 번(수집 11번).
- 부가세는 ÷1.1(검색광고 총비용은 VAT 포함). 파일 원천(디스플레이 CSV)은 원자료 보존 + 반영 여부 + 다음 기간 안내(수집 12번).
- 검토 규약: 실 DB 금지(사본 + 별도 포트), 저장·수집 버튼 금지, 키 파일 열람 금지, 실 API는 GET만.

## 만들며 배운 것

- **입력 검증의 첫 질문은 "빠진 원천이 없는가"** — 합계가 원 단위까지 맞았는데 광고 계정 하나가 통째로 빠져 순수익이 10% 부풀어 있었다. 계정·스토어·채널 목록을 사람이 아는 전체 목록과 먼저 맞춘다.
- 파일로 넣는 원천은 "넣었는가"를 화면이 말해 줘야 한다 — 자료 없는 기간을 0원으로 보이면 순수익이 부푼다 → [[모름-vs-0-표시-규약]].
- 검토가 만든 것의 절반만큼을 고쳤다(fix:feat = 61:62). 반복 유형: 모름→0 표시 · 경계 검증 · 부분 응답으로 대량 삭제 · 병합 vs 통째 교체 · 이중 계산 · 비밀 유출 · 원자성 · 프런트 레이스 · 실데이터 문턱 → [[Claude-Skill]] 5역할의 실측 표본, [[바이브-코딩]] "기획 먼저".
- 이름으로 탭을 찾고 **고정 열**로 읽는 마진 시트 코드는 양식이 바뀌면 오류 없이 틀린 값을 넣는다 → [[시트-칸-골라읽기]] · [[실마진-공헌이익-모델]](실마진을 쓰면 수수료·풀필먼트·원가 차감 코드를 꺼야 두 번 안 빠진다).
- 테스트가 실보고서를 덮어쓴 사고 — 테스트는 임시 폴더만.
