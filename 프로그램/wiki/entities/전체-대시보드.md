# 전체 대시보드 (회사 손익 대시보드)

## 교훈 — 계산

- **월 청구서가 이기고, 일별 자료는 나누는 비율로만 쓴다.** 쿠팡 광고는 달마다 청구된 캠페인 파일이 정답이고, 일별 보고서(pa_daily)는 그 달 금액을 날짜에 나누는 가중치(최대 나머지 방식)로만 쓴다. 일별 파일만 있는 달은 일별 값 그대로. 일별이 그 달 **일부만** 덮으면 알림 — 다 덮으면 알림 없음. 이렇게 하니 1~8월 월 합계는 한 푼도 안 바뀌고(구글 −2,642원 제외) 일별 브랜드 이익이 생겼다.
- **보고서 파일은 모양이 여러 개다.** 구글 애즈는 「캠페인 보고서」(상태·합계 줄 있음 → 검산)와 보고서 편집기 「제목 없는 보고서」(날짜 줄만 → 검산 없음) 둘 다 온다. 필수 칸만 요구하고, 검산은 **검산할 재료가 있을 때만**.
- **파일 이름 규칙은 사람이 늘 조금씩 바꾼다.** ESM이 `_지마켓_`, `_YY.MM.DD-YY.MM.DD` 이름으로 오자 「확인 필요」가 떴다. 별칭 표 + 기간 이름 허용으로 풀었고, 같은 정규식이 원본 격자에서 `09.01-26.09`를 **2009-01~2026-09**로 읽는 버그도 같이 나왔다 — 이름 해석은 한 함수로.
- **원가에 이미 든 비용은 또 빼면 이중 차감.** 제품 원가(실마진 시트)에 넣은 알바비가 프리랜서 탭에도 있었다 → 프리랜서 탭 「비용처리필요」 칸 X = 비용 아님, 지출 탭 유형 「제품 제작 인건비」 = 비용 아님. 8·9월 공통비용이 60.9만 원 줄었다. 모르는 값(O/X 아님)은 비용으로 두고 알림 → [[실마진-공헌이익-모델]].
- **부가세 칸이 비면 짐작하지 않고 보류.** 지출 탭: 빈칸 → 보류, `x` → 부가세 없음, 숫자 → 비용 = 지출 − 부가세. 9월 급여가 「아직 안 들어감」으로 보인 원인이 이것(대표가 x를 넣자 해결).
- **「진행 중인 달」 안내는 데이터로 켠다.** 「월말 급여 아직」 문구를 늘 띄우니 대표가 오류로 읽었다 → 진행 중인 달 인건비가 지난달의 절반 미만일 때만.

## 교훈 — 빈 자료 판정

- **빈 날은 「수집 기록」으로 판정한다.** 광고비가 0인 날이 「안 썼음」인지 「못 받음」인지는 금액으로 모른다. 네이버·메타는 수집 기록(ok/no_data)이 있는 날만 「받았음」으로 보고, 나머지를 「광고비 자료 없음: 메타(9/16~9/25 없음)」처럼 **날짜로** 알린다 → [[모름-vs-0-표시-규약]].
- **API 가게의 빈 날은 표시하고 사람이 누른다.** 주문을 API로 받는 가게(스마트스토어·카페24·쿠팡·11번가)의 주문 없는 날은 누락보다 「진짜 주문 없음」일 가능성이 크다 → 「API로 받음」 배지를 달고, 「정상(원래 없음)」은 **대표가 누른다**(자동으로 정상 처리하지 않음). (2026-10-06부터 이 버튼은 대시보드가 아니라 '자료 넣기' 탭에 있다 — 아래.)

## 교훈 — 자료 넣기 (2026-10-06)

어떤 채널 엑셀이 언제부터 언제까지 필요한지 보여 주는 탭(대표·직원 공용). 설계서 `docs/superpowers/specs/2026-10-06-자료-넣기-design.md`.

- **「빠짐」은 파일이 덮는 날로 판정하고, 매출 0원으로 판정하지 않는다.** 파일이 덮는 기간 안의 매출 없는 날은 「0원 확인」(막대 빗금)이고 알림이 아니다. 대표 지적: "9/1~9/30 파일을 줬는데 9/23~25 매출 없다고 알리지 마, 딱 봐도 0원이잖아." → 파일 하나가 덮는 기간을 이름·내용에서 읽어 스캔 때 저장한다(`raw_files.meta_json["period"]`).
- **덮는 날 = 원본 폴더 파일 ∪ DB에 실제로 들어 있는 날.** 설정 화면에서 올린 파일은 원본 폴더가 아니라 `data/display` 등에 저장된다. 원본 폴더만 세면 실제로 있는 9/1~15 디스플레이가 「빠짐」으로 나왔다(실데이터 검증에서 발견).
- **월 단위 파일은 「달이 끝나야 넣을 수 있다」를 따로 보여 준다.** 진행 중인 달은 할 일이 아니라 「반영 전」이고, 순이익 칸 옆에 「월 단위 엑셀 반영 전」을 바로 붙인다. 이것까지 「확인할 것」 개수에 넣으니 대시보드가 영영 초록이 안 됐다 → 할 일이 있을 때만 센다.
- **쿠팡 정산은 「아직 정산 전」 기간이 있다.** 최근 약 35일은 리포트가 아직 안 나왔을 수 있어 「반영 전 — 숫자는 추정」으로 둔다. 주는 정산주기 종료일로 만들고(월요일과 그달 1일 중 늦은 날부터), CATEGORY_TR이 있어야 그 주를 「있음」으로 친다. 하루에 정산 리포트가 여러 개 생기기도 한다.
- **예전 「정상」 표시를 버리지 않는다.** 새 열쇠(`need|줄|시작|끝`)를 쓰되 예전 열쇠(`store|`·`ad|`·`excel|`·`coupang_ad|`)도 같이 읽고 같이 쓴다 — 손익 확정 판단(cost_ledger)이 예전 열쇠를 보기 때문. 쿠팡 API 가게는 로켓그로스·윙 **둘 다** 정상일 때만 정상(한쪽 표시가 다른 쪽 수집 끊김을 가리지 않게).
- **저장된 열쇠는 엄격히 검사한다.** 파이썬 3.11+의 `date.fromisoformat`은 `20260901`도 받아, 달을 90으로 읽어 끝없이 도는 버그가 났다 → 날짜는 정규식 `YYYY-MM-DD`로 먼저 거른다.
- **다운로드 안내는 직접 받아 보며 만든다.** 사이트마다 대표와 같이 받아 보니 문서·짐작과 달랐다:
  - 네이버 디스플레이 — 게재 위치 기본값이 「매체 그룹」(하루 여러 줄) → 「전체」로 받거나 날마다 더해 읽기.
  - ESM — 판매진행내역 「매출기준」, 파일 이름이 고정이라 기간을 이름에 붙여야 한다.
  - 쿠팡 로켓그로스 — 기준일 「매출 인식일」, 리포트 9종을 줄마다 따로 받는다. 70%·30% 리포트는 내용이 같다.
  - 쿠팡 광고 — Wing [광고비 내역] 탭 엑셀은 일부 광고만 있다. 광고센터 「일별 광고비 정산내역」이 손으로 합친 월별 파일과 캠페인마다 같다(8월 2,271,596원) → 이것으로 대체.
  - 네이버 NT — 옛 양식(사용자정의채널)은 2026-10-28에 끝나고, 새 양식(방문 분석)은 일부 전환이 빠진다.
  - 안내 그림은 원본 캡처에 빨간 상자·번호를 그리고 고객명·금액을 흐린 뒤 저장소에 넣는다(원본 캡처는 저장소 밖).
- **파일 내용으로 스스로 검산하고, 어긋나면 넣지 않는다.** 쿠팡 정산내역은 날짜 줄 합계 = 캠페인 줄 합계일 때만 그 달을 통째로 바꾼다. 빈 파일로는 지우지 않는다. 같은 달 파일이 여럿이면 나중에 받은 파일이 이긴다(이름 순으로 두면 ` (1)` 사본이 진다).
- **판정은 손익의 '미확정' 규칙과 같아야 한다.** 할 일 목록이 "빠진 것 없음"인데 순이익 칸은 '미확정'이면 대표가 어느 쪽도 믿지 못한다. 가게 첫 주문 전 기간·시작일만 있는 광고·로켓그로스 매출은 있는데 쿠팡 광고 자료가 없는 계정·원본 격자의 밀크런·주문 파일까지 같은 규칙으로 맞췄고, '정상'을 누르면 예전 열쇠도 같이 써서 손익 확정에도 그대로 반영된다. 쿠팡 로켓그로스·윙처럼 이름이 둘인 가게는 이름마다 따로 판정한다.

## 교훈 — 웹 올리기 (자료 넣기 3단계, 2026-10-06)

줄마다 ① 받기(사이트 열기·그림) ② 넣기(끌어 놓기 — 대표·직원 어느 PC에서든) ③ 확인. 계획 `docs/superpowers/plans/2026-10-06-자료-넣기-3단계.md`.

- **받는 곳은 둘, 정리하는 곳은 하나.** 간략 대시보드(읽기 전용 DB)는 양식만 확인해 원본 폴더 `_받은 파일\`에 파일+메타를 내려놓기만 하고, 전체 대시보드 서버만 처리한다(올린 즉시 + 30초마다). 직원 화면 서버가 DB를 쓰지 않는다는 원칙을 지키면서 직원도 올릴 수 있다.
- **"옛 파일 보관"은 새 파일이 옛 파일 내용을 다 담는다고 확신할 수 있는 종류만.** 처음엔 기간만 보고 쿠팡 정산 파일도 보관하게 했는데, 쿠팡 정산은 같은 주를 일부러 여러 파일로 나눠 받기도 하고 가져오기가 매번 다시 덧씌워서, 옛 파일에만 있던 주문이 다음 동기화 때 되돌아간다(검토에서 발견). → 보관은 ESM만(주문번호로 덮어쓰기, 나중 전체 기간 파일이 상위 집합). 나머지는 둘 다 두고 가져오기가 중복을 한 번만 센다. 같은 주라도 리포트 종류가 다르면 절대 같이 보관하지 않는다.
- **사람만 아는 것은 사람에게 묻고, 짐작하지 않는다.** ESM 파일은 이름이 늘 같고 내용으로 기간을 못 정한다 → 올릴 때 "사이트에서 검색한 기간"(한 번에 1개월까지 — 사이트 제한과 같게)을 받는다. 주문·밀크런은 주문 날짜로 달을 짐작하면 빈 달이 '있음'이 되므로 "이 파일이 담은 달"을 고르게 한다. 처음 값은 빠진 기간으로 미리 채운다.
- **가져온 뒤에는 되돌리지 않는다.** 파일을 자리로 옮긴 뒤 기록 쓰기가 실패해 파일만 되돌리면, DB 숫자와 파일이 어긋난다. 옮기기 전에 메타에 "어디로 옮김"을 적어 두고(저널), 다음 차례에 마무리한다. 옮길 때는 절대 덮어쓰지 않는다(`os.rename`).
- **되돌리기는 파일만 되돌린다는 것을 화면에 정직하게 쓴다.** 가져오기는 파일이 빠져도 이미 들어간 줄을 지우지 않으므로, 새 파일에만 있던 줄은 숫자에 남는다. 뒤에 올린 파일이 보관해 버린 파일은 먼저 되돌리지 못하게 막는다.
- **잠금은 '폴더를 훑는 모든 길'에.** 올리기 처리, 30초 처리, '지금 읽기' 버튼, 채널 가져오기 버튼, 설정 저장 뒤 다시 만들기가 같은 잠금을 쓴다. 다른 프로세스(07:00 수집)는 파일 잠금을 보고 그 차례만 건너뛴다.
- **올리기 본문은 다 읽기 전에 크기부터.** `request.body()`는 전부 메모리에 올린다 → Content-Length와 읽는 중 누적으로 30MB 넘으면 바로 413. 포털(리버스 프록시)은 200MB까지 흘려보내고 머리글을 지우지 않으며, 화면은 상대 경로(`App.url`)로 보내야 한다.
- **사람이 준 이름·줄 id는 경로에 쓰지 않는다.** 실제로 있는 할 일 줄인지 확인하고, 계정은 길이·윈도 예약어(CON·NUL…)·보이지 않는 글자까지 거른다. 직원 화면 기록에는 경로·내부 오류 이름을 보내지 않는다.
- **배포 묶음도 시험한다.** 코드 ZIP 스크립트가 html·css·js만 담아 안내 그림(png)이 빠질 뻔했다 → 정해진 폴더의 그림만 허용.

## 교훈 — 운영

- 버튼 이름이 말하는 범위와 실제로 읽는 원천이 다를 수 있다 — 어느 원천을 다시 읽는지 확인하고 누른다.
- 상태를 바꾸는 POST는 `X-SA-Client: dashboard` 헤더가 있어야 받는다(다른 출처 폼 차단, 스크립트도 같은 헤더) → [[유료-주문-이중결제-방지-패턴]].
- 실제 화면 점검은 헤드리스로 → [[라이브-검증-프로토콜]]. (2026-09 말엔 큰 작업을 클라우드 세션에 맡겼으나 토큰이 모자랐을 때뿐 — 2026-10-06부터 대표 지시로 한 세션이 직접 만든다 → [[여러-클로드-세션-협업]].)
- 숫자를 건드리지 않는 기능도 **같은 DB 복사본에 main 코드와 새 코드를 각각 돌려** 달마다 매출·순이익·브랜드 이익·미확정 이유를 대조한 뒤 합친다(자료 넣기: 1~9월 전부 같음).

## 교훈 — 분석에 쓰기

- 이익이 떨어지면 **판매이익률(원가 문제인가) → 매출 → 판매처별 매출(어느 문이 닫혔나) → 광고 매체별(무엇을 언제 바꿨나) → 캠페인 노출·클릭률 → 광고그룹 직접 ROAS** 순으로 쪼갠다.
- 광고비를 바꾼 **달**과 매출이 빠진 **달**을 나란히 놓으면 한 달 지연이 보인다(메타를 끈 뒤 자사몰 매출이 한 달 늦게 빠진 사례 — 시기 일치만, 인과는 재개 시험으로).
- 클릭이 같아도 판매가 줄 수 있다 — 넓힌 키워드는 질 낮은 유입 → [[측정-지표-함정]].

## 내 생각 / 미해결 질문

- 과거 기간 화면에 「현재 상태」 필터(운영중만)를 걸면 지난달이 비어 버린다 — 과거 기간엔 현재 상태 필터를 끄는 게 맞을 듯.
- 부호 색 규칙(적자 빨강)과 계열 색 규칙이 부딪힐 때 어느 쪽이 이기나.
