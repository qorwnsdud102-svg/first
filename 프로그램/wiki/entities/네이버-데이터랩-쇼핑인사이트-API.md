# 네이버 데이터랩 쇼핑인사이트 API

## 한 줄 정의

키워드·분야의 **월별 검색 추이(상대비율)** 를 주는 공식 API. 급등·신규 판정의 유일한 시간축 소스.
발급처가 개발자센터 → [[NAVER-API-HUB]] 로 이관 중이라 **엔드포인트가 두 벌** 존재한다.

## 두 벌의 엔드포인트 (요청 바디·응답은 완전 동일)

| | 개발자센터 (레거시) | NAVER API HUB (신규) |
|---|---|---|
| URL | `openapi.naver.com/v1/datalab/shopping/category/keywords` | `naverapihub.apigw.ntruss.com/shopping/v1/category/keywords` |
| 헤더 | `X-Naver-Client-Id` / `X-Naver-Client-Secret` | `X-NCP-APIGW-API-KEY-ID` / `X-NCP-APIGW-API-KEY` |
| 계정 | 네이버 계정 | NCP(네이버 클라우드) 계정 |
| 쿼터 | **일 1,000콜/키** | **월 30,000콜 기본무료** (일일 제한 없음) |

→ 이관 비용은 **URL 1줄 + 헤더 2개**. 바디(`startDate·endDate·timeUnit·category·keyword`)와
응답(`results[].data[].{period, ratio}`) 구조가 그대로라 어댑터 하나로 양쪽 지원 가능.

## 요청 규격

```
POST  body(JSON): { startDate, endDate, timeUnit: 'month',
                    category: '<네이버 CID>',           # 문자열
                    keyword: [{name, param:[kw]}, ...], # 최대 5개
                    device:'', gender:'', ages:[] }
```

- **1콜 = 키워드 5개** — 쿼터 계산의 기본 단위(월 30,000콜 = 키워드 15만 개).
- 데이터 시작은 2017-08-01.
- `ratio` 는 **응답 전체에서 최댓값=100** 인 상대값. 한 콜에 검색량 차이가 큰 키워드를 섞으면 작은
  키워드가 0 에 수렴해 정밀도가 깨진다 → **검색수 순으로 정렬해 비슷한 것끼리 묶어 호출**.
- 절대 검색수 역산: `해당월 ratio / 기준월 ratio × 그 키워드의 실제 월간 검색수`.

## ⚠️ 검색 없는 달은 응답에서 생략된다 (최대 트랩)

0 으로 주지 않고 **배열에서 통째로 빠진다.** 비건뷰티 조회 시 8개월 중 5월·7월이 없음.

- 이걸 0 으로 복원하지 않으면 **"N개월 전 0 → 지금 급등" = 신규 판정이 구조적으로 성립 불가**.
  실제로 7,889개를 돌려 신규 브랜드 **0건**이 나왔고, 4월 첫등장한 명백한 신규가 '급등' 으로 오분류됐다.
- 대응: 조회기간 전체 월 목록을 만들어 `{m: got.get(m, 0.0) for m in months}`.
- 일반화 → [[측정-지표-함정]] §침묵하는 결측.

## 이관 일정 (2026)

| 시점 | 내용 |
|---|---|
| 2026-06-25 | NAVER API HUB 정식 출시 |
| **2026-07-31** | 개발자센터에서 **검색 API·검색어트렌드·쇼핑인사이트 신규 신청 차단** (등록 화면 드롭다운에서 사라짐) |
| 2027-06-30 | 개발자센터 지원 종료 — **기존 발급 키도 이후 차단** |

- 기존 키는 2027-06-30 까지 정상 작동(유예). 신규 발급은 API HUB 에서만.
- **이관 제외**: 검색 API 중 `쇼핑·책·전문자료` 는 2026-07-31 완전 종료(대체 없음). `webkr` 등은 무사.

## 쿼터 운용

- 개발자센터: 키(앱)당 **일 1,000콜**. `_dl_idx` 라운드로빈으로 950콜마다 다음 키. 소진 시 429
  `{count/quota=1000/1000}`.
- API HUB: **일일 제한 없음 + 월 30,000콜 기본무료**. 30,001~50,000 구간은 "한시적 무료"(추후 유료화
  가능) → **콘솔 월 한도를 30,000 으로 막아두면 과금 사고가 원천 차단**된다.
- 하루에 몰아 쓸 수 있게 되면서 "후보를 잘게 압축" 하던 설계 제약이 사라졌다 → [[API-쿼터-경제학]].

## 다른 엔티티와의 관계

- [[NAVER-API-HUB]] — 새 발급처·콘솔·요금.
- [[ItemScout-API]] — 짝. 후보 전수와 절대 검색수를 무료로 담당.
- [[네이버-검색광고-API]] — 같은 프로젝트의 다른 네이버 API. 인증 방식(HMAC) 다름.
- [[네이버-급등-신규브랜드-탐지-노하우]] — 이 API 로 급등·신규를 판정하는 실전편.

## 내 생각 / 미해결 질문

- **비공식 웹 엔드포인트(`datalab.naver.com/shoppingInsight/*`)는 쓰지 말 것** — IP 차단 대상.
  공식 API 로 옮기면 문제가 "차단"(해결 불가)에서 "쿼터"(돈·시간으로 해결)로 바뀐다.
- `timeUnit=week/date` 는 미사용. 주 단위로 보면 "1달 이내 급등" 을 더 예민하게 잡을 수 있을지 미검증.
