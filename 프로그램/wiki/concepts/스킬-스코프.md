# 스킬 스코프

## 한 줄 정의

Claude Code가 [[Claude-Skill|스킬]]을 **어디서 읽어와서 언제 발동시키는지의 규칙**. user-level(글로벌)·project-level(프로젝트 한정) 두 스코프가 있고, 발동은 SKILL.md frontmatter `description:` 매칭으로 자동 트리거.

## 핵심 주장 / 속성

### 두 스코프

| 스코프 | 위치 | 효과 범위 |
|---|---|---|
| **user-level** (글로벌) | `~/.claude/skills/<이름>/SKILL.md` | **CWD 무관** — PC의 어느 폴더에서 `claude` 띄워도 작동 |
| **project-level** (프로젝트 한정) | `<프로젝트>/.claude/skills/<이름>/SKILL.md` | 그 프로젝트 안에서만 작동. 다른 프로젝트엔 영향 X |

→ "어디서든 작동"을 원하면 **user-level**, "이 저장소에서만 도는 특수 스킬"이면 **project-level**.

### 발동 방식 — description 매칭

각 `SKILL.md`의 frontmatter `description:` 필드가 사용자 발화·맥락에 의미적으로 매칭될 때 **자동 발동**. 명시 호출 없이도 알아서 들어옴.

예 — `karpathy-guidelines` 스킬의 description:
> "Use when writing, reviewing, or refactoring code to avoid overcomplication, make surgical changes, surface assumptions, and define verifiable success criteria."

→ 코드 작성·리뷰·리팩터 작업 시 자동 발동.

`brainstorming` description:
> "Refines rough ideas through questions, explores alternatives, presents design in sections for validation."

→ "이거 어떻게 만들지 같이 정해보자" 같은 설계 단계 발화에 자동 발동.

### 항상-로드 baseline은 별도 레이어

description 매칭이 안 닿는 발화에도 **무조건 적용**돼야 하는 규범은 스킬이 아니라 **`~/.claude/CLAUDE.md`** (user-level memory)에 박는다.

- 스킬 = 상황별 호출되는 직원 (5인 사이클) — description 매칭으로 발동
- ~/.claude/CLAUDE.md = 모든 세션 시작 시 무조건 로드되는 가게 매뉴얼 — vault 밖 프로젝트(예: `C:\CLAUDE\ATM WEBSTIE`) 세션도 이걸 통해 "5인 역할분담" 같은 메타 프레임 인지 가능

**왜 필요한가**: 스킬은 작업 단위로 발동되지만 "5인 사이클 메타 프레임" 같은 framework-level 지식은 vault 위키 안에만 있어서 vault 밖 프로젝트 세션은 모름. ~/.claude/CLAUDE.md에 핵심 framework 박으면 모든 세션이 인지.

### 세션 시작 시 한 번 로드

스킬 인덱스는 **세션 시작 시점**에 잠긴다. 세션 도중에 `~/.claude/skills/` 폴더에 새 SKILL.md를 떨궈도 그 세션엔 반영 X — **새 세션부터** 적용. 점검 시 항상 새 터미널.

## 본 vault의 운영 선택

- **5인 사이클 5스킬 + karpathy-guidelines = 모두 user-level**. 사장님은 여러 폴더·프로젝트를 옮겨가며 Claude Code를 띄우니까 글로벌이 자연 선택.
- project-level은 본 vault 범위 밖에서 다룸 — 특정 저장소(naver-biding 같은 운영 PC 코드)에 그 프로젝트 한정 스킬이 필요할 경우 그 저장소 안에 `.claude/skills/`로 격리.
- 새 PC 셋업 시 user-level 설치만으로 충분하지 project-level까지 손댈 일 X (특수 케이스 빼고).

## 폴더 layout

```
~/.claude/
├── skills/                          ← user-level 스킬 (어디서 띄워도 작동)
│   ├── brainstorming/
│   │   └── SKILL.md                 ← description:으로 auto-trigger
│   ├── writing-plans/
│   ├── verification-before-completion/
│   ├── requesting-code-review/
│   ├── writing-skills/
│   └── karpathy-guidelines/
├── CLAUDE.md (옵션)                  ← 모든 세션 무조건 로드 (description 매칭 X)
├── plugins/                         ← 플러그인 묶음 (superpowers 통설치가 여기)
└── settings.json                    ← Claude Code 전역 설정
```

## 새 PC 셋업 · 글로벌 CLAUDE.md

- 설치: `_setup/README.md` §스킬·플러그인 설치 (superpowers 플러그인 + karpathy-guidelines → 새 터미널에서 확인).
- `~/.claude/CLAUDE.md`(모든 세션 무조건 로드)의 **정본은 `_setup/claude-global.md`** 하나다. 이 페이지에 두던 읽기용 미러는 2026-10-06 지웠다 — 정본과 어긋나도 아무도 몰랐고(드리프트 가드는 라이브↔`_setup`만 본다), 미러에만 있던 줄은 없었다(대조 확인). 내용을 보려면 정본을 연다.
- **왜 install.ps1이 필요한가**: `~/.claude/`(글로벌 CLAUDE.md·settings.json hook)는 **vault 밖**이라 git pull로 안 따라간다. vault는 *지식*만 동기화 → 각 PC에서 `_setup/install.ps1`로 그 지식을 `~/.claude/`에 한 번 박아줘야 "어디서나 자동 로드"가 된다. 새 PC는 `git pull → install.ps1 → 새 터미널` 3스텝.
- 라이브가 정본과 어긋난 채 Edit/Write 하면 `_setup/check-claudemd-sync.ps1` hook이 경고한다. hook도 **새 터미널/`/hooks`부터** 활성(세션 시작 시 settings 잠금).

## 다른 엔티티와의 관계

- [[Claude-Skill]] — 스킬 본체. 본 페이지는 그 스킬들이 "어디 살고 언제 깨어나는지" 메커니즘.
- [[superpowers]] · [[karpathy-guidelines]] — 본 vault에서 user-level 스코프로 설치하는 두 출처(superpowers는 플러그인 통설치).
- [[클로드-베이커리-비유]] — 본 페이지의 "스킬 vs ~/.claude/CLAUDE.md" 구분이 비유의 "직원 vs 운영 매뉴얼" 구분과 1:1.

## 내 생각 / 미해결 질문

- `~/.claude/CLAUDE.md` 도입·다PC 자동화 경위 → 상세 기록: 프로그램/프로젝트/운영-공통/스킬-설치-이력.md
- **project-level 사용 케이스**: 본 vault에선 안 쓰지만, naver-biding 같은 외부 운영 코드 저장소에선 그 프로젝트 한정 스킬(특정 API 호출 패턴 등)이 정착할 가능성. 그때 그 저장소 CLAUDE.md에서 정의.
- **세션 시작 시 잠금**의 부작용: 새 스킬·플러그인을 추가한 직후엔 항상 새 터미널 필요 — 잊고 같은 세션에서 호출 시도해서 "왜 안 되지?" 헷갈리는 트랩.
