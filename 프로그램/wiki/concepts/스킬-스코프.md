# 스킬 스코프

## 한 줄 정의

Claude Code가 [[Claude-Skill|스킬]]을 **어디서 읽어와서 언제 발동시키는지의 규칙**. user-level(글로벌)·project-level(프로젝트 한정) 두 스코프가 있고, 발동은 SKILL.md frontmatter `description:` 매칭으로 자동 트리거.

## 핵심 주장 / 속성

### 두 스코프

| 스코프 | 위치 | 효과 범위 |
|---|---|---|
| **user-level** (글로벌) | `~/.claude/skills/<이름>/SKILL.md` | **CWD 무관** — PC의 어느 폴더에서 `claude` 띄워도 작동 |
| **project-level** (프로젝트 한정) | `<프로젝트>/.claude/skills/<이름>/SKILL.md` | 그 프로젝트 안에서만 작동. 다른 프로젝트엔 영향 X |

→ "어디서든 작동"을 원하면 **user-level**, "이 저장소에서만 도는 특수 스킬"이면 **project-level**.

### 발동 방식 — description 매칭

각 `SKILL.md`의 frontmatter `description:` 필드가 사용자 발화·맥락에 의미적으로 매칭될 때 **자동 발동**. 명시 호출 없이도 알아서 들어옴.

예 — `karpathy-guidelines` 스킬의 description:
> "Use when writing, reviewing, or refactoring code to avoid overcomplication, make surgical changes, surface assumptions, and define verifiable success criteria."

→ 코드 작성·리뷰·리팩터 작업 시 자동 발동.

`brainstorming` description:
> "Refines rough ideas through questions, explores alternatives, presents design in sections for validation."

→ "이거 어떻게 만들지 같이 정해보자" 같은 설계 단계 발화에 자동 발동.

### 항상-로드 baseline은 별도 레이어

description 매칭이 안 닿는 발화에도 **무조건 적용**돼야 하는 규범은 스킬이 아니라 **`~/.claude/CLAUDE.md`** (user-level memory)에 박는다.

- 스킬 = 상황별 호출되는 직원 (5인 사이클) — description 매칭으로 발동
- ~/.claude/CLAUDE.md = 모든 세션 시작 시 무조건 로드되는 가게 매뉴얼 — vault 밖 프로젝트(예: `C:\CLAUDE\ATM WEBSTIE`) 세션도 이걸 통해 "5인 역할분담" 같은 메타 프레임 인지 가능

**왜 필요한가**: 스킬은 작업 단위로 발동되지만 "5인 사이클 메타 프레임" 같은 framework-level 지식은 vault 위키 안에만 있어서 vault 밖 프로젝트 세션은 모름. ~/.claude/CLAUDE.md에 핵심 framework 박으면 모든 세션이 인지.

### 세션 시작 시 한 번 로드

스킬 인덱스는 **세션 시작 시점**에 잠긴다. 세션 도중에 `~/.claude/skills/` 폴더에 새 SKILL.md를 떨궈도 그 세션엔 반영 X — **새 세션부터** 적용. 점검 시 항상 새 터미널.

## 본 vault의 운영 선택

- **5인 사이클 5스킬 + karpathy-guidelines = 모두 user-level**. 사장님은 여러 폴더·프로젝트를 옮겨가며 Claude Code를 띄우니까 글로벌이 자연 선택.
- project-level은 본 vault 범위 밖에서 다룸 — 특정 저장소(naver-biding 같은 운영 PC 코드)에 그 프로젝트 한정 스킬이 필요할 경우 그 저장소 안에 `.claude/skills/`로 격리.
- 새 PC 셋업 시 user-level 설치만으로 충분하지 project-level까지 손댈 일 X (특수 케이스 빼고).

## 폴더 layout

```
~/.claude/
├── skills/                          ← user-level 스킬 (어디서 띄워도 작동)
│   ├── brainstorming/
│   │   └── SKILL.md                 ← description:으로 auto-trigger
│   ├── writing-plans/
│   ├── verification-before-completion/
│   ├── requesting-code-review/
│   ├── writing-skills/
│   └── karpathy-guidelines/
├── CLAUDE.md (옵션)                  ← 모든 세션 무조건 로드 (description 매칭 X)
├── plugins/                         ← 플러그인 묶음 (cherry-pick 권장이라 본 vault 사용 X)
└── settings.json                    ← Claude Code 전역 설정
```

## 새 PC 셋업 시 점검

[[Claude-Skill]] §설치 방법 절차로 cherry-pick → `ls ~/.claude/skills/`에 6개 폴더 다 보이면 끝. 작동 확인은 **새 터미널**에서 `claude` 띄우고 `/skills` 또는 임의 발화로 테스트.

추가로 5인 사이클·4원칙 메타 프레임을 vault 밖 세션도 알게 하려면 **§유저 CLAUDE.md (canonical 사본)** 절차도 따라 한 번 더 설치.

## 유저 CLAUDE.md (canonical 사본)

아래 내용을 그대로 `~/.claude/CLAUDE.md` 파일로 저장하면 모든 Claude Code 세션이 (vault 밖이든 안이든) 시작 시 무조건 로드 → "5인 역할분담 + karpathy 4원칙" 메타 프레임 인지.

**경고**: `~/.claude/CLAUDE.md`는 vault 밖이라 git sync 대상 X — 각 PC마다 본 페이지에서 canonical 사본 복사해서 설치.

### Canonical 내용 (복붙용)

```markdown
# 사용자 글로벌 가이드 (모든 세션 자동 로드)

## 프로그램 만들 때 — 5인 역할분담 사이클 (베이커리 비유)

코드 작성·자동화 만들 때 다섯 직원이 한 사이클로 돈다. 각각 `obra/superpowers` 스킬에 1:1 매핑. (출처: CCFM-AX-TEAM 강동이 교안 PART 3-2)

| # | 직원 (PDF 비유) | 역할 본질 | 매핑 스킬 (`~/.claude/skills/`) |
|---|---|---|---|
| ① | **bob** 메뉴 기획자 | 오늘 뭐 만들지 큰 그림·구조 | `brainstorming` |
| ② | **dd** 작업반장 | step-01·02·03 단계 분배 | `writing-plans` |
| ③ | **harness** 위생·안전 매니저 | 이번 작업 한정 룰 강제 = 위생 게이트 | `verification-before-completion` |
| ④ | **eval** 시식 평가자 | 독립 채점 (90/70점) | `requesting-code-review` |
| ⑤ | **learnings engine** 일지 막내 | 교훈 자동 누적 → 다음 사이클 자동 참고 | `writing-skills` |

**한 사이클**: ① bob → ② dd → ③ harness → ④ eval → ⑤ learnings engine → 다음 사이클 bob에 자동 반영.

## 베이스라인 규범 — karpathy-guidelines (4원칙)

5인 사이클이 도는 동안 늘 깔린 가게 매뉴얼 역할. 모든 코딩 작업에 적용.

1. **Think Before Coding** — 가정 명시 / 여러 해석 제시 / 헷갈리면 멈춤
2. **Simplicity First** — 요청 외 기능 X / 200줄→50줄 가능하면 다시 써
3. **Surgical Changes** — 인접 코드·주석·포맷 손대지 마 / 모든 변경이 요청 한 줄로 추적돼야
4. **Goal-Driven Execution** — 명령형 → 검증 가능한 목표로 변환 / `step → verify` 포맷

## 베이커리 4축 (전체 그림)

| 축 | 정체 | 역할 |
|---|---|---|
| 🏪 운영 매뉴얼 | CLAUDE.md 파일 | 가게 전체에 늘 깔린 룰북 (= 이 파일) |
| 👥 직원 5명 | skills | 빵 하나를 만드는 전문 직원 (위 표) |
| 🚪 위생 게이트 | hook | 규칙 어기는 순간 자동 차단 |
| 📚 비법 노트 | WIKI | 우리만의 지식 저장소 |

## 깊이 있는 컨텍스트

5인 사이클·4축의 상세·출처는 LLM-WIKI vault 참고: `<vault 경로>/프로그램/wiki/concepts/Claude-Skill.md`·`클로드-베이커리-비유.md`·`karpathy-guidelines.md`·`스킬-스코프.md`. vault 경로는 각 PC의 git pull 위치 기준.
```

### 설치 절차

**PowerShell (Windows)**:
```powershell
# 본 페이지의 위 codeblock을 복사한 뒤:
$content = @"
<여기에 위 markdown 통째로 붙여넣기>
"@
$content | Out-File -Encoding utf8 "$env:USERPROFILE\.claude\CLAUDE.md"
```

**Bash (macOS·Linux)**:
```bash
# 위 codeblock을 ~/.claude/CLAUDE.md로 저장
cat > ~/.claude/CLAUDE.md << 'EOF'
<여기에 위 markdown 통째로 붙여넣기>
EOF
```

또는 단순히 본 페이지를 Obsidian으로 열고 codeblock 영역을 복사 → `~/.claude/CLAUDE.md`로 저장.

### 작동 확인

새 터미널 열고 임의 폴더(vault 밖 OK)에서 `claude` 띄운 뒤:
> "5인 역할분담 알아?"

→ 5인(bob·dd·harness·eval·learnings engine) 답변 나와야 정상.

## 다른 엔티티와의 관계

- [[Claude-Skill]] — 스킬 본체. 본 페이지는 그 스킬들이 "어디 살고 언제 깨어나는지" 메커니즘.
- [[superpowers]] · [[karpathy-guidelines]] — 본 vault에서 user-level 스코프로 cherry-pick 설치하는 두 출처.
- [[클로드-베이커리-비유]] — 본 페이지의 "스킬 vs ~/.claude/CLAUDE.md" 구분이 비유의 "직원 vs 운영 매뉴얼" 구분과 1:1.

## 내 생각 / 미해결 질문

- **~/.claude/CLAUDE.md 도입 여부**: 사장님 환경엔 아직 없음 (2026-05-29 실측). karpathy-guidelines가 코딩 발화에 잘 매칭돼서 스킬만으로 충분할 수도 — 한 달 운영 후 "이 4원칙이 발동 안 한 순간"이 있었는지 회고해서 격상 결정.
- **project-level 사용 케이스**: 본 vault에선 안 쓰지만, naver-biding 같은 외부 운영 코드 저장소에선 그 프로젝트 한정 스킬(특정 API 호출 패턴 등)이 정착할 가능성. 그때 그 저장소 CLAUDE.md에서 정의.
- **세션 시작 시 잠금**의 부작용: cherry-pick으로 새 스킬 추가한 직후엔 항상 새 터미널 필요 — 잊고 같은 세션에서 호출 시도해서 "왜 안 되지?" 헷갈리는 트랩.
