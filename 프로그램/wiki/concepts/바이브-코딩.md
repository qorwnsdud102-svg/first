# 바이브 코딩

## 한 줄 정의

개발 언어로 코드를 직접 짜는 게 아니라, **자연어(한국어)로 대화하듯 코딩하는 행위**. 비개발자가 자동화 도구를 만드는 새 길.

## 핵심 주장 / 속성

- **BEFORE → AFTER** — 전통적 코딩(개발자가 일일이 개발 언어로 작성) → 바이브 코딩("이 기능 어떻게 구현해", "~만들어줘"로 자연어 지시).
- **핵심 도구 = 클로드 코드 (Claude Code)** — 자연어로 코드를 작성하는 행위의 1순위 도구. [[CCFM-AX-TEAM]] 교안은 클로드 코드를 바이브 코딩의 디폴트로 전제.
- **레벨이 존재한다** — 입문(웹 챗봇), 중급(CLI·스킬·하네스·MECE), 고급(자동화 일주일 내 $200 토큰 소진 수준). [[마케팅/근육돌이]] "AI-에이전트-빌딩 중급 10가지" 글 참고.
- **CLI가 분기점** — CLI 기반 클로드 코드 사용 = GUI 대비 작업량 100배·정확도 차이. 검은 창에서 파일 직접 제어 + 입출력 제한 없음 + 내 PC 도구 전체 활용.
- **방법론이 갈린다** — 단순 "AI에 시키기" 수준에서 멈추면 결과물이 매번 들쭉날쭉. MECE 설계 + SPEC.md + MD 우선 수정 같은 [[클로드-베이커리-비유|4축 운영]]을 갖춰야 자산이 됨.

## 실전 경고 — "딸깍 속에 낙원은 없다" (엠타트업 22기, 작형 코치)

10년차 이커머스 코치(작형)가 바이브 코딩으로 자동화 도구를 다수 만들어본 결론 (cross-domain — [[마케팅/엠타트업]] 22기 4주차):

- **바이브 코딩 도구는 "내 느낌대로" 만든 개인화 도구라 남이 안 쓴다** — "나는 불편했다고 생각했는데 남은 사실 불편하지 않았다." 자작 도구(카페 외부 자동작성기·새벽 키워드 순위 체커)를 공유해도 아무도 안 씀.
- **"딸깍 속에 낙원은 없다"** — AI 자동화만으로는 월 50~100만원 수준이 한계, 그 이상은 무리. **AI는 (아직) 도구일 뿐.** 단, 흐름을 놓치지 않게 조금씩 연습은 하라 — 도구는 클로드 코드 권장 ("만들어줘 엔터, 고쳐줘 엔터").

→ 시사점: 도구는 **자기 워크플로 효율화**용으로 만들고 (남에게 팔/줄 생각 말고), 판매 대상은 도구가 아니라 도구가 만들어내는 성과. 사장님의 파이프라인 스킬 패키지도 같은 결 — 본인 전용 자산화가 1차 목적.

**야사 — 수강생 실증 (22기 노하우 모음)** (⚠️ 수강생 주장, 재현성 미검증 — 마케팅 도메인 정사/야사 관례 준용):
- 32번 "**바이브 코딩 절대 금지 — 기획 먼저**": 결과물도 결국 R — 명확한 기획 없이 시작하면 방향 표류·구조 꼬임·재작성. 핵심 질문 = "어떤 업무 흐름을, 어떤 기준·단위로 쪼개 만들 것인가". 카페 자동화 사례: 키워드 추적(구글시트 대시보드) / 글쓰기(**3개 파일을 함께 읽혀 작성** — 키워드 기획서+제품 기획서+플랫폼 글쓰기 규칙서, 플랫폼 규칙만 교체하면 멀티플랫폼) / 저장·배포 분리. "가장 중요한 건 툴이 아니라 사고력 — 어디까지 사람이 판단하고 어디부터 시스템이 처리할지." → 사장님의 SKILL.md(계획)+references 분리 구조와 정확히 같은 결.
- 성공 사례도 있음: 골포커싱 SaaS(선행지표 역산 → 매출 2배) · 네이버 키워드 조회 확장프로그램(SA API+GPT) — **본인 워크플로 문제를 명확히 정의한 경우**에 성공.
