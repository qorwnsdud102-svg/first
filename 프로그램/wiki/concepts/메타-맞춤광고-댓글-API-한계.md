# 메타 맞춤 광고 댓글 API 한계

## 한 줄 정의

메타 광고를 **노출 위치별 소재 맞춤**(피드·스토리·릴스마다 다른 영상, `asset_feed_spec.optimization_type=PLACEMENT`)으로 만들면, 사람들이 실제로 반응하는 게시물이 조회 API가 알려주는 게시물 목록에 없다 — **게시물을 주기적으로 조회해서 댓글을 관리하는 방식은 단일 소재 광고에서만 작동한다.** 맞춤 광고 댓글은 새 댓글 알림(웹훅)으로 실제 게시물 ID를 받아야 할 가능성이 높다.

## 증상 — 인사이트엔 있는데 조회 API는 0

- 맞춤 광고는 광고 인사이트에 반응·댓글이 잡히는데, 조회 API로 읽으면 **0 · 0**이다. 같은 계정의 단일 영상 광고(대조군)는 인사이트와 게시물 반응이 맞게 읽힌다.
- API가 주는 광고 게시물(`creative.effective_object_story_id`)은 사람이 화면에서 연 게시물과 **문구부터 다를 수 있다** — 다른 게시물이다.
- **0이 나오는 경로 전부**: `effective_object_story_id` 게시물 · 페이지 `ads_posts`의 같은 시각 형제 게시물 · 소재 영상 객체 `/{video_id}/comments` · `/{post}/dynamic_posts` · 페이지 feed/posts/published_posts · IG `effective_instagram_media_id`.
- 권한·앱 상태는 원인이 아니다: 필요한 권한을 다 가진 시스템 사용자 토큰, 앱 라이브 게시 **전후 결과 동일**.

## 해결 — 형태별 게시물을 찾는 법 (웹훅 없이)

"조회 API로 안 보인다"는 **어느 게시물을 조회해야 하는지 몰랐다**는 뜻이었다. 실제 게시물 ID를 찾는 자리가 따로 있었다.

- **FB:** 댓글은 페이지 소유 **비공개 릴스 영상**(대표가 복사한 링크 `facebook.com/reel/{영상}/?comment_id=…`)에 달린다. 이 영상 ID는 소재·페이지 목록 어디에도 없고, 광고 `/{ad_id}/previews`(`MOBILE_FEED_STANDARD`, `FACEBOOK_REELS_MOBILE`)가 주는 iframe HTML 안 **`"videoMediaData":{"videoID":<숫자>`(따옴표 없는 숫자)** 한 자리에 있다. HTML의 15~17자리 숫자 수십 개 중 나머지는 앱 번호·국가 전화 코드·카테고리 번호다. 그 영상은 `from.id=페이지`, `post_id` 있음, `/{영상}/comments`로 댓글·`can_hide`·`permalink_url`이 읽힌다. 미리보기가 가끔 500 오류를 내니 재시도한다.
- **IG:** 형태별 미디어는 광고계정 `/adcreatives`의 `effective_instagram_media_id`에 있다. 소재 목록에 **문구**(`body`·`object_story_spec.video_data.message`·`asset_feed_spec.bodies`)가 오고 IG 캡션과 일치한다 → 켜진 광고 소재와 **문구가 같고 게시 시각 ±15분**인 미디어가 형태별 게시물. 미디어 수천 개 정보를 다 받지 않고 같은 문구 미디어의 시각만 받는다.
- **숫자를 하나씩 "이거 영상이야?"로 조회하는 방식은 앱 전체 호출 한도를 태운다** → [[메타-API-호출-한도-주머니]].
- 메타는 이 앱에 **FB 사용자 댓글의 작성자(`from`)를 주지 않았다** — 본인 댓글 거르기 같은 작성자 기준 로직은 작성자 없음을 전제로 짠다(되돌릴 수 있는 숨김은 하고 삭제만 막기).

## 규칙

1. **"권한 오류 없음 + 빈 배열"을 "댓글 없음"으로 읽지 않는다.** 먼저 같은 객체의 **다른 원천 집계**(광고 인사이트 `actions.comment`·`post_reaction`, 게시물 인사이트 클릭)와 대조한다. [[모름-vs-0-표시-규약]]의 API 판본 — 조회 결과 0은 "없음"이 아니라 "여기서는 안 보임"일 수 있다.
2. **대조군을 하나 둔다.** 같은 계정의 단일 소재 광고가 맞게 읽히면 권한·앱 모드가 아니라 **객체 구조**가 원인이다. 이 한 번의 대조로 "개발 모드" 가설을 기각했다.
3. **광고 댓글 도구를 설계하기 전에 광고 제작 방식부터 센다.** `asset_feed_spec` 유무·`optimization_type`을 계정 전체에서 집계하면 조회 방식이 커버하는 비율이 바로 나온다(이 계정은 4%).
4. **화면(비즈니스 스위트·광고관리자 미리보기)은 보이고 API는 안 보이면**, 화면이 쓰는 게시물 ID를 받아 그 ID로 직접 조회해 본다 — "게시물 ID만 알면 읽히는가"가 웹훅으로 풀리는 문제인지, 고급 액세스(앱 검수)가 필요한 문제인지 가른다.

## 업계 사례 (3등급 — 업체 도움말)

- BrandBastion: 유연 형식 광고는 과거 댓글 크롤링 불가, 접근 권한 부여 뒤 새 댓글만 추적. IG 어드밴티지+ 크리에이티브·다이내믹 광고는 "어느 업체도" 크롤링 불가.
- Agorapulse: 다이내믹·어드밴티지+ 광고 댓글은 새 댓글이 달려야 동기화.

## 공식 문서 조건 (웹훅 쪽)

- IG `comments` 웹훅: 앱 라이브 + **고급 액세스(앱 검수)** + 비즈니스 인증 + 공개 계정.
- FB 페이지 웹훅: 페이지 구독에 `pages_manage_metadata`. 검수 필요 여부는 문서에 명시 없음(미실측).

## 반응 조회도 막힌다 — 광고 전용 피드 게시물

이 페이지는 **게시물을 못 찾는** 문제를 다루는데, 찾은 뒤에도 한 겹이 더 있다.
**광고 전용(`is_published=false`) FB 피드 게시물은 좋아요·댓글 수를 못 읽는다 — 오류가 아니라 0 이 돌아온다.**

```
GET /{page_id}_{post_id}?fields=likes.summary(true),comments.summary(true)
  → {"likes":{"summary":{"total_count":0}}, "comments":{"summary":{"total_count":0}}}
  실제(브라우저)  좋아요·댓글 수백·수십
```

`reactions`·`comments.filter(stream)`·`shares` 로 바꿔도 전부 0 이다. **릴스(`/reel/`)는 같은 방법으로 제대로 읽힌다.**
릴스도 `is_published=false` 인데 읽히므로, **비공개라서 못 읽는 것이 아니다.**

원인으로 보이는 것: `/me/accounts` 가 주는 페이지 id 와 그 게시물이 실제로 사는 페이지 id 가 **다르다**
(브라우저 주소의 페이지 번호 ≠ 토큰이 주는 페이지 번호). 토큰 쪽 id로 만든 합성 id 는 **에러 없이 빈 껍데기**를 돌려주고, 브라우저 쪽 id로는 그 객체를 열 수 없다(권한 없음).

`post_impressions` 계열도 v25 에서 사라졌다(`(#100) The value must be a valid insights metric`).
남아 있는 것은 `post_video_views`·`post_clicks` 인데, **광고 노출을 제대로 안 잡는다** — 릴스 오브젝트 자기 조회가 그 소재의 `facebook_reels` 광고 노출의 10분의 1 수준이었다.

### 규칙

- **FB 피드 게시물의 0 은 "반응 없음" 이 아니라 "못 읽음" 이다.** 도구가 그렇게 표시해야 한다([[모름-vs-0-표시-규약]]).
- **게시물 단위 인사이트로 노출을 판단하지 않는다.** 노출은 광고 insights(구좌 breakdown)로 본다 — [[광고-구좌별-노출-쏠림]].
- 반응을 꼭 세야 하면 **사람이 브라우저로 연다.** 지금 API 로 가는 길은 없다.

## 메타가 스스로 숨기는 광고 댓글 (`is_hidden`)

메타는 **페이지 설정을 켜지 않아도** 광고 댓글의 상당수를 스스로 숨긴다. API로 읽으면 `is_hidden=true`로 오지만 **작성자 본인과 그 친구에게는 보인다** — 그래서 대표 눈에는 멀쩡히 보이고 프로그램만 "이미 숨겨짐"으로 건너뛴다. 또 하나의 「API가 보여 주는 것 ≠ 사람이 보는 것」이다.

- **숨겨지는 쪽은 거의 부정 댓글**(욕설·「사기」 단정), 짧은 무의미 댓글(「ai」 「광고네」)도 걸린다. **보이는 쪽은 거의 문의·중립**이다.
- 페이지의 「특정 단어 숨기기」·「비속어 숨기기」가 다 꺼져 있어도 일어난다 — 사람이 건 필터가 아니다.

### 프로그램 설계에 주는 함의

1. **부정 댓글 자동 숨김의 추가 가치는 생각보다 작다.** 메타는 **욕설·명백한 사기 단정은 잡고, 욕 없는 비꼬기는 놓친다.** 우리 몫은 그 틈과 IG, 그리고 정책이 바뀔 때의 보험이다.
2. **진짜 값어치는 구매 문의 쪽에 있다.** 메타가 남겨 둔 댓글의 절반 이상이 구매 문의·효과 질문·관심이다. 메타는 이걸 대신 해 주지 않는다.
3. **자동 숨김에 걸린 구매 문의는 놓친다.** 짧은 문의가 걸리면 우리가 건너뛰어 메시지를 못 보낸다. 표본에 숨김된 구매 문의가 없는 동안은 **건너뛴다**(판단·기록·구매 문의 모두 안 함, 숨김이 풀리면 그때 — 대표 결정).
4. **건너뛴 것도 화면에 보여야 한다.** 숨겨진 댓글은 기록으로 남지 않아 화면이 조용하다 → 댓글이 달렸는데 아무 변화가 없으면 사람은 프로그램이 죽은 줄 안다. 현황에 "지난 확인 … **이미 숨겨져 있어 건너뜀 2건**"처럼 **건너뛴 사유와 건수**를 한 줄로 낸다([[모름-vs-0-표시-규약]] — 0건과 "안 본 것"을 구분).
5. **숨김이 풀려도 댓글 수는 그대로다.** "댓글 수가 바뀐 게시물만 읽기" 최적화를 쓰면 숨김 해제를 못 알아챈다 — 정기 전체 재읽기에 의존하게 된다. 즉시 반영이 필요하면 강제 재읽기 수단이 있어야 한다.

### 확인·조작 방법 (사람 손)

- 무엇이 숨겨졌나: 비즈니스 스위트 → 받은 메시지함 → **Facebook 댓글** → 게시물 → 「이 페이지에서 숨김」([숨기기 취소]로 풀 수 있다).
- 페이지 필터 확인: 페이스북에서 **페이지 프로필로 전환** → 설정 → 검색 "단어" → 「페이지에서 특정 단어를 포함하는 댓글 숨기기」·「비속어가 포함된…」. (개인 프로필 설정과 화면이 똑같아 헷갈린다 — 반드시 페이지로 전환한 상태여야 한다.)
- 인스타는 별도다: 인스타 앱 → 설정 → **숨겨진 단어**("공격적일 수 있는 댓글 숨기기"가 기본 켜짐인 경우가 많다).

## 쓰기 쪽 — 숨김·비공개 답장·토큰

- **IG 댓글도 API로 숨길 수 있다** — `POST /{ig-comment-id}?hide=true`. 비즈니스 스위트에는 IG 숨김 메뉴가 없어 사람 손으로는 삭제밖에 없던 것.
- **비공개 답장(댓글 작성자에게 DM)은 FB·IG 모두 `POST /{page}/messages`** 로 나간다. IG를 `/{ig-user-id}/messages`로 보내면 `(#3)`.
- **댓글당 1통, 한 통에 글 또는 첨부 하나** — "글 + 사진"은 불가능하니 IG는 카드 한 통(사진 + 짧은 글 + 버튼)으로 묶는다. IG DM은 글 속 주소가 눌리지 않는다.
- **일반 고객 대상 비공개 답장은 표준 권한으로 된다** — 앱 검수가 필요 없었다.
- **토큰:** 권한 추가 = 새 토큰 발급(기존 토큰은 유효). Graph API 탐색기 토큰은 몇 시간짜리라 운영에 쓰지 않는다. 「토큰 취소」는 같은 앱 토큰을 한꺼번에 끊을 수 있어 누르지 않는다.
