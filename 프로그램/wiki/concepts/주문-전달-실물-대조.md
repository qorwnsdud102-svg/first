# 주문-전달-실물-대조

## 한 줄 정의

바깥 업체(SMM 패널)에 돈 주고 시킨 작업은 **그 업체가 "완료"라고 말한 것으로 끝내지 않고, 결과가 실제로 남는 곳(여기서는 메타)에서 직접 확인**한다. 접수·진행·완료는 업체의 주장이고, 게시물에 달린 댓글 수는 사실이다.

## 왜 (2026-09-20 실측)

[[snskit-booster]] 첫 실주문 날, 패널이 말하는 진행 상황이 **양방향으로** 틀렸다.

| 패널이 말한 것 | 실제 |
|---|---|
| FB 여성 좋아요 `남음 4`(1개 처리) | 게시물 좋아요 **+4** 반영 |
| FB 여성 랜덤 댓글 "2개 처리" | 게시물 댓글 **0건** |
| FB 커스텀 댓글 `Pending`·시작 카운터 0 | 4~5시간째 정말로 0건 |
| 2026-08-03 주문 `Completed`·시작 카운터 공백 | 댓글은 실제로 달려 있었다 |

`start_count`·`remains` 는 작업자가 보고하는 값이라 지연·누락·과대보고가 섞인다. 이 숫자만 보고 "됐다/안 됐다"를 판정하면 **돈이 나간 뒤에도 몇 시간 동안 모른다**.

## 어떻게 (메타 쪽 확인 경로)

광고 계정 토큰만으로는 게시물 댓글을 못 읽는다 — **페이지 토큰**이 필요하다.

1. `GET /me/accounts?fields=id,name,access_token` → 그 페이지의 `access_token`
2. FB: `GET /{page_id}_{post_id}?fields=comments.limit(n){id,message,created_time,is_hidden},likes.summary(true)`
   - `is_hidden` 으로 숨긴 댓글까지 구분된다(메타는 숨긴 댓글도 목록에 준다).
3. IG: `/me/accounts?fields=instagram_business_account` → `GET /{ig_user_id}/media?fields=id,shortcode,permalink,comments_count,like_count`

## 규칙

1. **주문 전 기준값을 찍는다.** 그 게시물의 댓글 수·좋아요 수를 먼저 읽어 두지 않으면 "원래 있던 것"과 "내가 산 것"을 못 가른다(실제로 좋아요 6개를 보고 몇 개가 들어온 건지 몰라 다시 주문해 확인했다).
2. **문구로 대조한다.** 커스텀 댓글은 내가 보낸 줄이 그 게시물에 있는지 문자로 맞춰 본다 — 수량보다 정확하고, 어느 패널이 단 것인지도 갈린다.
3. **시간 기준을 상품별로 둔다.** IG 는 분 단위, FB 댓글은 시간 단위다. 한 기준(예: 48시간)으로 묶으면 정작 고장 난 것을 늦게 안다.
4. **안 달렸으면 사람에게 올린다.** 접수 후 n시간이 지나도 0건이면 '지금 볼 것'에 띄운다. 조용히 기다리면 그 사이 다음 회차가 또 나간다.
5. **읽기 호출도 예산이다.** 같은 페이지 토큰을 쓰는 다른 프로그램([[메타-댓글-자동관리]])이 있으면 중복 조회를 피한다 — [[메타-API-호출-한도-주머니]].

## ⚠️ 대조하는 쪽도 틀린다 (2026-09-22 — 이 페이지를 한 번 뒤집은 날)

위 규칙을 지키다가 **정반대로 틀렸다.** 메타 실측을 근거로 "FB 피드 게시물은 배달이 안 된다" 고 보고했는데,
대표가 브라우저로 열어 보니 **좋아요 225 · 댓글 34** 가 멀쩡히 있었다.

원인: `/me/accounts` 가 주는 페이지 id(`586083164589708`)와 그 게시물이 실제로 사는 페이지
id(`61574054860277`)가 다르다. `{586…}_{게시물id}` 로 물으면 **오류 없이 좋아요 0 · 댓글 0** 이 돌아온다.
릴스(`/reel/`)는 같은 방법으로 제대로 읽힌다 — 그래서 **"릴스만 배달된다" 는 착시**가 생겼다.

| | API 가 주는 값 | 실제(브라우저) |
|---|---|---|
| FB 피드 게시물(광고 전용) | 좋아요 0 · 댓글 0 | 좋아요 225 · 댓글 34 |
| FB 릴스 | 좋아요 222 · 댓글 33 | 같음 |
| IG 미디어 | like_count 정상 | 같음 |

**그래서 규칙이 하나 늘었다:**

6. **대조군으로 눈금을 먼저 맞춘다.** 실측 도구를 믿기 전에, **실제로 달린 게 확실한 대상**을 같은 방법으로 읽어
   숫자가 맞는지 본다. 한 종류(릴스)에서 통한 판독법이 다른 종류(피드)에서도 통한다는 보장은 없다.
7. **0 과 "못 읽음" 을 구분해 표시한다.** 도구가 0 을 줄 때 "안 달렸다" 가 아니라 **"내 도구가 못 읽는다"** 를
   먼저 의심한다([[모름-vs-0-표시-규약]] 과 같은 정신 — 이번엔 그 규약을 지킬 쪽이 우리였다).
   `배달확인.py` 는 FB 피드 줄에 `0 은 '미전달' 이 아니라 '모름'. 브라우저로 확인` 을 찍는다.

> 돈·중단 같은 결정을 **실측 하나로** 내리기 전에 사람에게 화면으로 교차 확인을 청한다.
> 이 건은 "15,300원이 버린 돈" 이라는 보고와 "snskit 에 환불 문의" 라는 제안까지 갔다가 되돌렸다.

## 수량은 늘 조금 모자란다 (2026-09-22 실측)

기준값을 박고 잰 밤샘 드립에서 **IG 커스텀 댓글은 세 게시물 전부 주문 11개 → 실측 +10** 이었다.
셋 다 똑같이 1개 모자라다. 원인은 모른다(중복 문구가 걸렸는지, 계정 하나가 실패했는지).

→ **판정 기준을 "주문 수량과 정확히 같은가" 로 잡으면 매번 실패로 읽힌다.** `수량 −1` 근처면 정상으로 닫고,
**0 증가**인 건만 따로 추적한다. 좋아요는 정확히 맞았다(10개 주문 → +10, 세 건 모두).

완료 표시까지 걸린 시간은 상품마다 다르다 — IG 커스텀 댓글은 어제 16건이 **60분~5시간**에 흩어졌다.
"몇 분 안에 안 붙었다" 로 고장 판정하면 안 된다.
