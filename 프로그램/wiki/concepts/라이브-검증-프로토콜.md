# 라이브 검증 프로토콜

## 한 줄 정의

"됐다"고 말하기 전에 **무엇을 어떻게 확인해야 진짜 확인인가**에 대한 규범. 대표가 가장 강하게·반복해서 요구한 축 — "내부 신호만 보고 완료 보고했다가 라이브에서 깨진 걸 대표가 발견"하는 사고를 막기 위해 성문화됐다. 카페24가 아닌 **어떤 프로그램·자동화에도 적용되는 검증 원칙**.

## 핵심 주장 / 속성

- **내부 신호 ≠ 사용자 경험.** 함수 호출·이벤트 가로채기·DOM 수치가 통과했다는 건 "코드가 그 줄을 지나갔다"는 뜻이지 "화면이 맞다"는 뜻이 아니다. 특히 클릭의 **부수효과**(네이티브 목록에 행이 남아 화면 오염)는 클릭 후 원래 화면을 다시 봐야만 보인다.
  - **규칙(플로우 변경 시)**: (옵션상태)×(버튼) 매트릭스로 **① 클릭 전 화면 ② 클릭 후 목적지(탭 URL 실확인) ③ 복귀 후 원래 화면 오염** 3장 세트 스크린샷. 결제 버튼은 최종 목적지 URL(예: `orders.pay.naver.com`)까지 실제 이동해 확인. 옵션 A→B→C 3연속 전환 시 표시·금액이 매번 교체되는지(잔존·누적=실패).

- **실배포물을 검증하라, 조건 충족된 샌드박스 말고.** 버그가 터지는 조건을 피해가는 테스트(예: root가 이미 존재하는 테스트요소로 스켈레톤 로직 확인)는 **통과할 수밖에 없는 테스트**다. 카페24는 대표가 붙여넣으니 Claude가 직접 배포 못 함 → 샌드박스/JS주입으로 대체하는 순간 실제조건(실행순서·타이밍·DOM순서·캐시·로그인상태)이 탈락한다.
  - **규칙**: 실제 조건 그대로 재현(예: root가 처음엔 비었다가 나중에 채워지는 순서)하거나, 못 하면 **"로직만 확인 — 실배포 미검증"** 이라고 정직히 표기. "실증 완료"는 실제 배포물을 실제 순서로 돌렸을 때만.
  - **적대적 검증**: 붙이기 전 "내 테스트 vs 진짜 페이지 차이(스크립트 위치·실행타이밍·캐시·로그인)"를 먼저 나열하고 그 차이로 깨지는지 시도.

- **"코드 존재 ≠ 화면 표시".** "기능 있습니다" 보고를 코드 grep으로 하지 말 것 → 라이브 3중 확인: ① `getBoundingClientRect` 기하 0×0 검출 ② `offsetParent`로 조상 display:none 색출 ③ 그 요소가 찍힌 스크린샷. 외부 조건 의존(앱주입·관리자토글·승인·배치반영) 기능은 **"코드 준비됨, ○○ 반영 전 미표시(정상)"** 로 의존 조건을 명시.

- **완성 선언 전 "전수 시각감사"를 스스로 실행** (대표가 QA를 안 해도 되게, 능동 신고). 내가 바꾼 것만 좁게 보지 말고:
  1. **전 구간 라이브 스윕**: 모바일(430px)로 위→아래 전 섹션 스크린샷. 겹침·깨진이미지·정렬어긋남·잘림·빈자리·값이상·갑툭튀·레이아웃점프 능동 점검.
  2. **레퍼런스 대조**: 같은 화면을 잘 되던 몰과 비교 — 빠진 것/값 달라진 것(드리프트). 리브랜딩값(색·전화·상품번호)만 다르면 정상.
  3. **과거 이슈 재발 체크리스트**를 매번 훑기.
  4. **애매해도 "이거 이상한데 의도인가요?"로 대표가 지적하기 전에 목록으로 먼저** 올린다.

- **"완료" 언어 규칙 + 독립 검증자 분리.** 전 항목 증거 있을 때만 "완료", 아니면 "검증된 것/미검증"을 분리 의무. 결제·심사급은 **구현 맥락 없는 별도 에이전트**가 요구사항 원문+라이브만 받고 흠집내기(구현자의 맹점이 검증 설계에 복제되는 것 차단).

## claude-in-chrome 라이브 검증 (도구 한계와 우회)

- **라이브 확인은 Claude가 직접** navigate → DOM/computed style(조상체인·display·크기) → console/network → 스크린샷. 붙여넣기 전에도 `javascript_tool`로 수정안을 라이브 DOM에 주입해 먼저 실증. **한계**: 공개 페이지만 — 로그인/관리자·실결제·비번 입력은 안 함(그 부분과 붙여넣기는 대표가).
- **짧은 애니(2초 GIF 등)는 스크린샷으로 못 잡는다**(캡처 지연 ~2초). → `getBoundingClientRect` 기하측정·`new Image().onload` natWidth·전역변수 감시(`window.__x`)로 증명. `javascript_tool`의 async 반환은 `{}`로 비어오니 **결과를 전역에 저장하고 다음 호출에서 읽기**. 육안 필요하면 애니 지속시간을 임시로 6초로.
- **`resize_window` ≠ 기기 뷰포트**(창 크기라 세로가 실기기보다 짧음). 정확한 폰뷰(아이폰14ProMax 430×932 dpr3)는 **F12 기기 에뮬레이션**으로 — 대표가 직접 켜줘야 함.
- **CSS 변수는 정의 요소가 아니라 "적용받는 자손"에서 읽어라.** `:root`에 `--x:30`, `body.scrolled`에 `--x:50`이면 `getComputedStyle(html)`은 항상 30 → 실제 값은 자손 요소에서 읽어야 보임.
- **기하 측정 전 트랜지션을 꺼라.** class 토글 직후 `getBoundingClientRect()`는 애니 중간값 → `*{transition:none!important}` 주입 후 reflow(`offsetHeight`) → 측정.
- **클래스/플래그 게이팅은 "켜지는 쪽" 값이 실존하는지부터 실증**(반대쪽만 보고 추정 금지). 예: `ez-view-type-pc`가 스크립트에 아예 없어 PC에서 영원히 미발동한 사고 → [[카페24-스킨구조-함정]].
