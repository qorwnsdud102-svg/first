# 메타 API 호출 한도 주머니

## 한 줄 정의

메타 Graph API 호출 한도는 하나가 아니라 **주머니 여러 개**다 — 광고(`ads_management`)·페이지(`pages`)·인스타(`instagram`) 같은 **비즈니스 사용 사례 주머니**와, 어느 비즈니스에도 속하지 않는 호출이 쓰는 **앱 전체 주머니**(X-App-Usage). 한도에 걸린 원인은 "호출이 많아서"가 아니라 **"엉뚱한 주머니를 쓰는 호출이 많아서"**일 수 있다. 같은 앱(토큰)을 쓰는 프로그램끼리 앱 전체 주머니를 나눠 쓴다.

## 실측 (2026-09-17, [[메타-댓글-자동관리]] 실데이터 시험)

| 호출 | 잡힌 주머니 | 비고 |
|---|---|---|
| 켜진 광고·광고 미리보기·소재 목록 | `ads_management` | 개발 등급(`ads_api_access_tier: development_access`) — 소재 목록 49쪽 한 번에 56% |
| 페이지 토큰 발급·FB 영상 댓글·숨김 | `pages` | 1% |
| IG 미디어·댓글 | `instagram` | 1% |
| **소유 확인이 안 되는 숫자 노드 조회**(앱 번호·국가 전화 코드 등)·`?ids=` | **앱 전체** | 이것이 107%까지 차서 `(#4) Application request limit reached` |
| 배치 요청(`POST /`) 자체 | 앱 전체에 안 잡힘 | 앱 107% 상태에서도 성공. 안의 항목은 각자 자기 주머니에 1건씩 |

- 앱 전체 주머니가 넘친 상태에서도 광고·페이지·인스타 주머니 호출은 모두 성공했다 → **한도 보호를 주머니별로 해야** 한 주머니 때문에 전체가 멈추지 않는다.
- `?ids=a,b,c` 여러 객체 한 번 조회는 `The ids query parameter is deprecated in v26.0+`(v25.0 요청에도)로 막혔다.
- 사용량은 응답 머리글로 온다: `x-business-use-case-usage`(주머니별 `call_count`·`total_time`·`total_cputime`·`estimated_time_to_regain_access` 분), `x-app-usage`, `x-page-usage`, `x-ad-account-usage`. 배치 응답은 항목마다 `headers`에 들어 있다.

## 규칙

1. **한도에 걸리면 먼저 어느 주머니가 찼는지 본다.** 응답 머리글을 호출 종류별로 기록하면 호출 0건으로 원인이 나온다. "호출을 줄이자"보다 "앱 전체 주머니를 쓰는 호출을 없애자"가 정답인 경우가 있다.
2. **소유가 확인되지 않는 ID를 하나씩 조회하지 않는다.** HTML·응답에서 숫자를 긁어 "이게 뭔지" 묻는 방식은 앱 전체 주머니를 태운다. 그 숫자가 들어 있는 **자리(키 이름)**를 찾아 거기서만 읽는다(예: 미리보기의 `"videoID":`).
3. **보호는 주머니별로, 쉼 시각은 저장소에.** 사용량 80%에서 그 주머니 호출만 멈추고, 한도 오류가 나면 `estimated_time_to_regain_access`(없으면 1시간)만큼 그 주머니만 쉰다. 쉼 끝 시각은 DB에 남겨 재시작해도 이어진다. 한도에서 계속 호출하면 회복이 늦어진다(문서).
4. **주기 확인은 "개수 먼저, 바뀐 것만 읽기".** 게시물마다 댓글 전체를 읽는 대신 배치 1~2건으로 댓글 수만 받고(`comments.filter(stream).summary(true).limit(0)`, IG `comments_count`) 수가 바뀐 게시물만 읽는다. 배치 안 항목은 한도에 1건씩 잡히지만 **HTTP는 1건**이고 페이지·인스타 주머니는 넉넉하다.
5. **목록은 한 번 저장하고 이어 읽는다.** 최신부터 오는 목록(소재 목록 등)은 처음 한 번 끝까지 저장한 뒤, 모두 아는 쪽에서 멈춘다. 읽기가 한 쪽이라도 저장된 뒤 끊겼으면 다음에는 끝까지 — 아는 첫 쪽에서 멈춰 뒤쪽을 영영 놓치는 함정.
6. **점검 도구도 캐시를 쓴다.** 운영 중에 실행하는 점검 스크립트가 메모리 저장소로 매번 전체를 다시 받으면 운영 프로그램의 한도를 같이 태운다 → 운영 DB 읽기 전용 사본을 캐시로.
