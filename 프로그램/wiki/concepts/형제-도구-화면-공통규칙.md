# 형제 도구 화면 공통 규칙

## 한 줄 정의

한 사람이 번갈아 쓰는 도구들은 **색·글꼴이 같은 것만으로는 부족하다.** 같은 자리에 같은 역할, 같은 아이콘에 같은 글자, 같은 버튼이 같은 쪽에 있어야 "적응"이 필요 없어진다.

## 어디서 나왔나

부스터(8004)와 댓글 관리(8005)는 같은 색·글꼴·레일 구조로 만들었는데도 대표가 "통일감이 없다"고 했다. 실제로 어긋난 것은 미세한 세 가지였다.

1. **레일 순서** — 한쪽은 설정이 맨 아래, 다른 쪽은 중간. 같은 체크 아이콘이 한쪽은 3번째, 다른 쪽은 2번째.
2. **같은 아이콘, 다른 글자** — 영수증 아이콘이 한쪽은 "주문이력", 다른 쪽은 "처리 내역".
3. **버튼 자리·색** — 파란 주 버튼이 한쪽은 오른쪽 끝, 다른 쪽은 왼쪽. 같은 뜻의 버튼 글자도 달랐다("지금 스캔" vs "지금 확인").

## 규칙

### 좌측 레일 — 자리가 뜻이다

| 자리 | 아이콘 | 역할 |
|---|---|---|
| 로고 | `ph-fill` · 같은 크기·색 | 프로그램 표시 — **모양만 다르게** |
| 1 | `ph-layout` | 첫 화면(현황) |
| 2 | `ph-stack` | 작업 대상 목록 |
| 3 | `ph-check-circle` | **사람 손이 필요한 대기열**(빨강 배지) |
| 4 | `ph-shopping-cart` | 돈이 되는 기회(파랑 배지) |
| 5 | `ph-receipt` | 결과 이력 |
| 6 | `ph-list-bullets` | 활동 기록(로그) |
| 맨 아래 | `ph-gear` | 설정 — **항상 맨 아래** |

- 없는 자리는 건너뛰고 **남은 것의 상대 순서는 바꾸지 않는다.**
- **같은 아이콘이면 글자도 같게.** 레일은 10px 작은 글씨라 짧은 공통어를 쓰고(예: "내역"), 무엇의 내역인지는 **화면 안 제목 줄**에서 말한다("주문이력" / "처리 내역").

### 상단바

왼쪽부터 정체성 칩 → 상태 배지 → 구분선 → 숫자 칩 → 자동 토글 → 마지막 시각.
오른쪽은 **맨 오른쪽이 파란 주 동작 1개**, 그 왼쪽이 흰 보조 동작들. 파란 버튼 자리가 화면마다 다르면 손이 헷갈린다.

### 상단바 아래 세 줄 (순서 고정)

1. **진행 줄**(연한 파랑) — 서버가 지금 하는 일. 도는 동안만, 단계 글 + 경과 시간.
2. **빨강 배너** — 멈춤·오류.
3. **노랑 배너** — 확인은 필요하지만 돌고는 있음.

빨강과 노랑을 한 칸에 섞지 않는다 — 급한 줄이 주의 줄 사이에 묻힌다.

### 목록 화면 뼈대

제목 줄(h-12) → 필터 줄(세그먼트 + 검색) → 보조 필터 줄(기간·플랫폼) → 표(머리 고정 h-10) → 쪽 나눔 줄. 휴대폰은 표 자리에 카드.

## 이름 충돌이 생기면 — 프로그램 안이 먼저다

프로그램 **사이** 통일보다 프로그램 **안**의 명확함이 우선이다. 한 화면에서 같은 단어가 두 곳을 가리키면, 옆 프로그램과 글자가 같아진 이득보다 손해가 크다.

- 실제 사례: 부스터 레일을 "승인 → 확인 필요"로 바꾸려 하니 대시보드의 "확인 필요 센터"(13가지 모음)와 겹쳤다 → **센터를 「지금 볼 것」으로 옮기고 레일을 「확인 필요」로.**
- 반대 사례도 있었다: 레일 "기록"을 "활동"으로 바꾸자는 제안은, 그 화면 안 탭 이름이 이미 [이벤트]·[활동]이라 **기각**됐다.
- **글자가 같아도 무게가 다를 수 있다.** 부스터의 "확인 필요"는 누르지 않으면 주문이 안 나가는 대기열(일이 멈춤)이고, 댓글 관리의 "확인 필요"는 봐야 할 목록(일은 돌고 있음)이다. 규칙 문서에 이 차이를 적어 둔다.

## 두 세션이 같이 고칠 때

한 저장소를 각각 다른 세션이 들고 있으면 **남의 저장소를 건드리지 않는다.** 대신 ① 규칙을 글로 정해 한쪽 저장소에 두고 ② 상대에게는 "무엇을 왜 바꿔 달라"는 요청문과 **반론 선택지**를 같이 보낸다. 실제로 반론이 타당해 결론이 바뀐 적이 있다(위 "활동" 기각).
