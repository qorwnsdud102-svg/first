# 다경로 데이터 모순 디버깅

## 한 줄 정의

같은 데이터를 두 코드 경로가 다르게 읽으면 거의 항상 모순 화면 또는 동작 버그가 나온다 — 디버깅 진입점.

## 핵심 주장 / 속성

- **표면 메시지 ↔ 내부 상태 모순** — 사유 텍스트가 "이탈" 인데 상태 머신이 "유지" 면 동작 버그. 사례 (2026-05-21): decider 가 락인 미노출 시 `at_sweet_spot=True` 유지하면서 사유는 "안착가 이탈, +10원 재탐색" 출력 → cycle 이 6h skip 으로 더 미노출 방치.
- **카드 vs 상세 모순** — 같은 사이클 카드 "미노출 mobile_rank=None" / 상세 "1위 안착 감액". 거의 항상 *같은 데이터를 두 경로가 다르게 읽음*. 사례 (2026-05-20): `owned_hints` 가 `decide()` 에는 `OWNED_HINTS ∪ ag.owned_companies` 합쳐 전달, `fetch_exposure_sync()` 에는 default `OWNED_HINTS` 만 전달.
- **단방향 sync 갭** — DB status 가 우리 UI 로만 갱신되고 외부 (네이버 광고주센터) 변경 reflect X 면 다음 cycle 오판. 사례: 사용자가 광고주센터에서 직접 OFF → cycle 미노출 판단 → +bid → stuck. fix: cycle 직전 `fetch_status` GET + 10분 주기 `bulk_sync`.
- **단서 모음** — 동일 사이클 두 곳 값 다름 / 사유 텍스트와 동작 일치 X / 사용자가 외부에서 변경 가능한 자원 → 의심.
- **검색 패턴** — 같은 인자가 두 함수 시그니처에 다 있는지 / 한 쪽만 수정한 PR 의 빈 구멍 / 코멘트와 동작 동기화 / 같은 enum 값을 다르게 해석하는 두 곳.
