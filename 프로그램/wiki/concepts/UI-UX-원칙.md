# UI/UX 원칙 — 화면 만들 때 체크리스트

## 한 줄 정의

화면을 처음 보는 사람이 **설명 없이 "뭘 하는 화면이고, 다음에 뭘 누르면 되는지"** 바로 아는 것. 예쁜지는 그다음 문제다.

## §0 언제 읽나 — Claude는 화면 작업 전에 이 페이지부터

프로그램·사이트·대시보드·카페24 스킨·관리 화면을 **새로 만들거나 고칠 때.** 순서:

1. **§1 만들기 전 5문**에 답을 적는다 (답이 안 써지면 코드 쓰지 말고 대표에게 묻는다).
2. [[디자인-기준-먼저]]로 색·글자·간격·컴포넌트 기준을 먼저 고정한다 (프로젝트에 이미 있으면 그걸 따른다).
3. 만든다 — §2 원칙 위반이 없게.
4. **§3 점검표**를 돌리고, [[라이브-검증-프로토콜]]로 실제 화면에서 확인한다.

> 왜 이 페이지가 생겼나 (2026-10-06): 대표 진단 — "프로그램·사이트 만들 때 UI/UX를 사용자 친화적으로, 직관적으로 못 만든다." 기능은 돌아가는데 처음 보는 사람이 헤맨다. 원인은 감각이 아니라 **기준 없이 화면마다 즉흥으로 그린 것** — 그래서 기준(원칙·토큰·점검표)을 위키에 고정한다.

## §1 만들기 전 5문

| # | 질문 | 막히면 |
|---|---|---|
| 1 | 이 화면을 쓰는 사람은 **어떤 상황에서 무엇을 끝내려고** 오나? (기능 이름 말고) | [[문제-정의-먼저]] |
| 2 | 이 화면의 **주인공은 하나** — 가장 크게 보일 숫자·버튼 하나는? | §2-1 |
| 3 | 사용자가 **다음에 할 행동**은? 그 버튼이 첫눈에 보이나? | §2-1·§2-6 |
| 4 | 실패·빈 값·로딩·권한 없음일 때 화면은 무엇을 보여주나? | §2-4, [[모름-vs-0-표시-규약]] |
| 5 | 되돌릴 수 없는 행동(삭제·발송·결제)은 어디에 있나? | §2-5 |

## §2 원칙 15개

등급: 1 = 공식·학술 ([[Nielsen_10-사용성-휴리스틱|Nielsen]]·[[토스_앱인토스-UI-UX-가이드|토스]]·[[Figma_UI-디자인-원칙-7가지|Figma]]) 또는 우리 실전 / 2 = 실측 실무자 ([[김경환_디자인-독학하기-브런치북|김경환]]) / 3 = 미검증 ([[와니_UI-UX-캐러셀-7편|와니]]·[[LinkedIn_5-UIUX-원칙|LinkedIn]]). 여러 출처가 겹치면 가장 높은 등급.

### 1. 한 화면 = 할 일 하나, 주인공 하나 (1등급)
- 화면마다 주된 행동은 1개. 길면 단계를 쪼갠다 (김경환: 1문1화면 설문 완료율 70~80%).
- 강조는 **하나만** — 강조는 개수가 아니라 주변과의 차이에서 나온다(폰 레스토프). 나머지는 크기·색을 낮춰 **희생**시킨다.
- 그래픽·아이콘도 핵심 1개, 나머지는 보조 (토스).
- 근거: Nielsen #8, 토스 그래픽, Figma 계층, 김경환 94·108·110, 와니 B.

### 2. 선택지는 줄이고, 나머지는 접는다 (1등급)
- 대표 선택지만 먼저, 나머지는 "더보기"·다음 단계로 (힉의 법칙, 점진적 공개).
- 17개짜리 드롭다운 금지 — 묶거나 검색으로. 주관식보다 객관식.
- 단, 접을 때는 **지금 몇 단계 중 어디인지**는 보여준다 (Figma) — 예외는 §5.
- 근거: Figma #2, Nielsen #6·#8, 김경환 74·93, 와니 B.

### 3. 익숙한 자리에 익숙한 모양 (1등급)
- 사용자는 다른 서비스에서 익힌 방식을 기대한다(제이콥의 법칙): 검색은 위, 설정은 맨 아래, 뒤로는 직전 화면으로.
- **우리 도구끼리도** 같은 자리 = 같은 역할 → [[형제-도구-화면-공통규칙]].
- "새로워 보이려고" 레이아웃을 바꾸지 않는다. 크게 바꾸면 옛 자리에 안내를 남긴다.
- 근거: Nielsen #4, Figma #3, 김경환 94·98·110.

### 4. 누르면 반드시 반응, 상태는 항상 보이게 (1등급)
- 클릭 → 즉시 변화(눌림·로딩·완료 토스트). 걸리는 일은 진행 표시.
- 완료 알림은 **토스트**, '확인' 눌러야 닫히는 팝업은 꼭 읽어야 할 때만.
- 현재 상태를 화면에 적는다 — 정렬 기준, 필터 적용 여부, 마지막 갱신 시각, 자동화 켜짐/꺼짐.
- 모르는 값은 0이 아니라 "–" → [[모름-vs-0-표시-규약]].
- 근거: Nielsen #1, 김경환 101·110, LinkedIn #4.

### 5. 실수는 막고, 되돌릴 길을 남긴다 (1등급)
- **막기**: 조건이 안 차면 버튼 비활성 + **왜 안 되는지 옆에 표시** (비활성만 하고 이유를 숨기면 더 헤맨다). 입력은 실시간 검증(빨강/초록). 불가능한 선택지는 아예 안 보이게.
- **알리기**: 누르기 전에 결과를 말한다 — "삭제하면 포함된 파일도 함께 삭제돼요".
- **버튼에 행동명**: [확인] 대신 [프로젝트 삭제]. 위험한 행동은 빨강, 다른 버튼과 떨어뜨린다.
- **되돌리기**: 휴지통·"되돌리기" 스낵바·작성 중 이탈 경고.
- 돈·발송이 걸린 행동은 여기에 더해 서버 쪽 방어 → [[유료-주문-이중결제-방지-패턴]].
- 근거: Nielsen #3·#5·#9, Figma 대비, 김경환 98·110, 와니 C.

### 6. 버튼·문구는 결과를 말한다 (1등급)
- 버튼 = 누르면 일어날 일. "필터 적용" → "하의 4,388개 보기", "Let's go" → "저장".
- 내부 용어·약어 금지 — 사용자가 쓰는 말로. 못 바꾸면 옆에 설명.
- 문구 하나가 행동을 바꾼다 (김경환: '이유'→'고민'으로 바꾸자 이탈 급감). 위치보다 메시지가 먼저다 (108: 불명확한 팝업에선 구석의 X가 61.6%).
- 세부 규칙 → [[UX-라이팅]].

### 7. 간격으로 관계를 보여준다 (1등급)
- 관련 항목은 붙이고, 다른 그룹은 띄운다(근접성). 선 대신 여백으로 묶는다.
- 그리드에 정렬 — 줄이 맞으면 예측이 쉬워진다.
- 간격 숫자는 정해진 단계만 → [[디자인-기준-먼저]].
- 근거: Figma #6·#7, 와니 B.

### 8. 기준을 먼저 정하고, 그 안에서 고른다 (1등급 + 3등급 실무법)
- 색은 값이 아니라 역할(Primary/Surface/Danger…), 글자는 역할(Title/Body/Caption…), 간격·둥글기·그림자는 단계로.
- 반복 UI는 공통 컴포넌트 + 상태(Default/Hover/Disabled/Loading/Error)를 먼저 정의.
- **Claude에게 새로 "만들게" 하지 말고 정해진 것 중 "고르게"** 한다 — 결과를 좌우하는 건 긴 프롬프트가 아니라 미리 정한 기준.
- 상세·예시 → [[디자인-기준-먼저]].

### 9. 중요한 버튼은 크게, 닿기 쉬운 곳에 (1등급)
- 피츠의 법칙: 자주·중요하게 누르는 것일수록 크고 가깝게.
- 터치 영역 최소 **44~48px**, 버튼 사이 8px 이상. 아이콘이 24px여도 누르는 영역은 44px+.
- 데스크톱 관리 화면: 주 버튼은 작업 흐름이 끝나는 자리(폼 하단·상단바 오른쪽 끝) 한 곳에 고정.
- 근거: 와니 B, 김경환 74·94·98(버튼 위→아래 이동 클릭률 7.46%→22.8%).

### 10. 장식은 빼고, 핵심 정보는 첫 화면에 (1등급)
- 의미 없는 그라데이션·파티클·아이콘 나열 금지. 그래픽이 버튼·숫자보다 튀면 안 된다.
- 큰 그림이 핵심 정보를 아래로 밀어내 스크롤을 만들지 않게.
- 오해 부르는 아이콘 금지 — 오류도 아닌데 느낌표, 기다릴 일 없는데 로딩 점.
- 설명 못 하는 칩·약어는 뺀다 → [[대시보드-추세-카드-원칙]].
- 근거: Nielsen #8, 토스 그래픽, 김경환 94·110.

### 11. 사용자를 붙잡는 장치는 쓰지 않는다 — 다크패턴 금지 (1등급)
- 들어오자마자 화면 가리는 팝업, 뒤로가기 가로채기, 닫기 없는 화면, 예고 없는 전면 광고 금지 (토스: 출시 불가 사유).
- 감정 호소·애원 문구 금지 — 손실은 **사실로** 알린다("지금 그만두면 연 2% 이자를 받을 수 없어요"는 OK).
- 로그아웃·탈퇴·해지를 숨기지 않는다.
- 근거: 토스 다크패턴 정책, Nielsen #3.

### 12. 이미 아는 건 다시 묻지 않는다 (2등급)
- 받은 정보는 자동으로 채운다. 기억시키지 말고 보여준다(최근 값·기본값).
- 입력에 맞는 키보드·입력칸 자동 포커스·필수만 받기·건너뛰기 허용.
- 근거: Nielsen #6, 김경환 74·93·101.

### 13. 기능보다 문제 먼저 (3등급, 방법론)
- "찜 기능이 필요하다"는 해결책이다. 문제는 "본 상품을 다시 찾기 어렵다".
- 문제 정의문 → HMW → JTBD로 흐름을 **원하는 결과까지** 그린다 → [[문제-정의-먼저]].

### 14. 바꿨으면 숫자로 확인 (2등급)
- 개선마다 KPI 1~2개를 미리 정하고 배포 뒤 본다. A/B는 한 번에 한 곳만 바꾼다.
- 흐름을 잘게 쪼개 가장 약한 구간부터 고친다(마이크로 퍼널).
- 근거: 김경환 94·108·110·121. 우리 쪽 함정 → [[측정-지표-함정]].

### 15. 누구나 읽을 수 있게 (1등급, Figma만)
- 글자·배경 대비 충분히, 색만으로 의미 전달 금지(빨강+아이콘/글자 병기), 키보드로도 조작 가능.
- 라이트·다크 둘 다 쓰면 중간 명도 색.

## §3 만든 뒤 점검표 (Claude가 보고 전에 직접 체크)

- [ ] 처음 보는 사람이 **5초 안에** 이 화면의 목적과 다음 행동을 말할 수 있나?
- [ ] 가장 큰 요소가 정말 가장 중요한 것인가? 강조가 2개 이상이면 하나로.
- [ ] 모든 버튼 글자가 "누르면 일어날 일"인가? (확인·OK·Submit 남아 있으면 고친다)
- [ ] 내부 용어·영어 약어·코드 값이 화면에 노출되지 않았나?
- [ ] 클릭마다 반응이 있나? 로딩·완료·실패 상태를 **각각** 눈으로 봤나?
- [ ] 빈 목록·0건·값 없음·에러일 때 화면을 봤나? 빈 상태에 다음 행동 안내가 있나?
- [ ] 비활성 버튼 옆에 이유가 보이나?
- [ ] 삭제·발송·결제 버튼: 결과 예고 + 행동명 라벨 + 분리 배치 + 되돌리기(또는 2차 확인)?
- [ ] 간격·글자 크기·색이 [[디자인-기준-먼저]]의 단계 밖 즉흥 값이 없나?
- [ ] 같은 뜻 같은 단어, 같은 역할 같은 자리 ([[형제-도구-화면-공통규칙]])?
- [ ] 모바일 폭(375px)에서 가로 스크롤·잘린 버튼·겹친 글자 없나?
- [ ] [[라이브-검증-프로토콜]] — 클릭 전/후/복귀 후 스크린샷으로 확인했나?

## §4 모바일·쇼핑몰 화면 전용 (카페24·상세페이지·모바일 웹)

- 주 행동 버튼은 **엄지 영역** — 화면 중앙보다 약간 아래~하단, 전체 폭. 구매·장바구니 CTA는 하단 고정 (김경환 98·121·122).
- 모바일 웹은 브라우저마다 "키보드 위 고정 버튼"이 깨진다 → 입력칸 바로 아래 고정 위치로 (김경환 101).
- 입력 종류에 맞는 키보드(`inputmode`·`type=email/tel`)와 첫 칸 자동 포커스.
- 진입 즉시 팝업·이탈 방지 팝업 금지 (§2-11) — 쇼핑몰 쿠폰 팝업도 해당.
- 상세페이지: 핵심 가치 문구를 목록→상세까지 같은 말로 반복, 형식적 정보표는 아래로 (김경환 122, 3등급 — 실데이터 없는 제안). 판매 화면 기획 자체는 마케팅 → [[마케팅/상페 구조]].
- 가로 키오스크·전체화면 함정 → [[모바일-가로-키오스크-웹앱-함정]].

## §5 출처끼리 부딪히는 곳 (판단 기준)

| 쟁점 | A | B | 우리 기준 |
|---|---|---|---|
| 진행 표시 | 보여줘라 (Figma, 김경환 74) | 문항 11개면 질려서 이탈 — 뺐다 (김경환 93) | 기본은 보여준다. 단계가 많으면 "n/N" 대신 "거의 다 왔어요"·남은 시간처럼 부담 낮게 |
| CTA 강조 수단 | 색 대비 (와니, Figma) | 주색이 페이지에 많으면 대비색은 잡음 — 모션으로 (김경환 93) | 화면에 강조가 하나뿐이면 색. 이미 색이 많으면 크기·위치·여백으로 |
| 위치 vs 문구 | 엄지 영역·크게 (피츠) | 문구가 불명확하면 위치 소용없음 (김경환 108) | **문구 먼저**, 그다음 위치 |
| 확인 팝업 | 삭제·이탈엔 확인창 (와니, 김경환 98) | '확인' 팝업 지양, 토스트·인라인 (김경환 101·110) | 데이터 손실·돈 = 확인창 / 일반 완료·오류 = 토스트·인라인 |
| 대화상자 왼쪽 버튼 | [취소] (와니, 김경환) | [닫기]로 통일 — 취소는 작업 취소로 오해 (토스) | **[닫기]** (작업 자체를 취소하는 버튼일 때만 "작업 취소") |
| 로그아웃·X 숨기기 | 찾기 어렵게 (김경환 101·108) | 다크패턴 (토스, Nielsen #3) | **숨기지 않는다** |
| 터치 크기 | 44×30px (김경환 74·94) | 48×48 (김경환 98) | 44px 이상, 여유 있으면 48 |
| 간격 단계 | 4/8/12/16/24/32 (와니) | 4/8/16/24/36/48/80 (김경환 110) | 프로젝트당 하나로 고정만 하면 됨 — 기본값은 [[디자인-기준-먼저]] |

## §6 우리 실전 규칙 (1등급 — 대표 지적·실가동에서 나온 것)

- [[형제-도구-화면-공통규칙]] — 같이 쓰는 도구는 레일 순서·아이콘 글자·주 버튼 자리까지 같게
- [[대시보드-추세-카드-원칙]] — 큰 숫자 + 비교 두 줄 + 7일 추세, 설명 못 하는 칩 금지, 경고는 "무엇이/왜/어디서 고치나"
- [[모름-vs-0-표시-규약]] — 모르는 값은 "–", 근사 라벨 어휘 고정
- [[모바일-가로-키오스크-웹앱-함정]] — 전체화면·회전·세이프존
- [[라이브-검증-프로토콜]] — 내부 신호는 화면이 아니다, 3장 세트 스크린샷, 툴팁에만 있는 라벨은 없는 라벨
- [[네이버-광고-자동화-운영-노트]] §2 — 시간은 "H시간 M분", 한 화면 같은 이름 통일, 변하지 않는 값은 숨김

외부 원칙과 우리 실전 규칙이 부딪히면 **우리 실전 규칙 우선** (대표가 실제로 써보고 지적한 것이므로).
