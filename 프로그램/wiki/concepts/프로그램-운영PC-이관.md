# 프로그램-운영PC-이관

## 한 줄 정의

**돌고 있는 프로그램을 다른 PC 로 옮기는 일은 코드를 옮기는 일이 아니라, 저장소에 안 들어가는 것들을 옮기는 일이다.**

## git pull 로 가는 것과 안 가는 것

| | 어떻게 옮기나 | 빠뜨리면 |
|---|---|---|
| 코드·문서·도구 | `git pull` | — |
| **DB** | **백업 API 사본**(`conn.backup`), 파일 복사 아님 | 기록 전부 소실 → 전체 재스캔, 진행 중인 것 소실 |
| `.env` | 본보기 파일(비밀값은 비워서) | 경로가 엉뚱한 곳을 가리킨다 |
| **키 파일** | **사람이 직접** | — |
| 로그 | 안 옮긴다(빈 폴더만) | — |
| `.venv` | 그 PC 에서 새로 만든다 | 파이썬·의존성 충돌 |

**꾸러미로 만든다** — 위 중 "저장소에 안 가는 것"만 한 폴더에 모으고, 받는 쪽이 읽을 안내문(`읽어주세요.md`)과
인수인계(`운영PC-클로드에게.md`)를 같이 넣는다. 폴더만 넘겨도 따라올 수 있어야 한다.

## 옮길 때의 규칙 다섯

1. **DB 는 "안전 위치"로 만들어 넘긴다.** 자동 처리·자동 발송을 **끈 상태**로 저장한다.
   받는 쪽이 키를 넣는 순간 뭔가 나가면 안 된다. (그냥 복사하면 보내던 설정 그대로 켜진 채 뜬다.)
2. **DB 는 백업 API 로 뜬다.** WAL 모드에서 `.sqlite` 만 복사하면 최근 변경이 통째로 빠진다 —
   2026-09-22 실측으로 본체 2.4MB 에 WAL 4.4MB(우리), 206KB 미반영(형제 도구). 파일 복사를 해야 한다면
   **프로그램을 끄고 `.sqlite`·`-wal`·`-shm` 세 개 전부.**
3. **켜는 순서를 정한다.** 서로 창구를 부르는 프로그램이 있으면 **불리는 쪽이 먼저** 뜬다
   (댓글 관리 8005 → 부스터 8004: 부스터 첫 회차가 우리 창구를 부른다).
4. **겹치는 구간을 만들지 않는다.** 옛 PC 와 새 PC 가 같은 계정·토큰을 쓰면 호출 한도를 나눠 쓰고,
   자동이 양쪽에서 돌면 같은 일을 두 번 한다. 순서: **새 PC 올려 확인 → 옛 PC 자동 끄기 → 새 PC 자동 켜기.**
   ("옛 PC 자동 끄기"가 "새 PC 자동 켜기"보다 **먼저**다.)
5. **되돌리기는 DB 를 가져오는 조건이 붙는다** → [[중복방지의-DB-경계]]. "폴더를 그대로 두면 언제든 되돌린다"는 절반만 맞다.

## 이관 전에 볼 함정

- **`skip-worktree` 파일은 저장소를 안 따라간다.** 개발 PC 에서 고쳐도 운영 PC 에는 안 간다 → 그 PC 에서 손으로 고친다.
  옮기기 전에 `git ls-files -v` 로 `S` 표시를 훑는다.
- **경로가 PC 마다 다르다**(폴더 이름까지). 기본값을 이름 하나에 매달지 말고 후보를 여러 개 두거나 `.env` 로 덮는다.
  **못 찾으면 조용히 넘어가지 말고 경보.** 박힌 경로는 **죽는 편이 낫다** — 이름이 같았으면 조용히 옛 PC 의 DB 를 읽고 "정상"이라 찍었을 것이다.
- **동기화 폴더 경고는 사실 확인부터.** 바탕화면이면 무조건 OneDrive 라고 보면 오탐 — 실제 `%OneDrive%` 밑인지로 판정한다.
  (동기화되는 자리면 SQLite 가 잠겨 기록이 멈춘다는 위험 자체는 진짜다.)
- **기동 구조가 바뀌어 있을 수 있다**(배치 파일 대신 설정 파일 + 감시 프로세스, 순서는 `order` 값). 점검 코드가 옛 구조만 알면 **멀쩡한 것을 ❌ 로 잡는다.**
- **점검 도구가 대상보다 늙는다.** 오래 ❌ 인 항목은 고치기 전에 **판정 기준이 아직 맞는지** 먼저 본다.
- **"붙어 오는 기능"을 본다** — 암호 게이트처럼 병합하면 포탈 전체에 로그인이 생기고 설정 파일이 없으면 아예 안 뜨는 것. 병합 전에 "이 브랜치에 뭐가 같이 들어 있나".
- **키 파일은 꾸러미 압축에서 뺀다.** 꾸러미가 동기화 폴더(OneDrive·Dropbox)에 놓이면 키까지 클라우드로 올라간다 — 키는 저장소 폴더에서 USB 로 바로 복사하고, **꾸러미 위치도 확인 대상**이다.
- **git 없이 옮기면 고친 코드도 손으로 간다**(바뀐 부분 전문 → 백업 → 반영 → 시험 수·실데이터 값 회신, [[여러-클로드-세션-협업]]). 자주 고칠 도구라면 처음부터 git 으로 옮긴다.
- **안전 위치를 기본값으로 만들 수 있다.** 자동 켬/끔을 따로 파일에 두고 **파일이 없으면 「끔」**이 기본이면, DB 사본만 옮겨도 새 PC 는 꺼진 채로 뜬다(규칙 1이 저절로 지켜진다).
- **토큰을 한쪽만 쓸 수 있으면 규칙 4의 순서가 바뀐다.** 쓰는 순간 바뀌는 refresh 토큰(카페24)은 두 PC 가 같이 못 쓴다 → **옛 PC 수집을 먼저 끄고** 최신 DB 를 뜬다. 멈춘 사이 데이터는 새 PC 첫 수집이 거슬러 채우게 만든다.
- **상대경로 화면은 끝 슬래시가 필요하다.** 화면이 `api/...` 상대경로면 `/meta`로 열 때 요청이 포탈 루트로 샌다 → 포탈이 `/meta` → `/meta/`로 돌려보내는지 확인한다.
- **「항상 200」 상태 주소는 감시에 「살아 있나」만 알려 준다.** 배지용으로 수집이 멈춰도 200을 주는 주소라면, 수집 고장은 화면 배너·확인 필요에서 본다.

## 자체 점검 도구를 하나 둔다

형제 프로그램과 **같은 자리·같은 이름**(`tools\이관준비.py`)으로 두면 사람이 두 프로그램을 같은 손버릇으로 쓴다.
읽기만 하고, 비밀값은 찍지 않는다. 우리 20여 항목의 뼈대:

- **안전 위치** — 자동 처리·자동 발송 꺼짐, 발송 상한·시간대, 처리 시작 시각, 확인 주기
- **저장소 자리** — DB·백업 폴더가 동기화 밖인가, 하루 안쪽 백업이 있나, WAL 크기(복사 경고용)
- **키·모델** — 키 파일 형식(값은 안 찍는다), AI 키·모델, 발송에 필요한 값(번호·안내 이미지·링크)
- **남은 일거리** — 보내기 대기 0, 확인 필요 0, 24시간 오류 0
- **코드 상태** — 커밋 안 된 변경 없음 + HEAD
- **형제와의 공존** — 포탈 기동 순서, 형제 폴더를 찾는가

## 옛 PC 를 내리는 순서

새 PC 가 하루 정상 운영을 하면 옛 PC 는 내린다. **프로세스만 내리고 나머지는 그대로 둔다.**

1. **조용한 때를 고른다** — 진행 중인 회차 없음 · 대기 중인 일 없음 · 자동은 이미 꺼져 있음.
2. **DB 를 한 벌 뜬다**(백업 API). 내리는 날짜를 이름에 박아 둔다 — 되돌릴 때 "어디까지가 옛 것인지" 기준이 된다.
3. **프로세스 중지.** 포트가 빈 것까지 확인한다.
4. **폴더·DB·`.env`·키·`.git` 을 그대로 둔다.** 지우지 않는다.

내리면 같은 계정·토큰을 쓰던 인스턴스가 줄어 **호출 한도를 새 PC 가 온전히 쓴다.**
자동만 꺼 두면 회차는 계속 돌아 한도를 나눠 쓴다 — "자동 꺼짐"과 "안 돈다"는 다른 말이다.

**되돌릴 때는 그냥 켜지 않는다** → [[중복방지의-DB-경계]]. 새 PC 가 이미 일을 했으면 그 DB 를 가져와야 한다.

## 내 생각 / 미해결 질문

- 꾸러미를 **사람이 손으로 만든다**는 게 약점이다. "저장소에 안 가는 것" 목록은 프로그램이 알고 있으니
  `tools\이관꾸러미.py` 처럼 한 번에 만드는 것이 맞다(형제 도구는 `DB내보내기.py` 로 절반 했다).
- 점검 20항목 중 셋이 **환경 판정**(동기화·기동 구조·폴더 이름)이었고, 셋 다 처음엔 틀렸다.
  환경을 글자로 추측하지 말고 **그 PC 에서 실제로 물어보는** 방식이 맞다.
