# 시트 칸 골라 읽기

## 한 줄 정의

개인정보(주민번호·계좌번호·연락처)가 같은 줄에 섞인 구글 시트 탭을 읽을 때, 탭을 통째로 받지 않고 **구글 시트 쿼리(gviz)로 구글이 고른 칸만 돌려주게** 한다 — 민감한 칸은 구글 밖으로 나오지도 않는다. 시트를 나누지 않아도 된다.

## 방법

```
GET https://docs.google.com/spreadsheets/d/<문서>/gviz/tq?tqx=out:json&gid=<탭>&headers=1&tq=<쿼리>
① tq = select * limit 0                         → 머리글 이름만(자료 줄 0개)
② 이름으로 칸 글자(A, E, I, J)를 찾는다          → 칸이 옮겨져도 엉뚱한 칸을 안 고른다
③ tq = select A, E, I, J where I contains 'DA'   → 필요한 칸·필요한 줄만(값은 contains로 넓게)
④ 돌아온 머리글에 주민·계좌·연락처·예금주·성함·은행이 끼어 있으면 버린다
```

- 시트 공유가 「링크가 있는 모든 사용자 보기」면 인증 없이 된다. 공유가 풀리면 구글은 200과 로그인 페이지(HTML)를 준다 → 콘텐츠 종류로 막는다.
- **CSV(`out:csv`)는 화면에 보이는 글자**라 날짜 서식이 「08. 11」(연도 없음)이면 연도를 잃는다 — `format A 'yyyy-MM-dd'` 절도 칸이 글자형이면 안 먹었다. **JSON(`out:json`)은 원래 값**(`Date(2026,7,11)`, 달은 0부터)을 준다. 글자 날짜는 연도가 없으면 올해, 미래면 작년으로.
- 예외 문구에 시트 주소(문서 ID)를 싣지 않는다 — 종류만.
- 한 겹 더: 사람이 운영 시트에 「AI 추출용」 탭을 만들어 `=FILTER(CHOOSECOLS('원래 탭'!A2:L, 1,2,3,…), 'A열'<>"")`로 민감 칸을 뺀 사본을 자동으로 채우게 하고, 프로그램은 그 탭을 위 방법으로 읽는다.

## 양식이 바뀔 때

사람이 쓰는 시트는 예고 없이 바뀐다(하루 두 번도). 안 깨지게 하는 규칙:

- **값은 「정확히 같음」이 아니라 「낱말이 들어 있음」으로 거른다.** 쿼리는 `contains 'DA'`로 넓게 받고, 프로그램이 쉼표·공백으로 나눠 「DA」 낱말이 따로 있는지 본다(「DAY」는 안 된다).
- **꼭 필요한 칸과 있으면 쓰는 칸을 나눈다.** 날짜·금액·구분은 없으면 오류, 제품·특이사항은 있으면 같이 고른다. 사람이 칸을 더하거나 빼도 멈추지 않는다. 돌아온 머리글이 고른 칸과 다르면 여전히 버린다.
- **번호로 고른 사본 탭은 원본에 칸이 끼어들면 머리글과 내용이 어긋난다.** `CHOOSECOLS(…, 11, 12)`처럼 번호로 가져오는 사본 탭은 원본 칸이 바뀌어도 옛 머리글을 그대로 달고 다른 내용을 보여 준다. 오류는 안 난다. **머리글 이름만 믿지 말고 값 모양도 한 번 본다**(특이사항 칸에 제품 이름만 → 이상).
- **0줄은 오류가 아니라 경고 + 이전 값 유지.** 저장된 값을 지우지 않으면 화면 숫자가 안 틀리고, 「확인 필요」에 이유가 뜬다([[수집-파이프라인-안전장치]]).
- 시트는 구글에 하나다. 개발 PC·운영 PC가 같은 탭을 읽으니 **양식 변경은 PC마다 할 일이 아니다.** 코드만 양쪽에 맞추면 된다.

## 기준 칸이 통째로 옮겨질 때

- **「개인정보를 뺀 사본 탭」도 원본 칸이 옮겨지면 개인정보가 새어 들어온다.** 머리글 이름 검사(주민·계좌·연락처…)는 머리글이 멀쩡하고 내용만 어긋나면 못 막는다. **필요 없는 칸은 처음부터 안 고르는 것**이 마지막 방어선이다 — 기준을 옮긴 뒤엔 옛 기준 칸을 고르지도, `where` 조건에도 쓰지 않는다.
- 시트를 사람에게 고치라고 하기 전에 **지금 시트 기준으로 프로그램 기준을 바꾸는** 쪽을 먼저 본다(대표 지시).
- **모르는 시트는 값을 안 보고 모양만 조사한다** — 개수·합계·형식 같은 집계만 받는다(gviz는 집계를 구글 쪽에서 계산해 숫자만 준다):
  1. `select * limit 0` — 머리글 이름과 칸 형식(string/number).
  2. 칸마다 `select count(X)` — 값이 있는 줄 수.
  3. 글자 칸마다 `select count(X) where X contains 'DA'` — 찾는 표시가 든 줄 수.
  4. 개인정보가 아닌 칸만 `group by`로 값을 묶어 합계가 경고 전과 같은지 대조.

## 사례

- 외주 제작비 탭의 구분 칸이 하루에 두 번 바뀌었다(「DA」 → 「DA, 히토」 → 「구분 DA」 + 「제품」 칸) — 위 「양식이 바뀔 때」 규칙이 여기서 굳었다(2026-09-24).
- 「구분이 DA인 줄이 없습니다」 경고 뒤 구분 칸 아래에 사람 이름·연락처 같은 값이 보였다. 집계로만 조사해 DA 표시가 제품 칸으로 옮겨진 것을 찾고 기준을 바꿨다. 경고 + 이전 값 유지로 사흘 동안 화면 숫자는 안 틀렸다(2026-09-27).
