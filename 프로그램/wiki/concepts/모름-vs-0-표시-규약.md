# 모름 vs 0 표시 규약

## 한 줄 정의

집계 결과에서 **"자료가 없다(모름)"와 "값이 0이다"를 끝까지 다른 값(None vs 0)으로 전파**하고, 근사·추정·부분 값에는 반드시 라벨을 붙인다. [[측정-지표-함정]] §침묵하는 결측이 입력 쪽 함정이라면 이건 출력 쪽 쌍둥이 — 모름을 0으로 찍으면 그럴듯한 숫자가 되어 아무도 검수하지 않는다.

## 규약 (SA 툴에서 리뷰에 6번 넘게 잡힌 뒤 성문화)

1. **COUNT로 존재부터 묻는다.** `SUM(x)`가 0이면 "0원"인지 "행이 없음"인지 모른다 → `COUNT(*) == 0`이면 None. (정산이 아직 안 들어온 기간의 순수익이 0원으로 보이던 사고)
2. **존재 여부는 금액이 아니라 건수로.** 원가 미상 주문이 취소돼 금액이 순액 0으로 상쇄돼도 `unknown_n`은 남는다.
3. **부분 데이터는 전체인 척 보이면 안 된다.** 정산 배치 커버리지(min~max basis) 밖 기간은 None; 원가를 아는 매출 비율이 50% 미만이면 순수익 숫자 대신 "일부 미상"; NT 파일이 덮지 않는 날의 광고비는 ROAS 분모에서 제외.
4. **3값 상태를 허용한다.** 보관료 `estimated`: None(미설정) / False(입력됨) / True(다른 달 값으로 추정) — "0원"과 "보관료 미설정"을 화면이 구분한다.
5. **불가능한 값은 모름으로 떨어뜨린다.** 마진율 > 1은 계산이 아니라 데이터가 깨진 것 → None.
6. **미상 항목은 모든 파생값에서 제외한다.** 원가를 모르는 줄의 정산·풀필먼트를 더하면 원가 0인 채 이익이 부푼다(손익분기 ROAS 20%대 착시).
7. **라벨 어휘를 고정한다**: "(배분)" 스토어 단위 값을 브랜드에 나눔 · "(추정)" 다른 기간 값으로 채움 · "근사값" 일수 비율로 나눔 · "일부 미상" · "보관료 미설정" · "근거 부족"(표본 미달) · 표시 비용 툴팁(VAT 포함 원값).
8. **빈 값과 0을 DB까지 구분한다.** 수기 입력 한쪽만 비우면 NULL 저장.

## 합계·라벨 — 규약이 깨지기 쉬운 자리

- **None은 합산에서 '빼기'가 아니다.** 모름인 브랜드를 건너뛰면서 **그 브랜드의 아는 비용(광고비·보관료)까지** 빠지면 총합이 부푼다 — 총합도 None(또는 "일부")으로 전파한다.
- **같은 화면에서 규약이 갈리지 않게 한 헬퍼로.** 합계 칸은 미상을 0으로, 기간표는 None으로 처리하면 한 화면에서 숫자가 어긋난다([[단일-진실-원천]]).
- **라벨은 숫자 옆에.** 툴팁·작은 범례·머리글 한 글자(†·※)에만 있으면 대표는 근사값을 확정값으로 읽는다. 라벨 플래그(`estimated` 등)는 API 응답까지 실어 보내야 화면이 붙일 수 있다 — **툴팁에만 있는 라벨은 없는 라벨이다.**

## 수집 원천이 여럿일 때

- **받은 적 없는 기간은 0이 아니라 모름.** 원천마다 처음 받아 둔 기간이 다르면(광고비 90일, 매출 30일) 비교 기간 이익이 거짓 큰 음수로 보인다. 첫 수집 범위 이전은 모름, 그날이 끝난 뒤 수집이 한 번 성공해야 안다.
- **더할 수 없는 값은 기간으로 다시 묻는다.** 도달·빈도는 날마다 더하면 같은 사람을 여러 번 센다 → 기간 선택 시 플랫폼에 기간으로 한 번 묻고, 못 받으면 「–」.
- **원천이 한 번도 안 읽혔으면 모름**: 시트를 한 번도 못 읽었으면 「–」(「없음」과 다르다). 매기지 못한 판매는 「마진표에 없는 판매 N건 빠짐」을 숫자 옆에.
- **일부 원천 빠짐**: 매출 원천 하나라도 그날 못 받았으면 합계 옆에 「일부 빠짐: 쿠팡」.
- **「0원인 날」과 「못 받은 날」은 수집 기록으로 가른다.** 금액만 보면 둘이 같다. 수집이 그날 ok/no_data를 남겼으면 「받았음(0이 맞음)」, 기록이 없으면 「광고비 자료 없음: 메타(9/16~9/25 없음)」처럼 **날짜 구간**으로 알린다.
- **가능성이 높아도 자동으로 정상 처리하지 않는다.** 빈 날이 「원래 없음」일 가능성이 커도 배지만 달고, 「정상(원래 없음)」은 사람이 누른다. 누른 것은 설정에 남고 확정 판정에 들어간다.
- **비어 있는 입력칸은 0이 아니다.** 빈칸 = 보류(계산에 안 넣음), 명시 기호(`x` 등) = 없음.

## 거르는 축이 못 나누는 숫자 (2026-10-06)

- 화면에 거르기(광고계정·캠페인 등)를 더할 때, **그 축으로 나눌 수 없는 숫자**가 있다 — 매출은 주문 단위라 「어느 광고계정 덕」으로 못 나눈다.
- 그 숫자를 비율로 나눠 가짜로 만들지 않는다. **거른 숫자(광고비)만 바꾸고, 나머지는 「제품 전체 기준」이라고 적고 흐리게** 둔다. 둘을 섞은 비율(ROAS)도 전체 기준 그대로. 매출과 짝인 그래프엔 안내 한 줄.
- 대표 선택(메타 대시보드 광고계정별 보기): 「메타 숫자만」.

## 사례

- SA 툴 검수: 「전체」 순수익이 모름 브랜드의 광고비·보관료를 빼 먹고 부풀었고, 9월 파레트 수로 8월까지 추정한 보관료가 「(추정)」 없이 나갔다(2026-09-15).
- 메타 대시보드: 매출을 30일만 받아 직전 기간 이익이 −429만 원으로 보였고, 쿠팡이 막힌 날 매출이 약 39% 빠진 채 확정처럼 보였다(2026-09-23).
- 전체 대시보드: 지출 탭 부가세 빈칸을 0으로 읽었으면 급여가 부가세 10%만큼 틀렸을 뻔했다(2026-09-25~27 무렵).
