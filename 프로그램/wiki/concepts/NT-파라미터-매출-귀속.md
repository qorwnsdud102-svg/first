# NT 파라미터 매출 귀속

## 한 줄 정의

네이버 전환추적은 **쇼핑검색만 구매를 잡는다**(파워링크·파워컨텐츠는 카페·블로그 글을 거쳐 스토어로 가므로 180일간 전환 0). 그 공백을 스마트스토어 **사용자정의채널(NT 파라미터: nt_source · nt_medium · nt_detail · nt_keyword)** 엑셀로 메워, 광고그룹 묶음(그룹) 단위의 "광고비 → 스토어 유입 → 구매·매출"을 판단 근거로 쓴다.

## 왜 엑셀인가

- 스마트스토어 통계(NT)는 **API가 없다**(네이버 공식 답변). 스마트스토어센터 → 통계 → 마케팅분석 → 사용자정의채널 엑셀을 **주 단위, 기간이 안 겹치게** 내려받아 `data/nt/`에 넣는다. 파일 안에 날짜 열이 없어 **파일명에서 기간을 읽는다**.
- 같은 기간이 (1)(2)로 나뉜 파일은 채널속성(PC/모바일/N+스토어앱)별 분할이라 행이 겹치지 않는다 → 합산. 진짜 중복이면 upsert가 덮어써 이중 계산은 구조적으로 불가(실측 2026-09-15: 4기간 12파일 키 겹침 0).

## 코드 사전과 매핑

- `파라미터` 시트 = 코드 사전. nt_source(IS=일상곡선, LEG=발받침대, MM=멜라맘, Bareuntop, Nunchok, MT=액막이명태, Guguguard — 구구컷은 시트에 빠져 있어 기본값으로 보강) / nt_medium(NPL=파워링크, NPC·N-Post=파워컨텐츠, 그 외 GSA=구글 검색, NVC=네이버 카페, NVB=블로그, NVV=영상 …) / nt_detail(HC=협착증, KB=허리디스크, HB=허브키워드, YDDS=디스크 운동, BYGB=병원, JYGB=지역 …).
- **파워컨텐츠 medium은 브랜드마다 NPC 또는 N-Post**라 유형만으로 못 정한다 → 같은 브랜드의 매핑된 그룹이 쓰는 medium을 따른다.
- 광고그룹 ↔ nt_detail 매핑은 시트(`N파컨정리` · `N파링+구글정리`)에서 (캠페인명, 광고그룹명)으로 148개 중 147개 일치. 우선순위 manual > sheet > default(브랜드×유형 묶음).
- 네이버는 동명 광고그룹에 `-1, -2`를 붙인다 → **정확 매칭 먼저, 접미사 제거는 폴백**(기본 정규화로 떼면 다른 그룹이 뭉친다). 병합셀 forward-fill은 **브랜드 블록 경계에서 리셋**.
- 시트에는 카페 계정 ID/PW 열이 있다 → 필요한 열만 이름으로 읽고, 행 내용은 로그·오류·화면 어디에도 남기지 않는다.

## 근사와 그 앞뒤 맞추기

- 주간 파일을 요청 창과 **겹치는 일수 비율로 나눠** 더한다(근사). 그러면 광고비도 **NT가 덮는 날만** 합산해야 ROAS가 맞다 — 커버리지 밖 날의 광고비를 매출 없는 채로 섞지 않는다.
- 그룹 근거 문턱: 유입 20 미만이면 "근거 부족"(그룹 ROAS 대신 브랜드 ROAS로 폴백). 검수 지적(추정): CVR 2%면 유입 150이라도 기대 주문 3건이라 건강한 그룹이 관측 ROAS < 150%로 나올 확률이 약 20% — ROAS 판단에는 20이 너무 낮다.

## 마지막 클릭이라는 한계 — [[마케팅/통합 로아스]]와 붙여 읽기

- NT 매출은 **광고 클릭 → 콘텐츠 → 스토어 링크 클릭 → 결제**만 잡는다. 나중에 검색해서 들어온 낙수는 안 잡힌다(과소). 반대로 브랜드 ROAS(스토어 전체 매출 ÷ 광고비)는 자연유입·재구매까지 다 넣는다(과대).
- 라이브 실측(2026-09-15, 7일): 파워링크 NT ROAS **66%**, 파워컨텐츠 148%, 브랜드 ROAS 169~238%. 두 숫자 사이가 낙수 + 자연유입이다. [[마케팅/통합 로아스]] "양방향 갭" 그대로.
- 판단 우선순위는 그룹(NT) → 브랜드 → 없음. 둘 다 보여주되 **어느 쪽으로 판단했는지**를 화면에 써야 한다.

## NT 파일이 바로 판단에 반영되지 않는다

파일을 넣으면 다음 수집 또는 서버 재시작 때 읽히지만 **판단(추천)은 다시 돌지 않는다.** 판단이 NT가 일부 날만 덮은 상태로 돌면 **분자·분모의 창이 어긋나**(키워드 7일 비용 ÷ 그룹 2일 비용) 비용 비중이 100%를 넘는 불가능한 값이 저장된다 → NT 반영 뒤 재판단이 필요하다.

## 사례

- 주간 NT 파일이 판단 뒤 오후에 들어와, 그날 판단이 2/7일 커버리지로 돌아 키워드 비용 비중 290%·414%가 저장됐다(2026-09-15).

## 내 생각 / 미해결 질문

- 카페·블로그·영상 바이럴(NVC·NVB·NVV)과 구글(GSA) 유입·매출이 **이미 NT 파일에 들어온다** — 화면은 그룹 표 한 줄뿐이고 비용이 없어 ROAS는 불가. 사장님 목표(카페 바이럴 성과)는 비용 입력 칸 하나면 절반은 채워진다.
- 사전에 없는 nt_source가 생기면 그 매출이 어느 그룹에도 안 붙는다 — 미지정 코드 목록을 화면에 띄워 사전 등록을 재촉해야 한다(현재 대기 목록은 상세 기록).
- 파일을 넣은 직후 판단을 다시 돌리는 버튼(또는 NT 반영 뒤 자동 재판단)이 필요하다.
