# 광고-구좌별-노출-쏠림

## 한 줄 정의

메타 광고 하나는 **구좌(placement)마다 다른 게시물**로 나가고, 노출은 그중 한두 구좌에 심하게 쏠린다 —
**광고에 박힌 "대표 게시물" 이 사람들이 실제로 보는 곳이 아닐 수 있다.**

## 노출은 어디로 쏠리나

- 구좌별 노출은 광고 insights에 `breakdowns=publisher_platform,platform_position`을 걸어 본다 — 게시물 단위 인사이트로는 못 잰다([[메타-맞춤광고-댓글-API-한계]]).
- 우리 계정에서는 **릴스(FB·IG)가 노출의 60% 이상**을 먹고, FB 피드는 한 자릿수 %다. 같은 FB 안에서도 릴스가 피드의 몇 배이고, 그 배수는 소재마다 크게 다르다.

## 대표 ≠ 사람이 보는 곳

광고 크리에이티브에 박힌 게시물(`effective_object_story_id`)을 여기서 **대표**라 부른다.
[[메타-댓글-자동관리]] 창구가 주는 목록과 대조하면 이렇게 갈린다:

| 구좌 | 링크 모양 | 대표/변형 |
|---|---|---|
| FB 릴스 | `/reel/{id}` | **전부 변형** |
| FB 피드 | `/posts/{id}` | **전부 대표** |
| IG | `/p/{code}` | 대부분 대표, 일부 변형 |

**FB 는 링크 모양만 보면 구좌가 갈린다** — 노출 데이터를 기다릴 필요가 없다. 게시물이 생기는 순간 안다.
**IG 는 못 가른다** — 대표·변형이 전부 `/p/{code}` 이고 `media_product_type` 도 셋 다 `AD` 다. 광고 전용 미디어라 `reach` 도 0으로 막힌다.

## 여기서 나오는 판단

좋아요·댓글을 돈 주고 심는다면([[snskit-booster]]), **어느 게시물에 심느냐로 값이 몇 배 갈린다.**

- 노출을 많이 받는 구좌(릴스 변형)에는 기본 수량, 노출이 적은 구좌(FB 피드 대표)에는 경량.
- 대표 게시물은 FB·IG 가 한 주문 단위라 **FB 만 줄일 수 없다.** 그래서 "FB 는 경량, IG 는 기본" 을 섞은 프리셋을 따로 만들고,
  한 플랫폼만 주문하는 변형에는 기본 프리셋을 준다(설정 `variant_preset_id`).
- 확정 배분표·게시물당 금액 → 상세 기록.

## 함정 — "노출이 없으니 안 달린 것" 이 아니다

FB 피드 노출 비중이 작다는 것과 **FB 피드에 주문이 안 붙는다**는 것은 다른 말이다.
둘을 섞으면 "피드는 돈만 나가고 아무것도 안 달린다" 는 오보가 나온다 — 실제로는 달렸는데 **메타 API 가 그 게시물을 못 읽었을 뿐**일 수 있다([[주문-전달-실물-대조]] §대조하는 쪽도 틀린다).

→ **노출 비중은 "얼마를 쓸지" 의 근거이지, "배달되는지" 의 근거가 아니다.** 둘을 섞지 않는다.

## 사례

- 최근 7일 계정 전체 노출 약 26만 중 릴스 둘이 63.3%, FB 피드 5.5% — FB 만 보면 릴스가 피드의 6.6배(소재별 1.8~12배). 이 분포로 대표 게시물 FB 경량 프리셋을 만들어 게시물당 4,920원을 줄였다(2026-09-22).
- 같은 날 노출 비중과 배달을 섞어 「피드는 안 달린다」고 잘못 보고했다가 되돌렸다.

## 내 생각 / 미해결 질문

- **IG 를 못 가르는 게 제일 아쉽다.** 한 소재의 IG 미디어 2~3개 중 실제로 트래픽을 받는 건 보통 하나인데(유기 좋아요 115 vs 0 vs 11),
  구분할 단서가 없어 전부 기본 프리셋으로 간다. 죽은 미디어 하나에 3,350원이 그냥 나간다.
  유기 좋아요 수가 유일한 단서인데 **우리가 주문하는 순간 오염**된다 — 주문 전 한 번 읽어 두는 수밖에 없을까?
- 구좌 비중은 소재마다 다르다(FB 릴스 9.7%~54%). 지금은 계정 전체 평균으로 판단하는데,
  **소재별로 갈라 쓰는 게 나은지**는 아직 모르겠다. 소재 등록 직후엔 그 데이터가 없다는 게 근본 제약이다.
