# 수집 파이프라인 안전장치

## 한 줄 정의

외부 API는 **부분 응답·빈 응답·늦은 정산**이 기본값이다 — 그것을 "삭제됐다·0이다·끝났다"로 읽지 않도록 수집 단계마다 증거 요구·규모 가드·재수집 창·잠금을 박아 두는 규약. [[API-쿼터-경제학]]이 호출량 쪽이면 이건 데이터 무결성 쪽이다.

## 규약 (SA 툴에서 성문화)

1. **증거 기반 DELETED.** 이번 실행에 안 나온 행을 지우되 **API가 실제로 응답한 범위 안에서만**. 캠페인 응답이 비면 표시 자체를 건너뛰고 warn. 한 테이블의 살아 있는 행 **절반 이상**을 지우게 되면 그 테이블은 건너뛴다(`SWEEP_GUARD_RATIO 0.5`) — 일시적 빈 응답이 키워드 4,274개를 삭제 처리하는 사고 방지. 캠페인마다 커밋해 중간 실패에도 거기까지는 남긴다.
2. **빈 본문은 기존 데이터 유지.** 보고서 본문은 있는데 파싱 0행이면 DELETE 없이 warn → 다음 실행에서 다시 받는다. 정상이면 날짜 단위 DELETE + INSERT 한 트랜잭션(멱등 재수집) + **원본 gzip 보관**(파서를 고치면 재처리).
3. **'수집됨'의 정의를 명시.** AD·AD_CONVERSION 두 보고서 모두, 각 (날짜, 단계)의 **가장 최근 실행**이 ok/no_data여야 한다. 그래서 실패한 날짜는 자동으로 "빠진 날짜"가 되어 30일 안에서 재시도된다.
4. **재수집 창.** 네이버가 부정클릭·전환을 며칠 뒤 정산하므로 **D-1~D-7은 항상 다시 받는다**(처음 3일 → 7일로 늘림). 정산은 뒤늦게 확정·변경돼 **매번 40일**을 다시 받는다.
5. **D-1 실패 시 판단 건너뜀.** 어제 데이터가 없는데 규칙을 돌리면 "비용 0 → OFF" 같은 오판이 나온다.
6. **대량 만료 가드.** 판단 대상이 직전의 절반 미만이면(마스터 동기화 실패 의심) 추천 만료를 건너뛰고, 연속 3회째에는 새 기준으로 받아들인다 — 가드에도 상한이 있어야 정상 축소를 반영한다.
7. **RunLock.** `O_EXCL` 파일 잠금, 3시간 stale, 장시간 백필은 진행마다 `touch`(heartbeat) — 안 그러면 3시간 넘는 백필이 stale로 오판된다. 스케줄러·bat·웹 버튼이 같은 잠금을 쓴다.
8. **단계 격리 + 기록.** 스토어·NT·마진 갱신 실패가 광고 수집·규칙 결과를 막지 않고, 각 단계가 `collect_runs`에 ok/warn/error/skipped로 남으며 `last_collect`는 finally에서 반드시 기록한다.
9. **매출은 저장하지 않고 현재 행 상태에서 매번 계산한다** → 재동기화 이중 차감이 구조적으로 불가.
10. **테스트는 네트워크를 전면 차단한다**(conftest autouse) — 가짜 세션 누락이 즉시 예외로 드러난다.

11. **원천(계정)이 여러 개면 모든 삭제·덮어쓰기·완료 판정을 원천 범위로 좁힌다** (2026-09-15 backstore1 연결).
    - 마스터 스윕: "이번 응답에 없는 행 = 삭제"는 **그 계정 행에만** 적용하고, 규모 가드의 분모도 그 계정 행으로 센다. 안 그러면 B 계정 동기화가 A 계정 캠페인을 "응답에 없음"으로 보고 지운다(가드에 걸려 경고만 나도 판정이 오염된다).
    - 날짜 덮어쓰기: `DELETE … WHERE date = ? AND 계정 = ?`. 기본키에 계정이 없어도 ID가 전역 유일하면 기본키는 그대로 둔다.
    - 완료 판정·빠진 날짜: 계정마다 따로. 한 계정 실패가 다른 계정을 "다 받음"으로 가리지 않게.
    - **NULL = 기본 계정** 규약으로 옛 데이터를 옮기지 않고 전환한다. 첫 수집 때 NULL을 기본 계정 ID로 한 번 채워, 키 파일 순서를 바꿔도 옛 데이터 소속이 흔들리지 않게 한다.
    - 판단(규칙)은 **모든 원천 수집이 끝난 뒤 한 번**. 어느 원천이든 어제 데이터가 실패하면 판단을 건너뛴다 — 한쪽 비용만 들어온 상태의 비중·ROAS는 틀린 숫자다.
    - **한 원천만 다시 받아도 판단 전에는 모든 원천의 어제 상태를 본다** (독립 리뷰 반영, 같은 날). 이번에 받은 결과만 보고 판단하면, 다른 원천이 어제 실패한 채로 한 원천 백필이 판단을 돌려 버린다. 원천마다 (날짜, 단계)별 **가장 최근 실행**이 성공인지로 본다.
    - **준비 단계도 원천별로 격리한다.** 백필 전 마스터 동기화에서 한 원천의 키가 거절(403)되면 그 원천만 오류로 기록하고 빼고, 나머지는 계속 받는다. 뺀 원천 수를 결과에 남겨 "완료"라는 말에 가려지지 않게 한다.
    - **"정상" 표시는 파일 형식이 아니라 마지막 실제 호출 결과로 정한다.** 키 파일 형식이 맞아도 네이버가 키를 거절할 수 있다. 계정별 배지는 그 계정의 마지막 동기화 결과(정상·경고·오류·수집 전)를 보여 준다.
    - **설정 파일 파서는 깨진 줄을 조용히 넘기지 않는다.** `[account.123] # 메모`처럼 머리글 뒤에 주석이 붙으면 블록 전체가 무시돼 계정 하나가 통째로 빠진다 — 줄 번호와 함께 멈춘다. 맨 위 기본 섹션은 좁은 키 이름만 받아, 같은 파일 위쪽의 다른 서비스 `api_key=` 줄을 잘못 읽지 않게 한다.

12. **API가 없는 원천은 파일 반입 + "이 기간에 반영됐는가" 표시가 한 몸이다** (2026-09-15 디스플레이 광고비, [[네이버-SA-성과측정-툴]]).
    - 네이버 디스플레이(카탈로그 판매) API는 공식 파트너사 전용이라 광고주는 못 받는다. 광고주센터 "광고비 보고서"(기간 단위 **일**) CSV가 유일한 입력이다 — 기간 단위를 "전체·주·월"로 내려받으면 날짜 열이 범위가 되어 읽을 수 없으니, 오류 문구에 "기간 단위를 '일'로 다시 내려받으세요"를 그대로 적는다.
    - **원자료 보존**: (날짜, 계정)이 기본키인 표에 총비용을 그대로 넣고, 같은 날짜는 나중 파일이 덮어쓰며, 폴더에서 파일이 사라져도 행은 지우지 않는다(NT 파일 반입과 다른 점 — 한 번 넣은 기간을 다시 넣지 않아도 되게).
    - **자료 없음 ≠ 0원**: 날짜별 값은 없으면 `None`, 기간마다 `covered/days`와 빠진 날짜 구간을 계산해 히어로·기간별 표 열마다 반영·일부만 반영·미반영을 붙인다. 안 그러면 파일을 안 넣은 달의 순수익이 광고비 없이 부풀어 보인다.
    - **파일 단위 거부·트랜잭션**: 파싱이 끝난 뒤 한 트랜잭션으로 쓴다(중간 오류면 아무것도 안 바뀜). 올린 파일이 형식 오류면 폴더에서 지운다(매일 수집이 같은 오류를 되풀이하지 않게). 폴더 파일은 mtime이 같으면 건너뛰어 오류도 한 번만 기록된다.
    - **모르는 사람도 따라 하게**: 화면이 "다음에 내려받을 기간"(마지막 반영일 + 1 ~ 어제, 자료가 없으면 처음 180일)을 계산해 보여 주고, 내려받는 순서를 번호로 적고, 올리기(브라우저 → 서버 폴더)와 폴더 복사를 둘 다 둔다. 서버가 다른 PC로 가도 올리기는 그대로 된다.
    - **공용 비용 배분**: 특정 제품 광고가 아닌 비용은 보는 기간의 브랜드 매출 비율로 나눈다(큰 나머지 반올림으로 합 보존). 매출이 없는 기간은 브랜드에 못 나누고 전체 합계에만 넣으며 "미배분"으로 적는다. 추천 규칙 입력(`brand_metrics`)은 건드리지 않고 화면 합계 층에서만 더한다 — 판단은 그 채널 자료만으로.
    - 대조: 파일의 일별 합(9/9~9/15 189,206원)과 광고주센터 캠페인 화면(189,204원), "전체" 단위 보고서(817,895원)와 일별 파일 합(817,897원)은 일별 반올림만큼 다르다 — 검색광고와 같은 성격이라 원 단위 차이는 정상.

## 검수에서 드러난 구멍 (실측 2026-09-15)

- **순서.** 일일 수집이 규칙 판단 → 스토어 동기화 → NT → 마진 순이라 판단이 **어제 매출 없이** 돈다(서버 시작 경로는 반대 순서로 바르게 짜여 있다). 07:30에 돈다면 D-1 주문 대부분이 커서 밖이다.
- **테스트가 실데이터를 덮어썼다.** 수집 API 테스트가 `report_dir` 기본값(실제 `data/reports/`)으로 가짜 보고서를 저장 → `2026-09-07_AD.tsv.gz`(118KB)가 4행짜리 가짜(158B)로 교체됐다. 픽스처의 경로 기본값은 반드시 tmp로. → [[라이브-검증-프로토콜]]
- **스케줄러는 항상 성공을 본다.** vbs가 대기하지 않고(`Run …, 0, False`) 즉시 0으로 끝나 `RestartCount 3`은 죽은 설정이고, 규칙 예외로 프로세스가 죽으면 그날 스토어·NT·마진이 전부 생략된다.
- **07:30에 실제로 돈 적이 없다**(로그: 08:44~08:56, 주말 0회) — 로그온 상태 필요·WakeToRun 없음. 7일 재수집 덕에 손실은 없으나 "어제" 숫자가 늦고 주말분은 월요일에 몰린다.
- **시트 통째 교체에 규모 가드가 없다.** 첫 탭이 비거나 탭 이름이 바뀌면 원가 239행·풀필먼트 27행이 0행으로 비워지고 "ok"로 기록된다. 마스터 스윕 가드와 같은 가드가 시트에도 필요하다.
- `requirements.txt`에 `bcrypt`·`openpyxl` 누락 → 새 PC에서 `처음설치.bat` 뒤 `실행.bat`이 import에서 즉사(이 PC에서 재현).
