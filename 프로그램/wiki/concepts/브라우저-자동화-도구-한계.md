# 브라우저 자동화 도구 한계

## 한 줄 정의

Claude가 브라우저(claude-in-chrome·내장 브라우저 pane·Playwright)로 화면을 직접 확인할 때, **도구가 거짓 신호를 내는 지점과 그 우회법**. [[라이브-검증-프로토콜]]이 "무엇을 확인해야 진짜 확인인가"라면, 이 페이지는 "확인하는 도구 자체를 언제 믿으면 안 되나".

## 측정이 틀리는 지점

- **짧은 애니(2초 GIF 등)는 스크린샷으로 못 잡는다**(캡처 지연 ~2초). → `getBoundingClientRect` 기하측정·`new Image().onload` natWidth·전역변수 감시(`window.__x`)로 증명. `javascript_tool`의 async 반환은 `{}`로 비어오니 **결과를 전역에 저장하고 다음 호출에서 읽기**. 육안 필요하면 애니 지속시간을 임시로 6초로.
- **`resize_window` ≠ 기기 뷰포트**(창 크기라 세로가 실기기보다 짧음). 정확한 폰뷰(아이폰14ProMax 430×932 dpr3)는 **F12 기기 에뮬레이션**으로 — 대표가 직접 켜줘야 함.
- **CSS 변수는 정의 요소가 아니라 "적용받는 자손"에서 읽어라.** `:root`에 `--x:30`, `body.scrolled`에 `--x:50`이면 `getComputedStyle(html)`은 항상 30 → 실제 값은 자손 요소에서 읽어야 보임.
- **기하 측정 전 트랜지션을 꺼라.** class 토글 직후 `getBoundingClientRect()`는 애니 중간값 → `*{transition:none!important}` 주입 후 reflow(`offsetHeight`) → 측정.
- **클래스/플래그 게이팅은 "켜지는 쪽" 값이 실존하는지부터 실증**(반대쪽만 보고 추정 금지). 예: `ez-view-type-pc`가 스크립트에 아예 없어 PC에서 영원히 미발동한 사고 → [[카페24-스킨구조-함정]].

## 창이 뒤에 있으면 브라우저가 일을 멈춘다

- **포커스 없는 자동화 창에서는 "브라우저가 일을 멈춘다".** 창이 뒤에 가려지면 **CSS 트랜지션이 진행되지 않아** `getComputedStyle`이 계속 옛 값을 반환하고(=수정이 안 먹은 줄 알고 30분 헛디버깅), **클립보드 API는 pending으로 매달리거나 거부**되며, **스크린샷이 5초 타임아웃**난다. → 기하는 `transition:none` 주입 후 측정, 클립보드·스크린샷은 **내장 브라우저(browser pane) 모바일 에뮬**로 재시도. 실제로 내장 브라우저 375×812에서 복사 버튼 **실클릭이 OS 클립보드에 기록되는 것까지 확인**됐다(앱이 "페이지가 클립보드에 썼다"고 경고 → 역설적으로 그게 성공 증거). 부작용: **대표 클립보드가 덮이니** 배포용 복사본이 물려 있으면 미리 알리고 나중에 재복사.
- **앱 창이 뒤에 있으면 내장 브라우저 캡처도 믿을 수 없다.** 스크롤 뒤 캡처가 5초 타임아웃·빈 회색 화면·잘린 화면(뷰포트 에뮬 시)으로 번갈아 나온다. 사용자 크롬도 화면 배율(`devicePixelRatio` 1.75)이면 캡처가 왼쪽 위만 잘려 온다.

## 클릭 좌표는 스크린샷 프레임 기준

- **브라우저 확대가 100%가 아니면 클릭이 어긋난다.** `devicePixelRatio≠1`이면 스크린샷 배율과 클릭 배율이 달라 엉뚱한 곳이 눌린다(눌렸는데 "아무 일도 안 일어남"으로 보임). → **클릭 좌표 = 요소 CSS 중심 × (스크린샷 프레임 폭 ÷ innerWidth)**, 그리고 `document.addEventListener('click',…,true)` 로거로 **실제 명중 대상**을 확인.
- 모바일 폭 재현이 필요하면 같은 도메인 **375px iframe에 페이지를 띄우고 그 안에 주입**(transform:scale로 확대해 캡처)해도 된다. 여러 케이스를 한 번에 훑는 프로브도 같은 방식([[라이브-검증-프로토콜]] §전수 순회).

## 전체 화면 점검은 헤드리스로

- 창 위치·배율과 무관하게 매번 같은 결과가 필요하면 **Playwright + 설치된 크롬(`channel="chrome"`, headless)** 로 탭마다 전체 페이지 캡처 → 1,200px씩 잘라 읽는다.
- **말풍선은 `hover(force=True)`로 판정하지 말 것.** 마우스가 이미 근처에 있으면 새 이벤트가 안 나서 「안 뜸」이 거짓으로 나온다. **`mouse.move(x, y, steps=8)`로 실제로 움직여** 확인하고, 「안 뜸」이 나오면 `elementFromPoint`로 마우스 밑에 무엇이 있는지까지 적는다.
- 스크립트에서 쓰는 창 크기·경로는 스크래치 폴더에 두고, 결과는 「문제 칸 사진 + 한 줄 설명」으로 보낸다.

## 사례

- 2026-09-27 전체 대시보드 점검 — `hover(force=True)`로 「말풍선 안 뜸」 7건이 나왔으나 전부 거짓, 실제 마우스 이동으로 다시 보니 모두 떴다.
