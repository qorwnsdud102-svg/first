# 카페24 스킨구조 함정

## 한 줄 정의

카페24 스마트디자인 스킨은 **여러 파일이 같은 DOM에 함께 로드되는 한 세트**다. "라이브가 엉망"의 상당수는 코드 버그가 아니라 이 구조(세트 의존·클래스 충돌·서버캐시·붙여넣기 위치)에서 온다. 라이브가 이상하면 **코드보다 이 구조부터 의심**하는 게 정석.

## 핵심 주장 / 속성

- **스킨은 서로 물린 한 세트 — detail만 붙이면 깨진다.** `detail.html`은 색을 `var(--brand)` 등으로 **사용만** 하고 정의(`:root{--brand:#1e3a8a…}`)는 **`header.html`에만** 있다. detail만 붙이고 header를 안 붙이면 `--brand` 미정의 → `background:var(--brand)`가 무색 → **구매버튼 투명** 등 전면 붕괴. → 라이브가 "엉망"이면 코드 버그부터 의심 말고 ① 나머지 스킨(9종)이 다 붙었는지 ② F12로 `--brand` 정의 여부부터 확인.

- **header(공통)+detail(상세)이 같은 DOM → 같은 클래스명이 충돌.** detail의 광범위 선택자가 header 요소를 때린다. **진단 신호**: "메인페이지는 정상인데 **제품(상세)페이지에서만** 깨짐/요소 사라짐" = detail.html의 bare 선택자가 공통 요소를 때리는 것부터 의심(메인엔 detail이 없어 증상 안 나타남). 실사례: detail의 `.drawer-header{display:none}`(자기 옵션 드로어 숨김용)이 header의 네비 드로어 로고(같은 `.drawer-header`)까지 숨김.
  - **원칙**: 페이지 전용(detail) CSS는 반드시 **자기 컨테이너 id로 스코프**(`#custom-drawer-panel .drawer-header`). 범용 클래스명에 bare 규칙 걸지 말 것.
  - **일반 원칙**: 전역 네임스페이스를 공유하는 여러 모듈이 한 문서에 로드되면, 각 모듈의 스타일은 **자기 루트 셀렉터로 스코프**해야 한다(CSS 격리 = 컴포넌트 격리).

- **서버 HTML 캐시 — 쿼리파라미터로 안 뚫린다.** 붙여넣기+저장해도 라이브가 안 바뀌면 십중팔구 카페24 서버측 페이지 HTML 캐시. 스킨 CSS/JS가 인라인 `<style>/<script>`로 들어가 페이지 HTML 캐시에 통째로 잡힌다. `?v=`·`?nocache=`는 **브라우저 캐시만** 우회 → 안 됨. 반드시 **관리자 → 디자인(스마트디자인) → 사이트 캐시 삭제**. **파일별로 따로 걸릴 수 있음** — 여러 파일 붙였는데 일부만 라이브에 뜨면 "안 뜬 파일만 저장 누락/캐시 미삭제" 의심. "붙였는데 소스에 내 수정이 없다"도 코드버그 아니라 이 캐시부터.

- **가변높이 바에 걸치는 플로팅 요소는 `var(--bar-h)`로 묶어라.** 하단 즉시구매 바가 스크롤에 따라 높이 변동(`:root{--bar-h:30px}`/`body.bar-scrolled{--bar-h:50px}`). 그 위 플로팅 요소(리뷰뱃지·구매버블)의 `bottom`을 고정 px로 박으면 바가 낮아질 때 떠 보인다. → `bottom: calc(var(--bar-h) + 2px + env(safe-area-inset-bottom,0px))` + `transition:bottom .24s`로 **바 높이 변수를 그대로 추종**. (라이브 측정 함정은 [[라이브-검증-프로토콜]]: 변수는 자손에서 읽기·트랜지션 끄고 측정.)

- **반응형 클래스가 한쪽에만 있을 수 있다 — 게이팅 전 실존 확인.** 이 계열 스킨은 모바일 폭에서만 `<html class="ez-view-type-mobile">`을 붙이고 **PC에선 아무 클래스도 안 붙임**(`ez-view-type-pc` 문자열이 스크립트에 아예 없음). PC 개편을 `html.ez-view-type-pc`에 걸었다가 **PC에서 영원히 미발동**한 사고. → PC 판정 = `!html.classList.contains('ez-view-type-mobile') && innerWidth>=768`. CSS는 JS가 붙이는 자체 클래스(`body.rp-pc-layout`)로만 스코프. load·resize(디바운스)·MutationObserver 3중 재판정.
  - **일반 원칙**: 조건부 로직을 걸기 전, **켜지는 쪽 조건이 실제로 존재/발생하는지 라이브에서 실증**하라(반대쪽만 보고 추정 금지).

- **붙여넣기 위치 착오 — 메인 백지 + "상품 코드가 없습니다".** `detail.html`(상품상세용, `module="product_*"`라 상품번호 필수)을 **메인 스킨 자리에 잘못 붙이면** 메인엔 상품번호가 없어 카페24가 렌더 중단하고 초소형 stub(3~4KB, `historyBack('상품 코드가 없습니다.')`)을 반환 → 백지.
  - **진단**: 브라우저 **alert가 뜨면 자동화(claude-in-chrome)가 차단**된다 → **curl로 서버 HTML 직접** 판별: `curl -s -A "Mozilla/5.0" https://몰/` 길이 3~4KB + `상품 코드가 없습니다` 문자열이면 detail이 메인에 들어감. 고유마커(`custom-drawer-panel`·`optionCards`)로 각 스킨에 뭐가 들었는지 교차 확인. (`curl -sI` HEAD는 카페24가 405 — GET으로 봐야 함.)
  - **복구**: 스킨편집 되돌리기 or 올바른 `main-index.html` 재붙여넣기. **함정**: 되돌리기로 메인 복구 시 **메인에만 있던 최신 detail 배포분이 같이 사라짐** → detail을 상품상세 스킨에 다시 붙일 것. "최신 반영" 판별은 **이번 배포에만 있는 고유마커**로(기존 마커는 예전 배포에도 있어 오판).

- **진열모듈은 "결과 0건"이면 블록째 사라진다 — 빈 칸이 아니라 무(無).** 메인의 `<div module="product_listmain_N">`은 카페24가 그 진열그룹 상품으로 채우는데, 결과가 0건이면 **컨테이너 자체를 출력하지 않는다**(빈 div도 안 남음). 증상 = 섹션 제목·부제만 남고 아래가 텅. 0건이 되는 경우가 **둘**이라 헷갈린다: ①그룹에 상품이 없음 ②그룹엔 있는데 그 상품들이 **'표시안함' 분류에만 속함**(광고 랜딩용 숨김 상품을 메인 그룹에 넣어둔 경우 — 관리자 목록엔 4개가 보이는데 화면은 0건). → 진단은 라이브 **서버 HTML에 컨테이너 클래스(`rp-bp-grid` 등)가 있는지**부터. 스킨 코드엔 있는데 서버 HTML에 없으면 100% 진열 데이터 문제(코드 수정 금지). 고치는 자리는 **상품 [표시설정] → 메인 진열 체크** + **[상품 진열 → 메인 진열] 그룹의 진열순위**(`$count=1`이면 1순위 1개만 노출). (2026-09-20 히토 실사고)
  - **일반 원칙**: 플랫폼이 "데이터 0건 = 마크업 삭제"로 동작하면 빈 상태 UI는 **내 코드가 아니라 플랫폼이 지운다** → 빈 칸 디버깅은 코드가 아니라 데이터·노출설정부터.

- **자동 SEO 주소에 상품명이 박힌다 — 이모지·한글이 %-인코딩돼 링크가 흉해짐.** 진열모듈의 `{$link_product_detail}`은 `/product/<상품명 슬러그>/11/category/1/display/2/?icid=…` 형태라 상품명에 이모지(🔒)가 있으면 `%F0%9F%94%92…`로 길어진다. 카드 링크만 깔끔하게 하려면 **로드 후 href 치환**: `href.match(/\/product\/[^?]*?\/(\d+)\//)`로 상품번호만 뽑아 `/product/detail.html?product_no=N`으로 교체(못 뽑으면 원본 유지=우아한 실패, 진열 상품이 바뀌어도 자동). ⚠️ **canonical·og:url은 그대로 SEO 주소** — 카톡 공유 미리보기·검색 대표주소까지 바꾸려면 상품명에서 이모지를 빼는 수밖에 없다. `?icid=`(유입경로 통계) 파라미터는 치환하면 사라진다.

- **공유 클래스 충돌은 드로어 "부품"에서도 반복된다.** `.drawer-header`뿐 아니라 **`.drawer-body`·`.drawer-footer`·`.drawer-main-pay`도 header 햄버거 드로어와 공유**. 구매 드로어에 요소를 넣을 땐 `querySelector('.drawer-footer')`가 아니라 **`#custom-drawer-panel .drawer-footer`**로 잡을 것(스코프 없이 넣었다가 화면 밖 메뉴 드로어에 붙어 좌측에 흰 조각이 보인 사례, 2026-09-20).
