# 부정 판정 지문 오탐 방지

## 한 줄 정의

차단·오류 같은 "부정 상태" 를 문자열 지문으로 감지할 때, 정상 페이지에도 존재하는 범용 토큰을 물어 대량 오탐을 낸다 — 정상 확인(포지티브 가드)을 지문보다 먼저 둔다.

## 핵심 주장 / 속성

- **사례 (2026-07-20)**: `looks_blocked` 지문 `"captcha"` 가 네이버 **모든** 검색페이지에 기본 탑재된 JS 설정 `"captchaApi": {"image": "https://captcha.nid.naver.com/..."}` 을 물었다. 받아온 페이지는 완전 정상(제목 `"허리디스크 : 네이버 검색"`, 광고 5개 정상 추출)인데 "차단" 판정 → 입찰가 동결·quota 소진 연쇄(2차 피해). 실제 제한은 오전 1회뿐 이미 풀렸고, 하루종일의 "차단 6회 → 백오프 4h" 는 **전부 가짜**였다.
- **교훈 4**:
  1. **부정 지문은 실제 정상 페이지 샘플로 사전 검증** — 합성 HTML 테스트만으론 부족. "정상엔 안 나오는 문구" 라는 가정 자체가 미검증이었다.
  2. **범용 영단어 지문 금지** (`captcha`·`error`·`blocked` 등) — 현대 웹은 정상 상태에서도 관련 인프라 설정·스크립트 URL 을 항상 포함한다.
  3. **포지티브 가드 우선** — 정상 셸(제목·본문 컨테이너)이 보이면 무조건 정상 처리, 네거티브 지문은 셸이 없는 페이지에서만 평가. 2단 판정이 네거티브 단독보다 안전.
  4. **감지기부터 의심** — 운영 신호가 상식과 어긋나면(사람 브라우저는 되는데 봇만 차단?) 가장 먼저 감지기 자체를 의심. 단서는 사용자 질문("내 브라우저는 되는데")이었다.
- **일반화** — 헬스체크·에러 분류·스팸/봇 필터·응답 파싱 등 모든 "부정 상태 판정" 에 적용. 위양성(false positive)이 자동 조치(동결·차단·재시도)를 트리거하면 피해가 연쇄된다.
