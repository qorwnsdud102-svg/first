# AI 리셀러 프록시 — 비용과 지연

## 한 줄 정의

Claude를 직접 쓰지 않고 **재판매 프록시**(AI Prime Tech 등)를 통해 쓰면, 응답이 느린 원인도 돈이 새는 자리도 **모델이 아니라 호출 1번의 고정비**다. 짧은 글을 많이 분류하는 도구는 **묶어 보내는 것**이 거의 유일한 최적화다.

## 실측 (2026-09-20 · 일상곡선 댓글 43건 표본)

| 재 본 것 | 결과 |
|---|---|
| 빈 요청("1+1?", 답 10토큰) sonnet-5 | **14.0초** |
| 빈 요청 fable-5 / opus-5 | 11.2초 / 12.0초 |
| 실제 판단 호출(판단 기준 3.4KB + 댓글) | 14.4초 — **첫 글자까지 13.1초, 글 쓰는 데 0.7초** |
| 댓글 17건 1건씩 | 482.6초 · 입력 39,310토큰 · **$0.117** |
| 댓글 17건 **한 번에 묶어** | 51.7초 · 입력 2,690토큰 · **$0.015** |

→ **시간의 90%는 줄서기**다. 모델을 바꿔도 11~14초로 같다. 스트리밍으로 쪼개 보면 첫 글자까지가 지연 전부다.

## 왜 고정비가 큰가

빈 요청인데 **입력 토큰이 1,314개**로 청구된다. 우리가 보낸 건 5토큰이다 — **프록시가 자기 지시문을 매 호출에 얹는다.** 여기에 우리 판단 기준(~950토큰)이 더해져 **댓글 1건에 약 2,300토큰**. 댓글 본문은 10~30토큰이다.

- 묶으면 이 고정비를 나눠 쓴다: 17건 묶음의 입력 2,690토큰 = 건당 158토큰(**1/15**).
- 프록시가 **프롬프트 캐싱은 이미 해 준다**(청구 내역에 cache read 2,179토큰). 우리가 `cache_control`을 붙여도 응답에 캐시 칸이 안 보이니 따로 할 일은 없다.

## 모델 단가는 상식과 반대일 수 있다

같은 1.0배 그룹인데 실제 청구는 이렇게 갈렸다(같은 작업 기준).

| 모델 | 1건씩 건당 | 17건 묶음 1회 |
|---|---|---|
| claude-sonnet-5 | **$0.0056 (7.7원)** | $0.0151 |
| claude-fable-5 | $0.0264 (36.5원) | $0.0852 |

**작은 모델이 4.7배 비쌌다.** 토큰 수는 거의 같다(39,310 vs 39,459) — 단가 차이다. 리셀러의 가격표는 모델 크기와 무관할 수 있으니 **대시보드 청구 내역(CSV)으로 확인**하고 고른다.

정확도도 함께 봤다(같은 17건): 숨김/남김 정답은 넷 다 16~17/17로 비슷했지만 **fable은 멀쩡한 댓글("저에게 물어보세요")을 숨김으로** 판정했다. 싸지도 않고 위험만 늘었다.

## 묶음 처리 설계 규칙

1. **모인 만큼만 묶는다.** 1건이면 1건짜리 호출 — 평소 회차는 지금과 같고, 처음 켤 때·몰릴 때만 이득이다. 손해 보는 경우가 없다.
2. **묶음 답이 어긋나면 1건씩으로 되돌아간다.** 개수·번호가 안 맞으면 실패로 올려 부르는 쪽이 원래 길로 가게 한다(조용히 일부만 쓰지 않는다).
3. **한 번에 보낼 개수에 상한**을 둔다(20건). 답이 길어지면 잘린다.
4. **앞뒤 댓글이 같이 보이면 판단이 좋아진다.** 17건 묶음은 1건씩에서 실패한 "하이"(JSON이 아닌 답)까지 살려 17/17이 됐다. 묶음은 비용 절감일 뿐 아니라 정확도에도 손해가 아니었다.
5. **타임아웃은 줄서기보다 넉넉히.** 대기 13초가 기본인데 30초로 끊으면 멀쩡한 호출이 재시도로 **두 번 청구**된다(17건 중 4건이 그랬다) → 60초.

## 이 개념이 바꾼 것

- [[메타-댓글-자동관리]]: 회차의 댓글을 다 모아 **한 번에** 판단(게시물·플랫폼이 달라도 한 호출). 실데이터에서 AI 호출 7번 → **1번**, AI 시간 180초 → 25초.
- 운영 비용 감: 댓글 1건당 7.7원, 하루 30건이면 230원. 처음 켤 때 밀린 댓글 수백 건도 묶음이면 몇 백 원.
