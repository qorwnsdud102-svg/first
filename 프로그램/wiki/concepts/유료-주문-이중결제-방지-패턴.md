# 유료-주문-이중결제-방지-패턴

## 한 줄 정의

외부 API에 **돈 나가는 요청**(주문·결제)을 보내는 프로그램이 같은 주문을 두 번 내지 않게 하는 네 겹의 규칙. [[snskit-booster]] 리뷰에서 한 겹씩 뚫릴 때마다 추가됐다.

## 네 겹

1. **호출 자체는 재시도 금지** — 타임아웃은 "실패"가 아니라 "모름"이다. 응답이 끊겨도 서버는 이미 접수했을 수 있다. 조회(balance·status)는 재시도해도 되지만 `add`는 0회.
2. **접수 불명은 별도 상태** — 클라이언트 예외에 `delivered_unknown` 플래그(연결 실패 = False, 읽기 타임아웃·비JSON·HTTP≥400 = True, 서버가 명시적으로 거부 = False). 엔진은 True면 `Unknown`으로 기록하고 **재주문하지 않으며** 사람이 주문내역과 대조해 정리할 때까지 그 (링크, 서비스)를 미완료로 취급한다. `Failed`로 적으면 다음 사이클이 재주문한다 — 리뷰가 잡은 첫 구멍.
3. **선기록(write-ahead)** — 주문 행을 `Placing`으로 **먼저** 커밋하고 API를 부른 뒤 결과로 갱신. 호출 직후 프로세스가 죽어도 돈 나간 주문이 기록 없이 사라지지 않고, 미완료로 남아 재주문을 막는다.
4. **DB가 최후 방어선** — 미완료 상태의 (링크, 서비스)에 부분 유니크 인덱스. 프로세스 락(RLock)은 인스턴스 단위라 엔진이 둘이면 뚫린다(리뷰가 두 인스턴스로 재현). 인덱스는 구조와 무관하게 INSERT를 거부한다.

## 같이 가는 규칙

- **상한 계산은 실제 나갈 수량으로** — 클라이언트가 보낸 댓글 줄 수가 선언 수량보다 많으면 상한 검사를 통과한 뒤 더 큰 주문이 나간다(500줄로 4.6배 재현). 줄 수 ≤ 수량을 API 입력에서 강제하고 엔진에서도 초과분은 건너뛴다.
- **시뮬레이션 모드 기본 ON** — 첫 가동은 "했을 주문"만 기록. 시뮬레이션 주문도 일일 상한에 누적해야 실전과 같은 보류가 재현된다.
- **부분 실패 재시도는 성공분 제외** — 한 회차의 항목 중 하나만 실패했으면 재시도 때 성공한 (링크, 서비스)는 뺀다.
- **집계는 주문마다 즉시** — 회차 도중 예외가 나도 이미 나간 주문 수가 요약에서 빠지지 않게.
