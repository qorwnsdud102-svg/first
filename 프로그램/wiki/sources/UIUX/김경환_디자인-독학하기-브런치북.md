# 김경환 — 브런치북 「디자인 독학하기」 (9화)

- 과학기자 출신이 독학으로 UI/UX 디자이너가 되어 **실무 1년 동안 직접 잰 전환율**을 글로 남긴 연재. 다른 UI/UX 출처(닐슨·Figma·와니)가 "원칙"이라면 이 책은 **"원칙을 적용했더니 숫자가 이렇게 바뀌었다"**를 가진 유일한 출처다.
- 책 예외 규정에 따라 9편을 한 페이지로 묶는다. 위치 표기는 글 번호(74·94…) + 그 글의 소제목.
- **수치 읽는 법**: 전부 한 앱(옷 사이즈·코디 검색 서비스, iOS + 모바일 웹)의 자체 측정. 대조군 없는 전후 비교가 많고, 저자 스스로 다른 요인을 인정한 곳도 있다(→ 121). "이 방향이 먹혔다"의 증거로 쓰고, 수치 크기를 우리 몰에 그대로 옮기지 않는다.

## 요지 — 행동 규칙으로

### 한 화면 한 가지 (가장 강한 근거)

- **한 화면엔 한 질문·한 행동만** ('1 Thing / 1 Page', 토스에서 차용 — 74·94 '단순하게'·110 원칙 02). 93: 스타일 설문 11문항을 한 화면 한 문항으로 쪼개자 설문 완주율 **주간 70% 이상, 최근 80%**. 110: 같은 원칙을 극단적으로 지킨 구간들 평균 전환 80% 이상.
- **주관식보다 객관식**, 답하기 싫을 수 있는 항목(본인 사진·키/몸무게)엔 **'건너뛰기' 버튼을 따로** (93 §5·§6). 사진 필수 화면에서 이탈이 몰려 선택으로 바꿨고 대신 "좋아하는 스타일 고르기"로 품질을 보완.
- **진행 막대는 일부러 뺐다** (93 §4) — 11문항이 많아 보여 초반 이탈을 부를 거라 판단. 74(핀터레스트 '1/3' 막대가 심리 부담을 줄인다)·101('다음이 마지막 단계입니다!' 안내)·[[Figma_UI-디자인-원칙-7가지|Figma 점진적 공개]](남은 단계를 알려라)와 **충돌**. 저자 판단이며 막대 유무 A/B는 하지 않았다 → 미검증 쟁점으로 둔다.

### 버튼 — 크기·위치

- **터치 영역 최소치**: 74·94에선 44×30px(Josh Clark·MS 연구, 7mm≈44px@160dpi, 인접 시 9mm≈57px, 간격 2mm≈13px) → **98에서 48×48로 갱신**(내비게이션 바 높이 48과 맞춤, 아이콘이 24×24여도 터치 영역은 48×48). 최신값 48×48을 쓴다.
- **꼭 눌러야 할 버튼은 엄지 영역(하단)으로** (98 §04). 같은 '사이즈 비교' 버튼이 iOS는 하단(신규 사용자 클릭 **23.4%**), 안드로이드는 상단 내비 바(**7.46%**) — 안드로이드도 하단으로 옮기자 **7.46%→22.8%** (약 3배). 이 책에서 가장 깨끗한 자연 실험.
- 단, 키보드가 엄지 영역을 차지하는 입력 화면에선 **진행 버튼을 내비 바 오른쪽에** 둬도 된다 (98 §03, 인스타그램 피드 등록 사례). 두 손 타이핑 땐 엄지가 더 위로 올라가므로 웹에선 **입력칸 아래 고정 위치**(40px)로 옮겨 브라우저 차이를 없앴다 (101 §03·93 §7).
- **엄지 최적점은 화면 맨 아래가 아니라 중앙보다 약간 아래** (121 §2-3) — 간편 로그인 버튼을 조금 위로 올린 근거.
- **필수 입력 전엔 버튼 비활성** — 빈 채로 눌러 경고 팝업을 보게 하지 말 것 (98·93 §2·110 원칙 03). 비활성 표시는 회색 #DBDBDB 또는 주색 투명도 40% (93 — 회색이 '이전' 버튼과 헷갈려 투명도로 바꿈).

### 메시지가 위치보다 세다

- **X 버튼 vs CTA 실험** (108 §02): 설명이 잘 안 전달되는 팝업에서 엄지 영역 CTA 38.4%, 누르기 어려운 오른쪽 위 X 61.6%. → **좋은 위치는 메시지를 대신하지 못한다.**
- **광고→스토어→앱까지 같은 말** (110 원칙 04·121): '코디 검색' 한 메시지로 맞추자 앱 내 21.9% 구간 전환이 **63%**, KPI 13%→20%. 121: 회원가입 화면 도달 42.7%→94.8%, 도달 후 완료 65.3%→89.9%, 신규 설치자 가입률 **27.9%→85.2%**.
  - ⚠️ **효과가 섞여 있다**: 같은 개편에서 "회원가입을 하지 않으면 앱을 쓸 수 없는 구조"로 바뀌었고 저자도 가입률이 "올라갈 수밖에 없다"고 인정(121 §2-2). 85.2%를 메시지 일관성만의 효과로 인용하지 말 것.
- **홈의 '주인공 버튼' 하나만 강조** (108 §01): 나머지 아이콘·탭 라벨을 죽이고 한 버튼에 색·크기·모션. 첫 방문자 29.9%가 눌렀고, 첫 옷 등록자의 74.2%(B안 이후 90%)가 이 버튼 경유. A/B/C 테스트는 **시안당 약 800명**, 바뀌는 영역 외엔 전부 동일하게 유지 — B안(값이 자동으로 채워지는 모션으로 가치를 보여 줌) 30.3%로 최고, 테스트 기간 KPI 7% 상승(%p인지 상대치인지 원문 불명).

### 문구 (UX 라이팅)

- **버튼 문구는 누른 뒤 일어날 일로** — '필터 적용'→'하의 4,388개 보기'/'나에게 맞는 3,784개 상품 보기'(숫자가 필터 따라 실시간 변경, 94 §2·§4), 삭제 확인엔 '확인' 대신 '삭제'(110 원칙 08).
- **사내 용어 금지** — '사이즈 필터'→'상의 찾기', '총장'→'총길이', 대체어 없는 용어엔 그림 (94 §4).
- **'이유'를 '고민'으로 바꾸자 이탈이 거의 사라짐** (93 '전환율, 그 결과는?'): "코디 받고 싶은 이유"는 생각해 본 적 없는 질문이라 막히고, "옷 입을 때 어떤 고민"은 평소 생각을 그대로 적게 한다. 체류 시간은 늘었다.
- **간편 로그인 버튼은 '~로 로그인' 대신 '~로 시작'** — 가입인지 로그인인지 고민하는 단계를 없앰 (121).
- 비밀번호 같은 보안 화면엔 ':)' 같은 캐주얼 표현을 빼고, 맥락 문구('1번만 입력하니 정확히')로 실수를 줄인다 (74).
- **'토스트'로 끝날 일을 '확인' 팝업으로 만들지 말 것** — 확인 버튼 팝업은 반드시 봐야 할 정보에만 (110 원칙 03).

### 가입·로그인

- 받을 정보는 꼭 필요한 것만, 비밀번호 규칙은 서비스 위험도만큼만(이 앱은 '6자리 이상'), 규칙 충족 여부는 **입력 중 실시간 피드백** (74·101·110).
- 간편 로그인은 선택지를 줄여 2~3개 (101: 카카오·페이스북 → 121 실측: 간편 로그인 비중 **99%**, 그중 **카카오 66%·네이버 33%**, 페이스북은 이메일보다 적음 → 페이스북·이메일은 작은 텍스트 버튼으로 강등). 선호 수단은 서비스 사용자층마다 다르다(독자 서비스는 네이버 압도).
- 이메일을 먼저 받고 **서버가 회원 여부를 판단해 가입/로그인 화면으로 자동 분기** — 사용자가 고르는 선택지를 하나 없앤다 (74·101).

### CTA·신뢰

- **CTA를 색으로 튀게 하는 대신 모션으로** (93 §03): 파란 보색 CTA는 눈에 띄지만 페이지 몰입을 깨서, 브랜드 주황을 유지하고 움직임으로 시선을 끌었다 (108도 카메라 아이콘 모션).
- **'무료' CTA 실패** (93): '코디 신청'→'무료 코디 신청' 이벤트 — CTA 클릭률은 5% 정도밖에 안 올랐고 무성의한 응답만 늘어 데이터 품질도 낮았다. 결론: 이벤트는 무료가 아니라 할인으로.
- 랜딩 CTA 클릭률(18~25%)은 랜딩을 두 번 갈아도 거의 안 변했고 **유입 광고·타깃에 더 좌우**됐다 (93). 다만 시각 품질을 올린 뒤 **평균 체류 10초→33초**.
- 후기는 신뢰의 핵심(엠브레인 2017: 78.6%가 구매 전 항상 리뷰 확인)이지만, 이 서비스에선 **스타일리스트 본인 사진**이 후기 0개를 이길 만큼 셌다 — 상품 특성에 따라 결정 요인이 다르다 (93 §02).

### 디자인 시스템 (110 원칙 05)

- 간격 **4/8/16/24/36/48/80** (XX-Small~XX-Large), 모서리 둥글기 **12로 통일**(특수한 경우 제외), 글자 크기 34/29/21/17/14/12/10(Noto Sans CJK KR, Bold/Medium/Regular), 좌우 여백 16(98). 작은 앱에선 색·타이포만 코드화해도 효과가 크다.
- 그 밖의 원칙 v2: 우리는 사용자가 아니다(데이터로 판단) / 반응을 보여라(로딩은 다음 화면으로 먼저 넘어간 뒤) / 예상할 수 있게(결과 없는 탭도 숨기지 말고 '결과 없음'+추천어) / 의미 있는 움직임만(이미지 선택 시 버튼이 아래서 나타나는 모션 — 두 화면 전환 84.8%) / 익숙함 존중(구글 지도 햄버거 버튼 한 달 안내 후 제거) / 필요한 만큼만 단순하게.

### 상세 페이지 제안 (122 — 데이터 없음)

- 쿠돈 채용과제: 핵심 가치(정품 보증)를 목록→상세까지 **고정 바로 반복**, 새 상품가 대비 할인율·"새 상품보다 3,350,000원 아낌"으로 합리적 가격 강조, 등급표 바로 아래 하자 사진 공개, 형식적 상품 정보는 아래로, 후기는 가치 전달 뒤 배치, 하단 CTA 고정, 장바구니 강조 여부는 A/B로. **실측 결과가 없는 제안**이므로 3등급으로 취급한다.

## 우리는 쓰지 않음 — 다크패턴 소지

- **"사용자가 누르지 않았으면 하는 버튼은 엄지에서 먼 곳에/찾기 어렵게"** (94 §5, 101 '가입 첫 화면 X를 위쪽에', 108 팝업 X를 엄지 영역 밖에) 와 **"로그아웃·탈퇴는 찾기 어렵게"** (101 '로그아웃과 탈퇴는 어렵게'). 저자는 비즈니스적으로 좋다고 쓰지만, 닐슨 #3(사용자 제어와 자유 — 분명한 비상구)과 [[토스_앱인토스-UI-UX-가이드|토스 다크패턴 정책]] 3번(나갈 선택지 없는 구조 = 검수 반려)에 정면으로 걸린다. **원칙 페이지에 규칙으로 옮기지 않는다.** (탈퇴 시 잃는 것을 알리는 팝업 자체는 사실 고지라 허용 범위.)
- **원클릭 약관 동의** (101 §2-7: 필수 항목만 있으면 체크박스 없이 버튼 누르는 것으로 동의) — 근거가 2019년 방통위 「스마트폰 앱 개인정보보호 가이드라인」이다. **현행 개인정보보호법·가이드 확인 전엔 규칙화 금지.**
