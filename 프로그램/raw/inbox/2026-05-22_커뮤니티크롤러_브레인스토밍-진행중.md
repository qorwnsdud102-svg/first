## 프로젝트 개요

**이름** (임시): 커뮤니티 크롤러 / 커뮤니티 VOC 수집기

**목적** — 쇼핑몰 운영자(사장님)가 판매 검토 중인 제품에 대해 **광고 없는 실사용자 의견(VOC)을 자동 수집**.

- 네이버 일반 검색 = 광고 오염 심함 → 우회 필요
- 커뮤니티(DC인사이드·블라인드·인스티즈·광고 없는 카페 등)는 광고 비율 훨씬 낮음
- 위키 핵심 명제와 연결: [[엠타트업]] 자관인간 1단계, [[NRCS]], [[욕구와 결핍]], [[프레임 분리]] — **고객의 실제 언어**가 마케팅 기반

## 결정된 것

### 1. 사용 방식 (확정)

```
사장님 (Claude Code 안): "블라인드에서 '발받침대' 키워드 크롤링해서 엑셀로 저장"
   ↓
Claude → 크롤러 CLI 실행
   ↓
크롤러 → 사이트 크롤링 → .xlsx 파일 생성
   ↓
사장님: "이 엑셀 분석해서 사람들 페인포인트 알려줘"
   ↓
Claude → 엑셀 읽고 + LLM-WIKI 컨텍스트 활용 → 분석 보고서
```

- **크롤러 = 단순 수집기** (raw → xlsx 변환만)
- **분석 = Claude 측이 별도 단계로** 수행 (LLM-WIKI 마케팅 지식 자동 활용)
- 두 레이어 분리: 크롤러는 멍청한 도구, 지능은 Claude

### 2. 코드 위치 (확정)

- **코드 폴더**: `C:\작업\<프로젝트명>\` (또는 사장님이 정한 위치). LLM-WIKI 외부.
- **LLM-WIKI 연결**: 프로젝트 폴더의 `CLAUDE.md`에 `@import`로 위키 헌법·index 끌어와서 Claude가 위키 컨텍스트 자동 인지.
- **개발 중 raw**: `프로그램/raw/inbox/` (결정 일지·학습 노트·디버깅 회고)
- **wiki 페이지는 나중에** — raw 충분히 쌓이고 정제할 만해지면 entity·ADR 생성

### 3. MVP 사이트 (확정 — 사장님 선택)

**블라인드 우선**.

단 리스크 명시됨 (사장님 답변 보류 상태에서 외출):

- ToS 위반 가능 (자동화 금지 약관 가능성 매우 높음)
- 계정 정지 위험 (anti-bot 강함, 회사메일 1개당 1계정이라 복구 어려움)
- 로그인 필수 (사장님 본인 계정 사용)
- Playwright(실제 브라우저 자동화) 필수 — `requests+BeautifulSoup` 불가

**견고한 접근안**:
- Playwright headful + 본인 계정 쿠키 영구 저장
- 인간처럼 행동 — 페이지당 5-15초 랜덤 대기, 한 키워드당 글 50개 상한
- 1회성 실행 (cron 자동화 X)
- 같은 키워드 재크롤 회피

## 다음 질문 (재개 지점)

**리스크 감안하고 어떻게 진행할지 사장님 최종 판단 필요**:

1. **DC/인스티즈 먼저 → 이후 블라인드** (추천): 쉬운 사이트로 전체 파이프라인(크롤러→엑셀→Claude 분석) 먼저 검증. 1주 안에 완성. 파이프라인 안정되면 블라인드 Playwright 레이어만 교체. 계정 손실 제로.
2. **블라인드 먼저** (사장님 1차 선택): 본인 계정·세션 쓰는 행위자 방식. 계정 정지·ToS 이슈 감안. 근덕한 설계 + 속도 제장.
3. **더 안전한 대안 찾기**: 레딧(/r/Korea 등)·트위터·다음카페 중 평소 사장님이 참고하는 곳 있으면 추가 제안.

→ 사장님 답변 후, 다음 단계는 **접근방식 2-3개 제안** (TaskList #4).
