CHAPTER 01
Aside가 무엇인지 알아보기
Aside는 AI에게 일을 부탁할 수 있는 웹브라우저입니다. 브라우저는 웹사이트를 열어 보는 프로그램이고, 
Aside 안의 AI 에이전트는 사용자의 요청에 따라 웹페이지를 살피거나 여러 단계의 작업을 진행하는 기능입
니다. 설정에 따라 로그인된 계정, 방문 기록, 파일, 저장된 로그인 정보를 활용할 수 있습니다. [S1]
예를 들어 공개 안내문을 열고 핵심 내용을 정리하도록 부탁할 수 있습니다. 상품 페이지 여러 개를 지정해 조
건을 비교하거나, 업무 자료를 읽고 메시지 초안을 만들도록 요청하는 방식도 생각해볼 수 있습니다. 공식 도
움말에는 영수증을 경비 보고서로 정리하거나 고객 문의의 답장 초안을 만드는 활용 사례가 나옵니다. [S2][S3]
중요한 것은 어떤 자료로 무엇을 만들지 정해주는 일입니다. 웹사이트 주소, 참고할 페이지, 필요한 항목을 구
체적으로 알려주면 결과를 확인하기도 쉬워집니다. 결과에 숫자나 날짜가 들어 있다면 원문과 대조하는 습관
도 함께 들이세요.

CHAPTER 11
권한과 개인정보 설정 이해하기
Aside가 접근할 자료의 범위는 작업과 함께 정해야 합니다. 파일을 읽는 연습인지, 결과 파일을 저장하는 작업
인지에 따라 필요한 범위가 달라집니다.
파일 접근 범위 확인하기
공식 권한 도움말은 다음 모드를 안내하며 새 작업의 기본값은 Guard라고 설명합니다. [S16]
모드
공식 설명을 쉽게 풀면
Read only
파일을 바꾸지 않고 브라우저와 파일의 내용을 살펴보는 모드
Guard
허용된 폴더에서 작업하며 다른 폴더 접근은 확인하는 모드
Full access
공식 설명상 컴퓨터 어디서든 파일을 읽고 쓸 수 있도록 파일 접근 범위를 넓히는 모드
그림 7. Guard 메뉴에서 현재 권한 확인하기
입력창 아래 Guard를 누르면 Read only, Guard, Full access가 표시됩니다. 체크 표시는 현재 Guard가 선택됐다는 뜻입니다. 아래 
Final confirm 항목도 보였지만 이번 실습에서는 변경하거나 동작을 시험하지 않았습니다. 메뉴를 열어 확인한 뒤 닫았습니다.
출처: Windows용 Aside 1.0.914.1 실제 앱 · 캡처: 2026.09.21 · 필요한 영역만 잘라 표시
별도로 도구 권한에는 Allow, Ask, Deny가 있습니다. 각각 허용, 실행 전 질문, 차단을 뜻합니다. 규칙이 충돌
하면 Deny가 Ask와 Allow보다 우선합니다. Full access도 저장된 비밀번호 원문을 AI에 보여주는 설정은 아닙
니다. 파일 권한과 웹사이트에서 일어나는 행동은 구분해서 이해하세요. Read only라는 이름만으로 모든 웹사
이트 변경이 차단된다고 보장할 수는 없습니다. [S16]
로그인과 추가 인증 이해하기
Aside Vault의 자동 입력으로 로그인할 수 있더라도, 사이트가 추가 인증이나 CAPTCHA를 요구하면 사람이 
진행해야 할 수 있습니다. 암호 관리자 접근 정책은 Settings > Passwords > Access policy for AI agents에서 
확인합니다. [S9]

로컬 저장과 외부 처리는 구분하기
공식 개인정보처리방침은 작업 기록과 산출물을 로컬에 저장하는 한편, 호스팅된 AI 모델에는 작업 수행에 필
요한 정보가 전달될 수 있다고 설명합니다. 전달 대상에는 요청문, 도구 결과, 선택된 화면이나 파일 등이 포함
될 수 있습니다. 계정, 결제, 분석, 동기화에도 서버 서비스가 사용됩니다. [S17]
따라서 ‘브라우저에서 처리하니 자료가 외부로 전혀 나가지 않는다’고 생각해서는 안 됩니다. 처음 실습은 공
개 자료나 가상 자료로 진행하고, 실제 업무 자료를 사용할 때는 자료의 처리 기준에 맞춰 범위를 정하세요.
Settings > Security & Privacy에는 방문 기록, 쿠키, 분석 공유 등의 설정이 있습니다. 메모리 설정과 함께 확
인하면 어떤 정보를 남길지 이해하는 데 도움이 됩니다. [S18]
CHAPTER 12
막혔을 때 해결하기
작업이 멈춰 있을 때
작업을 열고 질문이나 승인 요청이 있는지 확인합니다. 로그인이 필요한지, 추가 인증을 기다리는지, 파일 접
근을 요청하는지부터 읽어보세요. 요청을 처리한 뒤 화면에 재개 동작이 표시되면 이어서 진행합니다. [S19]
다른 페이지를 읽고 있을 때
현재 페이지 첨부와 요청한 URL을 확인합니다. 사용할 자료를 다시 지정하고 필요한 항목을 적어보세요. 진행
 중 수정은 Steer, 다음 실행에 반영할 내용은 Queue로 구분합니다. [S3][S19]
답이 맞는지 모르겠을 때
각 항목의 근거 URL을 붙여줘. 원문에서 확인한 내용과 네가 해석한 내용을 구분하고, 확인하지 못한 값
은 표시해줘.
이 문장은 검토할 근거를 요청하는 예제입니다. 출처가 붙었다고 내용이 자동으로 정확해지는 것은 아니므로,
 중요한 날짜와 숫자는 직접 대조하세요.
브라우저 데이터 가져오기가 실패할 때
원래 브라우저의 프로필이 존재하는지, 해당 가져오기 방식에 맞는 파일인지 확인합니다. 공식 도움말은 필요
한 경우 원래 브라우저를 닫고 재시도하거나, 해당 소스에 맞는 파일 가져오기를 사용하도록 안내합니다. [S19]
해결되지 않으면 남길 정보
문제가 발생한 사이트, 시각, 하려던 작업, 실제 결과, 화면에 표시된 오류 문구를 적어두세요. 공식 지원 주소
는 support@aside.com입니다. 문의할 때 첨부하는 화면과 기록에 개인정보가 들어 있지 않은지도 확인합니
다. [S19]

CHAPTER 13
내 업무에 적용하기
첫 실습을 마쳤다면 자신의 반복 업무 중 한 가지를 골라보세요. 매주 읽는 공지, 비교해야 할 서비스 페이지,
자료를 전달하는 메시지처럼 입력과 결과가 분명한 작업이 좋습니다.
다음 네 문장을 채워보면 실제 요청의 뼈대가 됩니다.
1. 내가 자주 하는 일은 ____________________ 입니다.
 
2. 참고해야 할 페이지나 파일은 ____________________ 입니다.
 
3. 필요한 결과는 ____________________ 입니다.
 
4. 내가 직접 확인할 내용은 ____________________ 입니다.
 
이제 완성한 내용을 Aside에 부탁하고, 결과가 실제로 쓸 만한지 확인하세요. 자료가 정확했는지, 원하는 항목
이 나왔는지, 수정하는 데 어떤 설명이 필요했는지 적어두면 다음 요청을 개선할 수 있습니다.
자주 쓰는 요청은 별도로 저장해두세요. 예제 문장을 그대로 반복하기보다 대상 자료와 기준을 자신의 업무에
 맞게 바꾸는 것이 이 안내서의 마지막 연습입니다.

Windows용 Aside 1.0.914.1에서 Ask 입력, 페이지 첨부, 요청 전송·요약 완료, 권한 메뉴를 확인했습니다. 비교

요금은 S6, 모델 연결은 S7, 데이터 처리는 S17을 기준으로 했습니다. 이 문서는 Aside가 발행·승인한 공식 매
뉴얼이 아닌 비공식 사용자 안내서입니다. 기능과 표시가 달라지면 현재 공식 자료와 앱 화면을 확인하세요.
