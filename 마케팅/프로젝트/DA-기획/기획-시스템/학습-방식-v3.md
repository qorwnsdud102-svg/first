# DA 기획 모델 학습 방식 v3 — 피드백 하나가 다음 카드의 선택 하나를 바꾸게

## 사장님 요구 (P6438~P6441)
더 원하는, 더 후킹되는 기획 · 노하우와 경험치가 쌓여 완성도가 오름 · 지난 피드백을 곱씹어 "이렇게 생각했는데 여기가 틀렸다, 다음엔 안 한다" · 불필요한 토큰 절약.

## v2에서 무엇이 됐고 무엇이 안 됐나 (2026-10-14 숫자)
| 숫자 | 결과 |
|---|---|
| 드릴 평균 | 3.1 → **5.4** (경험 문서를 먼저 읽고 쓴 5회차) |
| 같은 실수 반복률 | 4 → 5회차 **60%** (만들 수 없음 4장, 기존 대안 우세 2장) |
| 점수 예측 오차 | Claude 2.1 · GPT 1.7 (눈 v6는 3.0으로 미통과) |
| 해부 → 다시 쓰기 | 히트 11회차 4.8 → 같은 방식으로 다시 쓴 12회차 5.8 (약 450만 토큰) |
| 해부 비용 | 한 회차 3,300만~4,600만 토큰 |

## 바꾸는 네 가지
1. **바꿀 선택 하나.** 판정 한 건마다 `자가학습/경험/경험카드.jsonl`에 한 줄을 쓴다: 이전 선택(그때 남긴 flow) · 사장님 판정(원문 위치·점수) · **바꿀 선택 1개**(결핍 / 상징 / 구현 / 살 이유 중 가장 먼저 틀린 곳) · 적용 조건·예외 · 다음 시험(새 카드 ID와 결과). 새 카드는 어떤 경험카드를 적용해 무엇을 바꿨는지 `applied` 칸에 적는다. 판정 뒤 같은 곳을 사장님이 또 짚으면 반복으로 센다.
2. **관련 사례 4건만 읽는다.** 기획자는 `생각-순서.md`(한 쪽)와, 장부에서 꺼낸 비슷한 결핍의 성공·실패 각 1건 + 비슷한 구현의 성공·실패 각 1건만 읽는다(합계 6천 토큰 이내). 경험 문서 전체(약 15만 자)는 통째로 읽지 않는다. 장부는 쌓여도 읽는 양은 늘지 않는다.
3. **밤 연습은 작게.** 고쳐 쓰기 2건(틀린 카드에서 한 요소만 바꿈) + 다른 결핍에 옮기기 2건(7점 카드의 기획 수를 다른 결핍에). 사장님이 준 대안을 그대로 다시 쓰지 않는다. 대량 히트 해부는 기획 판단을 바꿀 질문이 있을 때만 하고, 카드는 사장님 순서(타겟 → 메인 결핍 → 대표 대안과 단점 → 컨셉 → 상징 역할 → 의심 막는 증거 → 배울 길)로 쓴다.
4. **활동별 토큰 기준선** (캐시 포함). **넘어도 멈추지 않는다**(사장님 P6481, 2026-10-14: 상한 때문에 작업이 중단되니 알아서 돌게 하고, 너무 많이 쓰면 평가해서 방식을 바꾼다). 단계마다 토큰을 기록만 하고 끝까지 돈다. 끝난 뒤 기준선의 2배를 넘은 활동은 Claude가 어디서 많이 들었는지 보고 방식을 바꾼다.

| 활동 | 기준선 (멈춤 아님) |
|---|---:|
| 경험카드 장부 첫 정리 | 25만 |
| 판정 반영(회고 → 장부) 1회 | 100만 |
| 드릴 카드 1장(초안 3 → 1) | 6만 |
| 밤 연습 4건 | 10만/밤 |
| 좁은 조사 1건 | 30만 |
| 히트 해부 1제품(필요할 때만) | 100만 |
| 역기획 시험 1회(15문제) | 500만 |

그대로 두는 것: 정본은 하드 탈락 체로만(⑥-25 만들 수 있나 포함), 사장님 판정 형식(점수 + 걸리는 곳 + 이유 한 줄), 봉인 후 판정, 눈은 미래 카드에서 통과하기 전엔 고르기에 안 씀.

## 드릴 6회차로 확인
- 새 방식으로 10장(결핍 10개, 결핍마다 초안 3개에서 1개). 사장님께 10장 그대로 올린다(Claude 선발 없음).
- **성공:** 평균 5.4 이상, 같은 실수 반복률 60% 아래, 드릴 토큰이 5회차보다 적다. 둘 이상 못 넘으면 v2로 돌아가거나 실패한 단계 하나만 바꾼다.
- 재는 숫자: 드릴 평균·7점 이상 비율 · 같은 실수 반복률 · 작성자 예측 오차 · 역기획 재발견율(15문제) · 7점 한 장당 토큰.
